## Description

FUNCTIONALITY: Allows attendees to request refunds for purchased tickets. Displays ticket details (event name, date, tier, purchase price) and current refund policy for the event (refund window, percentage allowed, processing time). Users can select refund reason from dropdown (event cancelled, personal circumstances, duplicate purchase, other) with optional detailed explanation textarea. Shows refund amount calculation in real-time based on policy (e.g., '80% refund = $64 of $80'). Displays refund method options (original payment method, store credit, alternative payment method). Checkbox to confirm understanding of refund terms. 'Submit Refund Request' button initiates the request. On success, shows confirmation with expected processing timeline and reference number. Displays refund status badge (pending/approved/rejected/processing/completed) with timeline showing current stage.
DESIGN APPROACH: Vertical scrollable layout with ticket summary card at top (event thumbnail, name, date, price). Refund policy displayed as an info card with key details highlighted (window remaining, percentage allowed). Form sections below: reason selection, explanation textarea, refund method radio buttons, confirmation checkbox. Refund calculation displayed prominently in a sticky card showing original price, refund percentage, and final amount. Mobile: full-width cards with stacked sections, sticky calculation card at bottom.
STATES: Loading shows skeleton ticket card and placeholder form fields. Success shows confirmation screen with reference number and 'View Status' button. Error 401 redirects to login with 'Sign in to request refund' toast. Error 403 shows 'Refund window closed' or 'Not eligible for refund'. Error 404 shows 'Ticket not found'. Error 500 shows error banner with retry. Validation error highlights invalid field with red border and message.
SECURITY: Authenticated users only. Users can only request refunds for their own tickets (enforced by Policy). Refund window validation server-side. Rate limit 5 requests/hour per user to prevent abuse.
