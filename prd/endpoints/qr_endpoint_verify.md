# Qr Endpoint Verify

POST /api/tickets/verify-qr

## Description

REQUEST: { qrCodeData (string, required - encrypted payload from QR scan), venueId (string, optional - for venue-specific validation) }
PROCESS: 1. Verify auth token and extract userId 2. Check user has 'VenueStaff' or 'Organizer' role via Policy 3. Decrypt qrCodeData using AES-256 server-side key 4. Extract ticketId, eventId, email, expiresAt from decrypted payload 5. Validate expiry: if current time > expiresAt, return 'QR code expired' 6. Query tickets by ticketId 7. Verify ticket status: if status='void', return 'This ticket is invalid' 8. Verify ticket status: if status='checked_in', return 'Already checked in at HH:MM' with checkedInAt timestamp 9. Query fraud_events by ticketId to check if ticket is fraud-flagged 10. If fraud-flagged with status='auto_blocked', return 'This ticket is blocked' 11. Verify event exists and matches eventId from payload 12. Verify event date hasn't passed (optional - allow check-in up to event end + grace period) 13. Increment qrCodeScannedCount 14. Update lastQrScanAt timestamp 15. Return ticket details: {ticketId, attendeeName, tier, eventTitle, status, isValid}
SUCCESS (200): { ticketId (string), attendeeName (string), tier (string), eventTitle (string), status (string: 'valid'|'checked_in'|'void'|'expired'|'fraud_flagged'), isValid (boolean), checkedInAt (timestamp, optional), message (string) }
ERRORS: 400 (invalid/malformed qrCodeData, decryption failed), 401 (unauthenticated), 403 (user not venue staff), 404 (ticket not found), 409 (ticket already checked-in, ticket void, ticket expired, fraud-flagged), 429 (rate limited), 500 (decryption error)
SECURITY: Auth required (bearer token). Venue staff role enforced via Policy. Rate limit 60 verifications/min per user (high limit for venue scanning). All verification attempts logged to auditLogs with staff ID, ticket ID, result. Decryption happens server-side only - encrypted payload never exposed to client.
