# Rbac Endpoint Update Permissions

POST /api/admin/permissions/update

## Description

REQUEST: { userId: string, permissionIds: [string], action: 'grant' | 'revoke', reason?: string }
PROCESS: 1. Verify admin authorization via Policy 2. Validate userId exists and permissionIds are valid 3. For each permissionId: a) Check permission riskLevel — if high-risk, require additional confirmation b) If action='grant', add to user's permissions array c) If action='revoke', remove from user's permissions array d) Create auditLog entry with old/new permission state e) Invalidate user's sessions to enforce new permissions 4. Return success
SUCCESS (200): { updated: number, message: 'Permissions updated' }
ERRORS:
- 400: Missing fields, invalid permissionIds, invalid action
- 401: User not authenticated
- 403: User is not admin, or attempting to modify own high-risk permissions
- 404: User or permission not found
- 429: Rate limit exceeded
- 500: Database error
SECURITY: Admin-only. High-risk permissions require explicit confirmation. Log all changes. Invalidate sessions. Prevent self-modification of high-risk permissions.
