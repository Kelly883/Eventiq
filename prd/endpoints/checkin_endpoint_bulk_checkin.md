# Checkin Endpoint Bulk Checkin

POST /api/venue/check-in/bulk

## Description

REQUEST: { eventId (string, required, UUID), ticketIds (array of strings, required, max 100 items), venueId (string, optional) }
PROCESS: 1. Verify auth token and extract userId 2. Check user has 'VenueStaff' or 'Organizer' role via Policy 3. Query events by eventId 4. Verify user is authorized for this event 5. For each ticketId: query tickets, verify status is 'valid', check fraud_events for blocks, update status to 'checked_in', set checkedInAt=NOW, set checkedInBy=userId 6. Create auditLog entries for each check-in 7. Decrement ticket_inventory.totalAvailable for each ticket 8. Increment analytics_events_metrics.totalTicketsSold 9. Return results with success/failure per ticket
SUCCESS (200): { checkedIn: integer, failed: integer, results: [{ticketId, status: 'success'|'already_checked_in'|'void'|'fraud_flagged'|'not_found', message}] }
ERRORS: 400 (invalid eventId, empty ticketIds, too many items), 401 (unauthenticated), 403 (user not authorized), 404 (event not found), 429 (rate limited), 500 (database error)
SECURITY: Auth required (bearer token). Venue staff role enforced via Policy. Event authorization validated. Rate limit 30 bulk operations/min per user to prevent abuse. Idempotent - checking in same ticket twice returns success but doesn't double-count.
