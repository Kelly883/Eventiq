# Qr Endpoint Void

POST /api/tickets/:ticketId/void

## Description

REQUEST: URL param ticketId (UUID), body: { reason (string, required, max 500 chars), fraudEventId (string, optional - reference to fraud_events if voiding due to fraud) }
PROCESS: 1. Verify auth token and extract userId 2. Check user has 'Organizer' or 'Admin' role via Policy 3. Query tickets by ticketId 4. Verify ticket belongs to organizer's event (if organizer role) 5. Update tickets record: status='void', voidedAt=NOW, voidedBy=userId, voidReason=reason 6. Create auditLog entry: action='ticket_voided', ticketId, userId, reason, timestamp 7. If fraudEventId provided, update fraud_events: status='approved', reviewedBy=userId, reviewedAt=NOW 8. Increment ticket_inventory.totalAvailable (restore capacity) 9. Create delivery_event with status='blocked' and blockReason='ticket_voided' 10. Return success
SUCCESS (200): { ticketId (string), status: 'void', voidedAt (timestamp), message: 'Ticket voided successfully' }
ERRORS: 400 (invalid ticketId format, missing reason), 401 (unauthenticated), 403 (user not organizer/admin or doesn't own event), 404 (ticket not found), 409 (ticket already void), 429 (rate limited), 500 (database error)
SECURITY: Auth required (bearer token). Organizer/Admin role enforced via Policy. Event ownership validated for organizers. Rate limit 10 voids/min per user. All voids logged to auditLogs with reason and admin ID.
