REQUEST: No body. Requires a bearer token for authentication and a custom `X-Device-Token` header containing the unique push notification token for the client device. PROCESS: 1. Authenticate the user via Sanctum. 2. Use the `user_id` to query for all tickets where the associated event's `start_date` is in the future. 3. Eager load all necessary relationships using Eloquent: `event`, `ticket_tier`, `order`, and `event.organizer`. 4. For each ticket, ensure the `qrCodeData` is available. 5. The data is formatted into a nested structure grouped by event using an API Resource collection to prevent data leakage and ensure consistent output. 6. After successfully preparing the data, find the `push_notification_devices` record matching the user and the `X-Device-Token` header, and update its `last_sync_at` field to the current timestamp. 7. Return the complete data payload for the client to cache. SUCCESS (200): A JSON object containing a list of events, each with its details and an array of associated tickets. ERRORS: Standard auth and server errors. SECURITY: Requires authentication. The endpoint is rate-limited to prevent abuse. The `X-Device-Token` header is used to identify the device for updating its sync timestamp.
