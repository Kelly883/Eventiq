# Qr Endpoint Generate

POST /api/tickets/generate-qr

## Description

REQUEST: { ticketId (string, required, UUID) }
PROCESS: 1. Verify auth token and extract userId 2. Query tickets by ticketId 3. Check user owns ticket via Policy 4. Generate random secret (32 bytes) 5. Create encrypted QR payload: {ticketId, eventId, userId, email, tier, expiresAt} using AES-256 6. Encode payload as base64 7. Hash secret with bcrypt (cost 12) and store in qrCodeSecret 8. Generate QR code image using qrcode library with encrypted payload 9. Upload QR image to Storage at qr-codes/{ticketId}.png 10. Update tickets record with qrCodeData, qrCodeSecret, qrCodeGeneratedAt, qrCodeExpiresAt 11. Return {qrCodeUrl, qrCodeData (encrypted), expiresAt}
SUCCESS (200): { qrCodeUrl (string - S3 URL), qrCodeData (string - encrypted payload), expiresAt (timestamp), message: 'QR code generated successfully' }
ERRORS: 400 (invalid ticketId format), 401 (unauthenticated - attempt token refresh → if fails, redirect to login), 403 (user doesn't own ticket), 404 (ticket not found), 409 (QR already generated for this ticket), 429 (rate limited), 500 (encryption/generation failed)
SECURITY: Auth required (bearer token). Ticket ownership enforced via Policy. Rate limit 10 generations/min per user to prevent abuse. QR payload encrypted with AES-256 using server-side key (never exposed to client). Secret hashed before storage. All QR generations logged to auditLogs.
