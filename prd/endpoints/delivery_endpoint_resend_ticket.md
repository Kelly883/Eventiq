# Delivery Endpoint Resend Ticket

POST /api/tickets/:ticketId/resend-delivery

## Description

REQUEST: URL param ticketId (UUID), body: { deliveryMethod (string, optional - 'email', 'sms', 'dashboard', defaults to user preference), recipientEmail (string, optional for email method), recipientPhone (string, optional for SMS method) }
PROCESS: 1. Verify auth token and extract userId 2. Query tickets by ticketId 3. Check user owns ticket via Policy 4. Query delivery_events by ticketId to get last delivery attempt 5. Validate deliveryMethod is enabled in user preferences 6. If email: validate email address format, check not already failed 5+ times 7. If SMS: validate phone format, check not already failed 5+ times 8. Check fraud_events to ensure order is not blocked 9. Increment attemptCount 10. Queue delivery job with ticketing SDK 11. Update delivery_events status to 'pending' 12. Return success with new delivery timestamp
SUCCESS (200): { ticketId, status: 'pending', deliveryMethod, nextRetryAt, message: 'Ticket resend initiated' }
ERRORS: 400 (invalid method, invalid email/phone format, max attempts exceeded), 401 (unauthenticated), 403 (user doesn't own ticket or delivery blocked by fraud), 404 (ticket not found), 409 (delivery already in progress), 429 (rate limited), 500 (delivery provider error)
SECURITY: Auth required. Ticket ownership enforced. Fraud check prevents delivery of flagged orders. Rate limit 10 resends/min per user to prevent abuse.
