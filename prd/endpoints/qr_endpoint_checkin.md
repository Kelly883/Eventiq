# Qr Endpoint Checkin

POST /api/tickets/:ticketId/check-in

## Description

REQUEST: URL param ticketId (UUID), body: { qrCodeData (string, required - for verification), venueId (string, optional) }
PROCESS: 1. Verify auth token and extract userId 2. Check user has 'VenueStaff' or 'Organizer' role via Policy 3. Query tickets by ticketId 4. Verify ticket status is 'valid' (not already checked-in or void) 5. Call verify-qr endpoint logic to validate QR code 6. If verification fails, return error 7. Update tickets record: status='checked_in', checkedInAt=NOW, checkedInBy=userId 8. Create auditLog entry: action='ticket_checked_in', ticketId, userId, timestamp 9. Decrement ticket_inventory.totalAvailable (for real-time capacity tracking) 10. Increment analytics_events_metrics.totalTicketsSold (for real-time dashboard) 11. Return success with check-in confirmation
SUCCESS (200): { ticketId (string), attendeeName (string), checkedInAt (timestamp), message: 'Checked in successfully' }
ERRORS: 400 (invalid ticketId format, invalid qrCodeData), 401 (unauthenticated), 403 (user not venue staff), 404 (ticket not found), 409 (ticket already checked-in, ticket void, QR expired, fraud-flagged), 429 (rate limited), 500 (database error)
SECURITY: Auth required (bearer token). Venue staff role enforced via Policy. Rate limit 60 check-ins/min per user. All check-ins logged to auditLogs with staff ID, ticket ID, timestamp. Idempotent - checking in same ticket twice returns success but doesn't double-count.
