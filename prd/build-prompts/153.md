We need six API endpoints for the email template system. All endpoints require authentication and admin authorization via the EmailTemplatePolicy.

1. GET /api/admin/email-templates — List all email templates. Return a paginated list (20 per page) with id, name, type, subject, is_active, created_at, updated_at. Support filtering by type and is_active status via query parameters. Sort by created_at descending by default. Used by AdminEmailTemplateManagementPage to populate the template list.

2. GET /api/admin/email-templates/:templateId — Get a single template's full details for editing. Return all fields including html_body, mjml_body, and variables. Return 404 if the template doesn't exist.

3. POST /api/admin/email-templates — Create a new template. Validate the request using StoreEmailTemplateRequest. Accept name, type, subject, html_body, mjml_body, and variables. Before saving, compile the mjml_body to HTML using the MJML library and store the result in html_body. Return the created template with 201 status.

4. PATCH /api/admin/email-templates/:templateId — Update an existing template. Validate using UpdateEmailTemplateRequest. Accept the same fields as POST. Recompile MJML to HTML if mjml_body changes. Log the change to auditLogs with metadata showing which fields changed. Return the updated template with 200 status.

5. DELETE /api/admin/email-templates/:templateId — Delete a template. Return 204 No Content on success. Log the deletion to auditLogs.

6. POST /api/admin/email-templates/send-test — Send a test version of a template to a specified email address. Accept templateId and recipientEmail in the request body. Validate that the template exists and the email is valid. Use a generic Mailable class (TestEmailMailable) that accepts raw HTML content. Send the email synchronously (not queued) so the admin gets immediate feedback. Return { success: true, message: 'Test email sent' } on success, or an error message if sending fails.

All endpoints should check authentication (401 if not logged in) and authorization (403 if not admin). Add rate limiting: 30/min for GET list, 20/min for GET detail, 10/min for POST/PATCH/DELETE, 5/min for send-test.
