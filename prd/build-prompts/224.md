We need to manage inventory data across the dashboard and modal using TanStack Query so we don't fetch the same data multiple times and can easily refresh after changes.

Create three query hooks:

1. useInventorySummary(eventId) — Fetches from GET /api/organizer/events/:eventId/inventory/summary. Returns totalCapacity, totalSold, totalAvailable, utilizationPercentage, lowStockTierCount, and an array of tiers with their individual stats. Cache this for 30 seconds (staleTime: 30000) since it updates frequently. This powers the summary cards at the top of the dashboard.

2. useInventoryDetails(eventId, tierFilter, sortBy, sortOrder) — Fetches from GET /api/organizer/events/:eventId/inventory with query params for filtering and sorting. Returns the full tier list with nested pricing windows. Cache for 30 seconds. This powers the main inventory table. When the user changes the filter or sort, this query automatically refetches with the new params.

3. useInventoryAuditLog(eventId, tierFilter, organizerFilter, adjustmentType, page, limit) — Fetches from GET /api/organizer/events/:eventId/inventory/audit-log. Returns paginated adjustment history. Cache for 1 minute. This will power an audit log view (optional, but good to have for transparency).

For mutations, create:

1. useAdjustInventory() — Calls PATCH /api/organizer/events/:eventId/inventory/adjust with the new quantity and reason. On success, invalidate both useInventorySummary and useInventoryDetails queries so they refetch automatically. This keeps the dashboard in sync without manual refresh.

All queries should handle errors gracefully: 401 means the session expired (redirect to login), 403 means access denied (show error), 404 means event not found (show error), 500 means server error (show error with retry).

Set up error boundaries or error callbacks so failed queries don't crash the page — instead, show a toast or error banner with a retry button.

For the export endpoint (GET /api/organizer/events/:eventId/inventory/export), don't use a query hook — instead, create a simple function that constructs the URL with query params and opens it in a new tab or triggers a download. This is a one-off action, not reactive state.
