Now we need to connect the accessibility and localization feature to the rest of the app so settings apply everywhere.

Add routes for the three settings pages: /settings/accessibility (AccessibilitySettingsPage), /settings/language (LanguagePreferencePage), and /settings/device-localization (DeviceLocalizationSyncPage). These should be nested under a settings section or accessible from the user settings menu.

Wrap the entire app with the three context providers (AccessibilityContext, LocalizationContext, DeviceSyncContext) at the root level, before any pages render. This ensures accessibility and localization settings are available globally.

On app startup, before rendering any pages, load accessibility and localization preferences. If the user is authenticated, fetch GET /api/users/me/accessibility-preferences and GET /api/users/me/language-preferences. Apply these settings to the DOM immediately (inject CSS variables for font size, line height, letter spacing, word spacing; apply high contrast class; disable animations if motionReduced is true; set ARIA attributes if screenReaderOptimized is true; enhance focus indicators if focusIndicatorEnhanced is true; apply color blindness filter if colorBlindnessMode is not 'none'). Initialize react-i18next with the user's language preference.

Add a settings link in the user menu or navigation drawer that shows the three settings pages. When users click 'Accessibility Settings', 'Language Settings', or 'Device Sync Settings', navigate to the corresponding page.

Wire up these connections:
- When accessibility settings are updated on AccessibilitySettingsPage, apply them immediately to the entire app (no page reload needed)
- When language is changed on LanguagePreferencePage, switch i18next namespace and update all UI text immediately
- When device sync completes on DeviceLocalizationSyncPage, show a success toast
- If a user's session expires (401 error), redirect to login, then back to the settings page they were on
- Deep links to /settings/accessibility, /settings/language, or /settings/device-localization should work when logged in

Make sure the app respects the user's accessibility settings everywhere: if motionReduced is true, disable animations on all pages; if highContrast is true, apply WCAG AAA colors globally; if screenReaderOptimized is true, ensure all interactive elements have proper ARIA labels.
