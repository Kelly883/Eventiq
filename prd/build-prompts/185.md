We need three reusable components that will be used across the app for displaying and managing offline tickets.

1. OfflineTicketCard — A responsive card component that displays a single cached ticket. Shows: event name, ticket tier name, QR code (as an image or data URL), order number, and event start date. On mobile (< 768px), stack vertically and make the QR code smaller. On desktop, arrange horizontally with the QR code on the right. Include a small badge showing "Cached" or "Synced X minutes ago". The component should accept a ticket prop (OfflineTicket type) and an optional onRefresh callback. Make it responsive using CSS media queries or Tailwind's responsive classes.

2. DeviceOfflineToggle — A switch component that lets users enable/disable offline mode for the current device. Shows the current offline_enabled status and last sync time. When toggled, calls PATCH /api/notifications/device-tokens/:token/offline-status to update the backend. Show a loading spinner while the request is in flight. On success, update the UI. On error, show a friendly message and revert the toggle. This component manages its own local state and makes the API call.

3. OfflineSyncStatus — A small status indicator that shows whether the app is currently syncing, when the last sync happened, and if there's a sync error. On mobile, render as a compact badge in the top-right corner. On desktop, render as a small panel. Show: "Syncing...", "Last synced 5 minutes ago", or "Sync failed: [error message]". Include a manual "Sync Now" button that triggers a sync. The component accepts isSyncing, lastSyncedAt, and syncError props, plus an onSync callback.

All three components should be fully responsive and work well on phones (320px+), tablets (768px+), and desktops (1024px+). Use CSS media queries or a utility-first CSS framework to handle breakpoints. Ensure touch targets are at least 44x44px on mobile for accessibility.
