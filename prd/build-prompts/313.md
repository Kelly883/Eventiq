We need to make sure things fail gracefully when something goes wrong, so users understand what happened and can recover.

TicketStatusPage:
- Network failure on first load → show a full-screen error with a 'Retry' button (not a small notification — the page has no content yet)
- 401 (session expired) → redirect to login with 'Session expired' toast
- 403 (user doesn't own ticket) → show 'Access Denied — you don't own this ticket' with a back button
- 404 (ticket not found) → show 'Ticket not found' with a link back to my-tickets
- 500 (server error) → show error banner with a 'Retry' button
- Resend fails with 400 (invalid email/phone format) → show 'Invalid email/phone format' in a toast
- Resend fails with 400 (max attempts exceeded) → show 'Maximum resend attempts reached, please try again later'
- Resend fails with 403 (fraud blocked) → show 'Delivery blocked due to fraud flag'
- Resend fails with 409 (delivery already in progress) → show 'Delivery already in progress, please wait'
- Resend fails with 429 (rate limited) → show 'Too many resend attempts, please wait a minute'
- Resend fails with 500 (provider error) → show 'Delivery service temporarily unavailable, please try again later'

DeliverySettingsPage:
- Network failure on first load → show a full-screen error with a 'Retry' button
- 401 (session expired) → redirect to login with 'Session expired' toast
- 403 (access denied) → show 'Access Denied' with a back button
- 500 (server error) → show error banner with a 'Retry' button
- Save fails with 400 (invalid email/phone format) → show inline error under the field
- Save fails with 400 (email/phone already in use) → show 'This email/phone is already registered'
- Save fails with 429 (rate limited) → show 'Too many changes, please wait a minute'
- Verification fails with 400 (invalid code) → show 'Invalid verification code'
- Verification fails with 429 (too many attempts) → show 'Too many verification attempts, please try again later'
- Verification succeeds → show 'Verified!' and update the status indicator

AdminDeliveryDashboardPage:
- Network failure on first load → show a full-screen error with a 'Retry' button
- 401 (session expired) → redirect to login with 'Session expired' toast
- 403 (not admin) → show 'Access Denied — only admins can view delivery dashboard' with a back button
- 500 (server error) → show error banner with a 'Retry' button
- Filter/search fails → show a notification but keep the previous results on screen
- Real-time polling fails → show a subtle notification 'Live updates paused' but keep the dashboard functional
- Retry failed button fails with 500 → show 'Retry failed, please try again'
- Export CSV fails → show 'Export failed, please try again'

General error handling:
- All error messages should be user-friendly (not technical jargon)
- Toast notifications for transient errors (rate limit, network hiccup)
- Full-screen or banner errors for critical failures (auth, access denied, not found)
- Always provide a way to recover (Retry button, back button, link to home)
- If the user's login expires (401), redirect to login page immediately
- Don't show the same error twice — if a retry fails with the same error, show it once and disable retry
