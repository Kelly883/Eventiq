We need to add the DeveloperPortalPage to the app's routing and make it accessible from the main navigation.

On the frontend (React + Vite), update the router configuration:

1. Add a new route for the DeveloperPortalPage at /developer. This route should require authentication (check that the user is logged in). If the user is not authenticated, redirect to the login page. If the user is authenticated but not an organizer, show an 'Access Denied' page.

2. Add a navigation link to the developer portal in the main app navigation (e.g., in the header, sidebar, or user menu). The link should say 'Developer' or 'API & Integrations' and only show for organizers. Use react-router-dom's Link or useNavigate() to navigate to /developer.

3. The DeveloperPortalPage should be a protected route that checks the user's role on the frontend (using the auth state from Zustand or context). If the user is not an organizer, show the 'Access Denied' page with a message like 'Only organizers can access the developer portal.'

4. On the backend, the Laravel routes should be protected by the auth middleware and the organizer role check. Add these routes to routes/api.php:
   - GET /api/developer/api-keys
   - POST /api/developer/api-keys
   - DELETE /api/developer/api-keys/{keyId}
   - GET /api/developer/webhooks
   - POST /api/developer/webhooks
   - DELETE /api/developer/webhooks/{webhookId}
   - GET /api/developer/api-logs

5. The public API routes should be added to routes/api.php as well:
   - GET /v1/events (public, authenticated with API key)
   - POST /graphql (public, authenticated with API key)

Make sure the routes are properly namespaced and grouped with the correct middleware (auth for developer routes, api_key_auth for public API routes).
