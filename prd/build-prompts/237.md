We need state management so the payout and settlement pages don't handle data fetching themselves. Use TanStack Query to manage server state and React Context for UI state.

For the OrganizerPayoutDashboardPage, create a custom hook called useOrganizerPayouts that manages: the list of payouts fetched from GET /api/organizer/payouts/list, loading state (initial load vs. loading more), pagination (current page, total count), filters (status, date range, payout period), sort options (sortBy field, sortOrder direction), and any errors. The hook should support: loading the first page of payouts, changing filters (which resets to page 1 and refetches), changing sort order (which refetches), and paginating to the next page. Use TanStack Query's useQuery to fetch payouts with automatic caching and background refetching every 60 seconds. Also create a hook called usePayoutSummary that fetches the four summary metrics (total revenue, pending payout, last payout date, next payout date) from GET /api/organizer/payouts/summary. This should also refetch every 60 seconds.

For the AdminSettlementDashboardPage, create a custom hook called useAdminSettlements that manages: the list of all pending settlements fetched from GET /api/admin/settlements/list, loading state, pagination, filters (organizer name, status, date range, revenue range), sort options, search query, and errors. Support: loading the first page, changing filters, changing sort, searching by organizer name or event ID, and selecting multiple settlements for bulk actions. Use TanStack Query's useQuery with automatic caching and background refetching every 30 seconds. Create a hook called useSettlementSummary that fetches the four summary metrics (platform revenue 24h, pending payouts, success rate, avg processing time) from GET /api/admin/settlements/summary. This should also refetch every 30 seconds. Create a hook called useSettlementActions that handles mutations: approveSettlement (POST to /api/admin/settlements/approve), rejectSettlement (POST to /api/admin/settlements/reject), and triggerManualPayout (POST to /api/admin/settlements/trigger-payout). These should use TanStack Query's useMutation and invalidate the settlements query after success.

For UI state, use React Context to manage: which rows are expanded (expandedPayoutIds, expandedSettlementIds), which settlements are selected for bulk actions (selectedSettlementIds), and any temporary UI state like which filter is open. This keeps the pages clean and lets you lift state up if needed.

Keep all business logic out of the pages — pages should just call hooks and react to state changes. The hooks handle all the data fetching, caching, filtering, and mutations.
