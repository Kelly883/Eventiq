We need three public API endpoints for the calendar feature. All are read-only and don't require authentication. Build these in app/Http/Controllers/EventCalendarController.php:

1. GET /api/events/public/calendar — Main calendar view. Query params: ?month=2024-03 (optional, ISO YYYY-MM), ?week=2024-W12 (optional, ISO week), ?category=concerts (optional), ?priceMin=0&priceMax=500 (optional), ?location=New York (optional). Process: Validate query params using CalendarFilterRequest. Query events where status='published'. Apply date range filter (if month provided, use start/end of month; if week provided, use start/end of week). Apply category, price range, and location filters. Join with pricing_windows to get current prices and ticket_inventory to get stock levels. Group events by date. Calculate availability status per date (available if any tickets available, low if <20% remaining, sold_out if 0). Return { dates: [{date, eventCount, availability, events: [{id, title, organizer, startTime, venue, startingPrice, ticketsAvailable}]}], month, week }. Rate limit: 30/min per IP.

2. GET /api/events/public/calendar/day/:date — Day detail view. URL param: date (ISO8601 YYYY-MM-DD). Query params: ?category, ?priceMin, ?priceMax, ?location, ?sortBy=date|price|popularity (default: date). Process: Validate date format using DayDetailRequest. Query events where status='published' and event_date matches the provided date. Apply optional filters. Join with pricing_windows, ticket_inventory, and organizers. Sort by requested field. Return { date, events: [{id, title, organizer: {id, name, avatar, brandingColors}, startTime, endTime, venue, description, bannerUrl, ticketTiers, ticketsSold, trending}], total }. If no events found, return 404. Rate limit: 30/min per IP.

3. GET /api/events/public/calendar/range — Date range view. Query params: ?startDate=2024-03-01 (required, ISO8601), ?endDate=2024-03-31 (required, ISO8601), ?category, ?priceMin, ?priceMax, ?location. Process: Validate date range using RangeRequest (startDate < endDate, both valid ISO8601). Query events where status='published' and event_date between startDate and endDate. Apply optional filters. Join with pricing_windows and ticket_inventory. Group events by date. Calculate availability status per date. Return { startDate, endDate, dates: [{date, eventCount, availability, events}], totalEvents }. Rate limit: 30/min per IP.

For all endpoints: Use EventCalendarService to handle the business logic (filtering, grouping, availability calculation). Return proper HTTP status codes: 200 for success, 400 for invalid params, 404 for not found, 500 for server errors. Add rate limiting middleware to prevent scraping.
