We need to add routes for the two compliance pages and make them accessible only to admins.

On the frontend (React), add two routes to your router:
- /admin/compliance/audit-logs → AuditLogsViewerPage
- /admin/compliance/reports → ComplianceReportsPage

Both routes should be protected by an admin-only guard. If a non-admin user tries to access these routes, redirect them to a 'Not Authorized' page or the home page.

Add navigation links in the admin dashboard or settings area:
- In the admin sidebar or menu, add a 'Compliance' section with two links: 'Audit Logs' and 'Compliance Reports'
- Both links should only appear if the current user has 'Admin' role

On the backend (Laravel), add the routes to routes/api.php:
- GET /api/admin/compliance/audit-logs/list
- GET /api/admin/compliance/audit-logs/:logId/details
- GET /api/admin/compliance/audit-logs/export
- POST /api/admin/compliance/audit-logs/bulk-tag
- POST /api/admin/compliance/reports/generate
- GET /api/admin/compliance/reports/list (for fetching generated reports)
- GET /api/admin/compliance/reports/:reportId/download (for downloading a generated report)
- GET /api/admin/compliance/checklist (for fetching compliance checklist status)

All routes should be protected by middleware that checks for admin role. Use Laravel's authorization policies (AuditLogPolicy, ComplianceReportPolicy) to enforce access control.

When a user navigates to /admin/compliance/audit-logs or /admin/compliance/reports, the page should load the initial data from the backend API. If the user's session expires (401 response), redirect to the login page and then back to the compliance page after re-authentication.
