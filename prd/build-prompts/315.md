We need to make sure errors don't break the user experience and provide helpful guidance to venue staff.

VenueCheckInPage errors:

1. Camera initialization failures:
   - Camera permission denied: Show a full-screen message 'Please enable camera access' with a button to open device settings. Don't retry automatically.
   - Camera hardware not available: Show 'Camera not available on this device' with a link to use manual entry instead.
   - Camera stream error (e.g., camera in use by another app): Show 'Camera is in use. Please close other apps and try again.'

2. QR scanning errors:
   - Invalid/unreadable QR code: Show a brief notification 'Invalid QR code' but keep scanning. Don't block the camera.
   - QR code detected but decryption fails: Show 'QR code corrupted or invalid' with a red badge. Suggest manual entry.
   - Malformed qrCodeData: Show 'This QR code is not valid for this event' with a red badge.

3. Ticket verification errors (from POST /api/tickets/verify-qr):
   - Ticket not found (404): Show 'Ticket not found' with a red badge. Suggest searching manually.
   - QR code expired: Show 'QR code expired' with a gray badge. Suggest contacting the organizer.
   - Ticket already checked-in: Show 'Already checked in at HH:MM' with an amber badge and the timestamp.
   - Ticket void: Show 'This ticket is invalid' with a red badge.
   - Ticket fraud-flagged: Show 'This ticket is blocked' with a red badge and a message to contact support.
   - Network error: Show 'Network error. Check your connection.' with a 'Retry' button. If offline, show 'Offline mode - limited functionality'.
   - Rate limited (429): Show 'Too many scans. Please wait a moment.' with a countdown timer.
   - Unauthorized (403): Show 'You do not have permission to scan tickets' with a message to contact the organizer.

4. Check-in action errors (from POST /api/tickets/:ticketId/check-in):
   - Check-in succeeds: Show a green checkmark and 'Checked in successfully' with the attendee name and timestamp.
   - Check-in fails because ticket just sold out: Show 'Sorry, this ticket just sold out' and update the ticket status to reflect this.
   - Check-in fails because ticket is void: Show 'This ticket is invalid' with a red badge.
   - Check-in fails because ticket is already checked-in: Show 'Already checked in at HH:MM' (this shouldn't happen if verify-qr worked, but handle it anyway).
   - Network error during check-in: Show 'Failed to check in. Please try again.' with a 'Retry' button. If offline, cache the check-in and show 'Cached - will sync when online'.
   - Rate limited (429): Show 'Too many check-ins. Please wait a moment.' with a countdown timer.

5. Void action errors (from POST /api/tickets/:ticketId/void):
   - Void succeeds: Show 'Ticket voided successfully' with a confirmation.
   - Void fails because user is not Organizer/Admin: Show 'You do not have permission to void tickets'.
   - Void fails because ticket is already void: Show 'This ticket is already void'.
   - Void fails because reason is missing or too long: Show 'Please provide a reason (max 500 characters)'.
   - Network error: Show 'Failed to void ticket. Please try again.' with a 'Retry' button.

6. Sync errors (from GET /api/venue/check-in/sync):
   - Sync succeeds: Update the real-time metrics (totalCapacity, totalCheckedIn, remainingCapacity) and show 'Synced' status.
   - Sync fails due to network error: Show 'Sync failed' with a yellow indicator. Retry automatically every 10 seconds.
   - Sync fails due to unauthorized (403): Show 'You are not authorized for this event'.
   - Sync fails due to event not found (404): Show 'Event not found'.
   - Sync timeout (>5 seconds): Show a warning 'Sync taking longer than expected' but keep trying.

7. Auth token expiration:
   - If any API call returns 401, attempt to refresh the token automatically.
   - If token refresh succeeds, retry the original API call.
   - If token refresh fails, redirect to the login page with a message 'Your session expired. Please log in again.'
   - After login, redirect back to /venue/check-in/:eventId so the staff member can continue.

8. Offline mode:
   - When internet is lost, show 'Offline mode - limited functionality' with a red indicator.
   - Allow check-ins to be cached locally (show 'Cached - will sync when online').
   - Show a badge with the count of pending check-ins.
   - When connection is restored, automatically sync cached check-ins.
   - If sync fails after connection is restored, show 'Sync failed. Please try again.' with a 'Retry' button.

Error message guidelines:
- Use plain language, not technical jargon. Say 'Camera not available' not 'Camera device initialization failed'.
- Be specific about what went wrong and what the user should do next.
- Use color coding: red for errors, amber for warnings, green for success.
- Show errors as toast notifications (brief, auto-dismiss) for non-blocking issues.
- Show errors as full-screen messages or modals for blocking issues (camera permission, auth failure).
- Include a 'Retry' button for transient errors (network, rate limit).
- Include a 'Contact Support' link for persistent errors.
