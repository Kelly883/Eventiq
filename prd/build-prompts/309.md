We need to make sure the analytics feature fails gracefully and gives users helpful error messages.

SalesAnalyticsDashboardPage:
- Network failure on initial load → show a full-screen error banner with 'Failed to load analytics' and a 'Retry' button. Don't show partial data.
- Network failure during auto-refresh → show a brief toast notification 'Data refresh failed' but keep the existing metrics on screen. The user can manually tap refresh to try again.
- 401 (session expired) → show a toast 'Your session expired' and redirect to login page after 2 seconds
- 403 (not organizer) → show a full-screen message 'Access Denied — only event organizers can view analytics' with a 'Back' button
- 404 (event not found) → show 'Event not found' with a link to the events list
- 500 (server error) → show an error banner with 'Something went wrong' and a 'Retry' button
- Invalid date range → show a validation error 'Invalid date range' and don't make the API call
- Rate limited (429) → show a toast 'Too many requests, please wait a moment' and disable the refresh button for 60 seconds

DetailedAnalyticsPage:
- Network failure on tab load → show a loading error state in that tab 'Failed to load data' with a 'Retry' button. Other tabs remain unaffected.
- 401, 403, 404, 500 → same as dashboard
- Empty data (no transactions) → show 'No transaction data available' in the Transactions tab, 'No funnel data' in Funnel tab, etc.
- Large dataset performance → if the transaction table is slow, show a message 'Loading large dataset...' and implement pagination or cursor-based loading

AnalyticsComparisonPage:
- Network failure loading event list → show 'Failed to load events' with 'Retry' button
- Network failure loading comparison data → show 'Failed to load comparison' with 'Retry' button
- 401, 403, 500 → same as dashboard
- Only 1 event exists → show 'Create more events to compare performance' message
- No events → show 'No events found'

Export functionality:
- Export fails → show a toast 'Failed to export report, please try again'
- Export succeeds → show a toast 'Report exported successfully' with the filename
- Large export takes time → show a progress indicator or 'Generating report...' message

General error handling:
- All error messages should be user-friendly, not technical jargon
- Show the error message in a toast or banner, not a modal (modals are disruptive)
- Provide a 'Retry' button for transient errors (network failures)
- For auth errors (401, 403), provide a clear next step (login, contact support)
- Log all errors to a monitoring service (Sentry, LogRocket) with context (page, endpoint, user ID, timestamp)
- Don't show raw error codes or stack traces to the user
- For 500 errors, show a support contact or error ID so users can report the issue

Implement error boundaries at the page level so a crash in one chart doesn't break the entire page. If a chart fails to render, show 'Chart failed to load' instead of crashing.

Handle edge cases:
- What if the date range is in the future? Show 'No data available for future dates'
- What if the tier filter doesn't exist? Show 'Tier not found' and reset the filter
- What if the event is deleted while viewing analytics? Show 'Event no longer available' and redirect to events list
- What if the user loses internet mid-refresh? Show 'Connection lost' and retry when connection returns
