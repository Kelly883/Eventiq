We need to build six API endpoints in Laravel that handle all the check-in operations. Here's what each one does:

1. GET /api/venue/check-in/search — Search for attendees by ticket ID, email, or name. Takes query params: eventId (required UUID), query (required, min 2 chars), limit (optional, default 10). Verify the user is authenticated and has VenueStaff or Organizer role. Query the tickets table filtered by eventId, searching across ticket_id (exact match), attendee_email (partial match), and attendee_name (partial match). Return paginated results with ticket status and check-in time if applicable. Rate limit: 60 searches/min per user.

2. POST /api/venue/check-in/bulk — Check in multiple tickets at once. Takes: eventId (required UUID), ticketIds (required array, max 100), venueId (optional). For each ticket: verify it exists, check status is 'valid', check for fraud flags, update status to 'checked_in', set checked_in_at and checked_in_by. Create audit log entries. Return results with success/failure per ticket. Idempotent — checking in the same ticket twice returns success but doesn't double-count. Rate limit: 30 bulk operations/min per user.

3. GET /api/venue/check-in/stats — Get real-time check-in statistics. Takes: eventId (required URL param), lastUpdateAt (optional query param for incremental updates). Return: totalCapacity, totalCheckedIn, totalRemaining, totalVoid, checkInRate (percentage), lastUpdateAt. If lastUpdateAt is provided, only return changes since that timestamp. Rate limit: 60 stats/min per user.

4. POST /api/venue/check-in/detect-duplicate — Detect duplicate check-in attempts. Takes: eventId (required UUID), qrCodeData (required, encrypted payload), ticketId (optional fallback). Decrypt qrCodeData server-side using AES-256 to extract the ticket ID. Query the ticket, check if already checked in, query fraud_events for duplicate flags. Return: ticketId, isDuplicate (boolean), previousCheckInAt (if duplicate), previousCheckInBy (if duplicate), riskLevel ('low'|'medium'|'high'), message. Rate limit: 60 detections/min per user.

5. POST /api/venue/check-in/offline-sync — Sync offline check-ins when back online. Takes: eventId (required UUID), localCheckIns (required array of {ticketId, checkedInAt, checkedInBy}), lastSyncAt (optional ISO8601). For each local check-in: verify ticket exists, check if already synced (compare timestamps), update status if not already checked in, create audit log. Return: synced (count), conflicts (count), results (per-item status), serverCheckIns (current server state for cache update). Rate limit: 10 syncs/min per user.

6. GET /api/venue/check-in/export — Export check-in data as CSV or JSON. Takes: eventId (required URL param), format (optional 'csv'|'json', default 'csv'), includeNoShows (optional boolean, default false), startTime (optional ISO8601), endTime (optional ISO8601). Query tickets filtered by eventId and status='checked_in', optionally by time range. If includeNoShows=true, also include status='valid' tickets. Return file stream with appropriate Content-Type and Content-Disposition headers. Rate limit: 5 exports/min per user.

All endpoints must:
- Verify auth token and extract userId
- Check user has VenueStaff or Organizer role via Policy
- Verify user is authorized for the event
- Return 401 for missing/invalid auth, 403 for unauthorized, 404 for not found
- Implement the specified rate limits
- Log all actions to audit_logs table
