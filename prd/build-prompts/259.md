Now we need to connect the three delivery pages to the rest of the app so users can actually reach them.

Add routes for: /my-tickets/:ticketId/status (TicketStatusPage), /settings/delivery-preferences (DeliverySettingsPage), and /admin/delivery/dashboard (AdminDeliveryDashboardPage).

On the existing my-tickets page, add a way to view delivery status — either a 'View Status' button on each ticket card or a status badge that links to the status page.

On the existing settings page, add a 'Delivery Preferences' link or tab that navigates to DeliverySettingsPage.

On the existing admin dashboard, add a 'Delivery' section or tab that navigates to AdminDeliveryDashboardPage. Restrict this route to users with the 'Admin' role — if a non-admin tries to access it, redirect to the home page with an 'Access Denied' toast.

Wire up these connections:
- When 'Resend Ticket' succeeds on TicketStatusPage, show a success toast with 'Ticket resend initiated' and update the delivery history timeline
- When preferences are saved on DeliverySettingsPage, show a success toast with 'Preferences saved'
- When email/phone verification succeeds, show a success toast and update the verification status indicator
- Back button from TicketStatusPage goes back to my-tickets
- Back button from DeliverySettingsPage goes back to settings
- Back button from AdminDeliveryDashboardPage goes back to admin dashboard
- Deep links to /my-tickets/:ticketId/status should work from email links or push notifications (including when the user isn't logged in — redirect to login first, then back to the ticket status page)
