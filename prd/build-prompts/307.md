We need to make sure errors don't break the user experience and provide helpful feedback.

Client-side error handling:
- Validation errors: When the user tries to save invalid tiers, show a clear error message for each invalid field (e.g., 'Price must be greater than 0', 'Early bird price must be less than regular price'). Highlight the problematic tier so the user knows which one to fix.
- Network errors: If the save request fails due to no internet connection, show 'Check your connection and try again' with a retry button.
- Server errors (400, 401, 403, 404, 500): Map each error code to a user-friendly message:
  - 400: 'Invalid tier data. Please check your entries and try again.'
  - 401: 'Your session expired. Please log in again.'
  - 403: 'You don't have permission to edit this event.'
  - 404: 'Event not found.'
  - 500: 'Server error. Please try again later.'
- Loading failures: If loading existing tiers fails, show an error message with a 'Retry' button.
- Unsaved changes: If the user navigates away with unsaved changes, show a confirmation dialog (not a silent discard).

UI feedback:
- Show a loading spinner while saving (disable the form so the user can't make changes while saving).
- Show a success toast after saving: 'Ticket tiers updated successfully'.
- Show error toasts for failures: 'Failed to save tiers: [error message]'.
- Keep the form open and editable after an error so the user can retry without losing their work.

Edge cases:
- If a tier is deleted on the backend while the user is editing it, handle the conflict gracefully (reload and show a message).
- If the event is deleted while the user is editing tiers, show 'Event no longer exists' and redirect to the event list.
- If the user's session expires mid-save, redirect to login and preserve the form data so they can retry after logging back in.
