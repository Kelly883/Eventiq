We're building an attendee check-in system for venue staff. For this step, I need you to create the React frontend pages that let staff search for attendees, check them in, and monitor real-time statistics.

Create three main pages:

1. CheckInDashboardPage at /check-in/:eventId — This is the main hub. At the top, show a large search bar that queries GET /api/venue/check-in/search as the user types (debounce 300ms, minimum 2 characters). Below the search bar, display real-time statistics from GET /api/venue/check-in/stats: total capacity, total checked in, total remaining, total void, and check-in rate percentage. Show these as large cards with clear numbers. Below that, show a list of recent check-ins (last 10) with attendee name, ticket tier, and check-in time. The page should auto-refresh stats every 5 seconds using the lastUpdateAt parameter for incremental updates (don't re-fetch everything). Handle loading states with skeleton cards and error states with a retry button.

2. SearchResultsPanel (integrated into CheckInDashboardPage, not a separate page) — When the user searches, show results below the search bar as a scrollable list. Each result shows: ticket ID, attendee name, tier, current status (valid/checked-in/void), and a check-in button. Clicking the check-in button calls POST /api/venue/check-in/bulk with that single ticket. Show a success toast when check-in completes. If the ticket is already checked in, show a disabled button with 'Already Checked In' label. If it's void or flagged for fraud, show a warning badge and disable the button.

3. BulkCheckInPage at /check-in/:eventId/bulk — For checking in multiple tickets at once. Show a text area where staff can paste or manually enter ticket IDs (one per line, or comma-separated). Add a 'Check In All' button that calls POST /api/venue/check-in/bulk with all the IDs. Show a progress indicator while processing. After completion, display a summary: X checked in successfully, Y already checked in, Z failed (with reasons). Show a 'Download Report' button that calls GET /api/venue/check-in/export with format=json.

All pages should:
- Check authentication on load — if no token, redirect to login
- Verify the user has VenueStaff or Organizer role — if not, show 'Access Denied'
- Display the event name prominently at the top
- Include a 'Back to Events' link to return to the event list
- Handle offline scenarios gracefully (show a banner if offline, queue actions for sync when back online)
- Use the offline-sync endpoint (POST /api/venue/check-in/offline-sync) to sync queued check-ins when connectivity returns
