Frontend (React + Vite):
- pages/ — for EventCalendarPage and CalendarDayDetailModal
- components/ — for reusable UI pieces like EventCard, CalendarGrid, FilterSidebar, SearchBar, DateHeader, AvailabilityIndicator, ViewToggle
- hooks/ — for custom React hooks like useCalendarEvents, useEventFilters, useDateSelection, useRealTimeInventory
- types/ — for TypeScript interfaces (Event, TicketTier, PricingWindow, TicketInventory, Organizer, CalendarDate)
- services/ — for API client functions (fetchCalendarEvents, fetchDayEvents, fetchEventRange, applyFilters)
- utils/ — for helper functions (formatDate, calculateAvailabilityStatus, groupEventsByDate, debounceSearch)
- styles/ — for component-specific CSS or Tailwind utilities

Backend (Laravel):
- Create app/Http/Controllers/EventCalendarController.php for the three public endpoints
- Create app/Http/Requests/ for request validation (CalendarFilterRequest, DayDetailRequest, RangeRequest)
- Create app/Services/EventCalendarService.php for business logic (filtering, grouping, availability calculation)
- Create database/migrations/ for any calendar-specific database adjustments
- Create routes/api.php entries for the three public endpoints

This structure keeps calendar logic separate from other event features and makes it easy to scale.
