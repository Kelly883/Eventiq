We need to make sure only authorized organizers can manage ticket tiers for their events.

On the frontend:
- Check that the user is authenticated before rendering the ticket tier management page. If not, redirect to login.
- Verify that the user is an organizer (has the organizer role) before allowing access to the ticket tier editor. If not, show a 'Not authorized' message.
- Include the bearer token in the Authorization header when making the PATCH request to /api/organizer/events/:eventId.
- Validate all tier data on the client side before sending to the backend (price positive, quantity positive, dates logical, etc.).

On the backend (Laravel):
- The PATCH /api/organizer/events/:eventId endpoint should check that the authenticated user is the event organizer (via the Policy: [user_id] == [AUTH_USER_ID]).
- Validate all incoming tier data: name required and non-empty, price required and positive, quantity required and positive, early bird price (if set) must be less than regular price, dates must be in logical order, max per customer (if set) must be positive.
- Use database transactions to ensure that if any tier fails to save, the entire operation rolls back (no partial updates).
- Never trust client-side validation — always re-validate on the server.
- Return 401 if the user is not authenticated, 403 if the user is not the event organizer, 400 if validation fails, 404 if the event doesn't exist.

Make sure the bearer token is stored securely in the frontend (in memory or a secure cookie, never in localStorage for sensitive tokens) and is included in every API request.
