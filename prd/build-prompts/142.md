We need to build five API endpoints that handle reading inventory data, adjusting stock, exporting reports, and viewing the audit log. All endpoints require authentication and enforce event ownership via Laravel Policy.

1. GET /api/organizer/events/:eventId/inventory/summary
   Returns a high-level overview of inventory across all tiers. Query the ticket_inventory table filtered by eventId, aggregate totals, and calculate utilization percentage. Return { totalCapacity, totalSold, totalAvailable, utilizationPercentage, lowStockTierCount, tiers: [{ tierId, tierName, allocated, sold, available, isLowStock }] }. Rate limit: 20/min per user.

2. GET /api/organizer/events/:eventId/inventory
   Returns detailed inventory with pricing windows nested. Support query params: ?tierFilter=uuid (optional), ?sortBy=allocated|sold|available (default: allocated), ?sortOrder=asc|desc (default: desc). Eager load pricing_windows for each tier. Return { tiers: [{ tierId, tierName, basePrice, totalAllocated, totalSold, totalAvailable, utilizationPercentage, isLowStock, lowStockThreshold, pricingWindows: [{ windowId, windowName, startDateTime, endDateTime, quantityLimit, quantitySold, quantityAvailable, isActive, priority }] }] }. Rate limit: 20/min per user.

3. PATCH /api/organizer/events/:eventId/inventory/adjust
   Manually adjust inventory for a tier or pricing window. Request body: { tierIdOrWindowId (string, required), newQuantity (integer, required, >= 0), reason (string, optional, max 500 chars) }. Validate that newQuantity doesn't exceed event capacity. Use a database transaction to atomically update ticket_inventory or pricing_windows and create an inventory_adjustments audit record. Return { tierId, tierName, newQuantity, previousQuantity, quantityDelta, message: 'Inventory adjusted successfully' }. Rate limit: 5/min per user to prevent abuse.

4. GET /api/organizer/events/:eventId/inventory/export
   Export inventory data as CSV or JSON. Query params: ?format=csv|json (default: csv), ?includeHistory=true|false (default: false). If includeHistory=true, include inventory_adjustments records. Set appropriate Content-Type and Content-Disposition headers. Return file stream. Rate limit: 10/min per user.

5. GET /api/organizer/events/:eventId/inventory/audit-log
   Return paginated audit log of all inventory adjustments. Query params: ?tierFilter=uuid (optional), ?organizerFilter=uuid (optional), ?adjustmentType=manual_increase|manual_decrease|reallocation|system_correction (optional), ?page=1 (optional), ?limit=50 (optional). Eager load organizer and tier details. Sort by createdAt descending (most recent first). Return { adjustments: [{ id, tierId, tierName, organizerId, organizerName, adjustmentType, quantityBefore, quantityAfter, quantityDelta, reason, createdAt }], total, page, limit }. Rate limit: 20/min per user.

All endpoints must:
- Check authentication (bearer token required, return 401 if missing/invalid)
- Enforce event ownership via Policy (return 403 if user doesn't own event)
- Validate input server-side (return 400 for invalid params)
- Handle errors gracefully (return 404 for not found, 500 for database errors)
- Log all write operations (inventory adjustments) to inventory_adjustments table with organizerId and timestamp
