We need state management to handle offline sync settings, cached tickets, and sync status across the app.

Create three state managers:

1. OfflineSyncDevicesState — Tracks the list of registered devices with their offline_enabled status and last_sync_at timestamps. Should support: loading the device list on page open, toggling offline_enabled for a device (optimistic update — update UI immediately, revert on error), and updating last_sync_at after a successful sync. This state should be accessible from OfflineSyncSettingsPage.

2. CachedTicketsState — Stores the tickets fetched from GET /api/me/tickets/for-offline-sync, grouped by event. Should support: loading cached tickets (calls the endpoint), clearing cached data, and checking if data is stale (compare last_sync_at to current time). This state should persist to localStorage so tickets are available even after the app closes. When the app starts, check localStorage first — if cached data exists and is less than 24 hours old, use it. Otherwise, fetch fresh data. This state should be accessible from OfflineTicketsPage.

3. OfflineSyncStatus — Tracks whether a sync is in progress, the last sync timestamp, and any sync errors. Should support: starting a sync (calls GET /api/me/tickets/for-offline-sync), handling success (updates CachedTicketsState and OfflineSyncDevicesState), and handling errors (stores the error message). This state should be accessible from both pages.

All three should handle loading, success, and error states cleanly. Don't let the pages handle API calls directly — they should just call methods on these state managers and react to state changes.

For localStorage persistence, store the cached tickets as JSON with a timestamp. When reading, check if the data is stale (older than 24 hours) and refresh if needed. Make sure to handle localStorage quota limits gracefully (if the data is too large, show a warning and offer to clear old data).
