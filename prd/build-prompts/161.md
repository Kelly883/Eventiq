We need to build nine API endpoints across three controllers. All endpoints require authentication and use Laravel Policies to ensure users only access their own data.

ApiKeyController (app/Http/Controllers/Developer/ApiKeyController.php):

1. GET /api/developer/api-keys — List the authenticated organizer's API keys. Use the ApiKeyResource to return only safe fields (never the hashed_key). Filter by organizer_id using the authenticated user's ID. Return a paginated list (20 per page). Use a Laravel Policy to ensure the user is an organizer.

2. POST /api/developer/api-keys — Create a new API key. Accept name (required, string), scopes (required, array of valid scope strings), and expiresAt (optional, timestamp). Generate a raw key using ApiKey::generateKey(), hash it with Hash::make(), and store the hash. Return the raw key ONCE in the response (in a modal on the frontend) — it's never retrievable again. Create an AuditLog entry with action='api_key_created'. Validate input with a FormRequest.

3. DELETE /api/developer/api-keys/:keyId — Revoke an API key (soft delete). Set revoked_at to the current timestamp. Use a Laravel Policy to ensure the user owns the key. Create an AuditLog entry with action='api_key_revoked'.

WebhookController (app/Http/Controllers/Developer/WebhookController.php):

4. GET /api/developer/webhooks — List the authenticated organizer's webhooks. Use the WebhookResource to return all fields except the secret. Filter by organizer_id. Return a paginated list.

5. POST /api/developer/webhooks — Create a new webhook. Accept url (required, valid URL), subscribedEvents (required, array of event types like 'order.created', 'ticket.checked_in'). Generate a secret using Webhook::generateSecret(). Set status to 'active'. Create an AuditLog entry. Validate with a FormRequest.

6. DELETE /api/developer/webhooks/:webhookId — Delete a webhook. Use a Laravel Policy to ensure the user owns it. Create an AuditLog entry with action='webhook_deleted'.

ApiLogController (app/Http/Controllers/Developer/ApiLogController.php):

7. GET /api/developer/api-logs — Retrieve recent API call logs for the authenticated organizer. Query the AuditLog table for entries where action='api_call' and user_id matches the organizer. Return a paginated list (reverse chronological, newest first). Include fields: id, action, resourceType, resourceId, ipAddress, createdAt.

Public API endpoints (create new controller or add to existing):

8. GET /v1/events — Public API endpoint to list events. Authenticate using the ApiKeyMiddleware. Verify the API key has the 'events:read' scope. Return events as JSON using an EventResource. Support pagination and filtering by organizer.

9. POST /graphql — Single endpoint for all GraphQL queries and mutations. Use the ApiKeyMiddleware for authentication. Check scopes at the resolver level for each query/mutation (e.g., a query to fetch events requires 'events:read' scope). Use rebing/graphql-laravel to handle request parsing and execution.

All endpoints should return appropriate HTTP status codes: 200 for success, 201 for creation, 204 for deletion, 400 for validation errors, 401 for missing/invalid auth, 403 for insufficient permissions, 404 for not found, 500 for server errors.
