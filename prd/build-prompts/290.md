Let's make sure the push notification system is locked down and can't be abused.

Authentication and authorization:
- All four endpoints (POST /api/notifications/device-tokens, DELETE /api/notifications/device-tokens, GET/POST/PATCH/DELETE /api/admin/push-templates, POST /api/admin/push-templates/send-test) must require authentication. Check that the user has a valid Laravel Sanctum token before processing any request. Return 401 if the token is missing or invalid.
- The admin endpoints (/api/admin/push-templates and /api/admin/push-templates/send-test) must check that the user has the 'Admin' role. Use Laravel Policies to enforce this. Return 403 if the user is not an admin.
- The device token endpoints must check that the user_id in the request matches the authenticated user's ID. Users can only register/delete their own device tokens, never someone else's. Use Laravel Policies to enforce this.
- The delivery preferences endpoint (/api/users/me/delivery-preferences/update) must check that the user is updating their own preferences, not someone else's. Use Laravel Policies.

Data validation and sanitization:
- On the device token endpoints, validate that the token is a non-empty string and the device_type is one of 'web', 'ios', 'android'. Reject invalid inputs with 400.
- On the push template endpoints, validate that the name and type are non-empty strings. Validate that the title is max 65 characters and the body is max 178 characters. Sanitize all template content on the backend to prevent injection attacks (even though these are admin-only, defense in depth is good). Reject invalid inputs with 422.
- On the send-test endpoint, validate that the user_id exists and that the template content (title and body) are valid. Don't allow sending test notifications to non-existent users.

Rate limiting:
- Rate limit the device token endpoints to prevent token spam: 10 requests per minute per user.
- Rate limit the send-test endpoint to prevent abuse: 5 requests per minute per admin.
- Rate limit the delivery preferences update to prevent rapid toggling: 10 requests per minute per user.

Token security:
- Device tokens should be stored securely in the database (they're already in the push_notification_devices table). Make sure the token field is indexed for fast lookups but not exposed in API responses unless necessary.
- Never log or expose device tokens in error messages or debug output.

Admin-only operations:
- The admin template management endpoints should only be accessible to users with the 'Admin' role. This is enforced by Laravel Policies, but double-check that the Policy is applied to all four CRUD operations.
- The send-test endpoint should only be accessible to admins. Validate this on the backend.

User privacy:
- Users can only see and modify their own delivery preferences. Don't expose other users' preferences.
- Users can only see and delete their own device tokens. Don't expose other users' tokens.
- Admins can see all templates and send tests to any user, but they shouldn't be able to see other users' device tokens or preferences (unless there's a specific admin feature for that).
