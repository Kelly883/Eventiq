# Step 228 of 345: Set up state management for checkout flow

================================================================================

**Flow:** feature_secure-checkout-payment-processing

## 📋 PROMPT - Copy Everything Below and Paste into Your AI Assistant

================================================================================

We need state management to handle the checkout flow without making pages manage complex logic themselves.

Create a CheckoutContext (or use Zustand if that's your preference) that tracks: the current step (1, 2, or 3), form data for billing information, the payment intent client secret, loading states for each step, and any errors. This context should expose methods: goToStep(stepNumber), updateBillingInfo(data), setClientSecret(secret), setLoading(boolean), setError(message), and clearError().

Create a CartContext (if not already present) that manages the shopping cart: items array, loading state for item updates, and methods to add item, remove item, update quantity, and clear cart. Cart data should persist to local storage so it survives page refreshes. When the user navigates to checkout, the cart state should be passed along.

Create a TicketsContext that manages the user's tickets: tickets array, loading state, error state, and a method to fetch tickets from GET /api/my-tickets. This should be populated when UserTicketsPage mounts.

Create an OrderContext that manages order details: the current order object, loading state, error state, and a method to fetch order details from GET /api/orders/:orderId. This should be populated when OrderConfirmationPage mounts with the orderId from the URL.

All contexts should handle authentication state — if the user isn't authenticated when accessing a protected context, they should be redirected to login.
