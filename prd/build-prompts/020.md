We're building a refund and cancellation management system for an event ticketing platform. This feature spans both user-facing refund request flows and admin dashboards for managing refunds at scale.

On the frontend (React + Vite), create a refunds feature area under src/features/refunds/ with these subfolders:
- pages/ (for UserRefundRequestPage, UserRefundStatusPage, AdminRefundDashboardPage)
- components/ (for reusable UI pieces like status badges, timeline visualizations, refund calculation cards, appeal modals, filter bars, metric cards)
- hooks/ (for custom React hooks that handle refund data fetching and state)
- types/ (for TypeScript interfaces matching the refund_requests, refund_policies, and refund_appeals schemas)
- services/ (for API client functions that call the backend endpoints)
- utils/ (for helpers like refund amount calculators, status formatters, date utilities)

On the backend (Laravel), create a refunds module under app/Http/Controllers/ with:
- RefundController.php (handles POST /api/refunds/request)
- AdminRefundController.php (handles admin endpoints)
- RefundPolicy.php (Laravel authorization policy for refund_requests)
- RefundAppealPolicy.php (Laravel authorization policy for refund_appeals)
- RefundRequest model (Eloquent model for refund_requests table)
- RefundPolicy model (Eloquent model for refund_policies table)
- RefundAppeal model (Eloquent model for refund_appeals table)
- RefundService.php (business logic for refund calculations, eligibility checks, status transitions)

Also create database migrations for the three tables: refund_requests, refund_policies, and refund_appeals. These will define the schema with all required fields, indexes, and foreign keys.
