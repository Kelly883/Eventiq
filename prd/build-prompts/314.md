We need to make sure things fail gracefully when something goes wrong.

**UserDashboardPage:**
- Network failure on first load → show a full-screen error banner with a 'Retry' button (not a small notification — the page has no content yet)
- Failure while auto-refreshing → show a brief toast notification but keep the existing metrics and activity feed visible
- 401 (session expired) → show a 'Session expired' toast and redirect to login after 2 seconds
- 403 (access denied) → show 'Access Denied' message with a back button
- 500 (server error) → show error banner with 'Retry' button

**UserTicketsDashboardPage:**
- Network failure on first load → show a full-screen error with 'Retry' button
- Failure while loading more tickets → show a brief toast notification but keep the tickets that already loaded
- Filter or sort change fails → show a toast notification and revert to the previous filter/sort selection
- Search fails → show a toast notification but keep any previous search results on screen
- 401 (session expired) → show 'Sign in to view your tickets' toast and redirect to login
- 403 (access denied) → show 'Access Denied' with back button
- 500 (server error) → show error banner with 'Retry' button

**TicketDetailPage:**
- Network failure on first load → show a full-screen error with 'Retry' button
- 401 (session expired) → show 'Session expired' toast and redirect to login
- 403 (access denied) → show 'Access Denied — you don't own this ticket' with back button
- 404 (ticket not found) → show 'Ticket not found' message with a link back to /my-tickets
- 500 (server error) → show error banner with 'Retry' button
- 'Resend Ticket' fails → show a toast with 'Failed to resend. Try again.' and a retry option

**All Pages:**
- If the user's login expires (401), redirect to the login page after showing a toast
- Network timeouts (no response after 10 seconds) → show 'Connection timeout. Check your internet.' with retry
- Validation errors from the backend (400) → show the specific error message (e.g., 'Invalid filter value')
- Rate limit exceeded (429) → show 'Too many requests. Please wait a moment and try again.'
- For auto-refresh failures, don't interrupt the user — just silently fail and try again next cycle

**Error Message Guidelines:**
- Be specific and helpful: 'Failed to load tickets' is bad, 'No internet connection. Check your WiFi.' is good
- Don't show technical jargon or error codes to users
- Provide a clear action: 'Retry', 'Go Back', 'Sign In', etc.
- Use toast notifications for non-blocking errors (failed refresh, resend failed)
- Use full-screen errors or banners for blocking errors (no content to show, auth required)
- Show errors for 3-5 seconds before auto-dismissing (unless user interaction is needed)
