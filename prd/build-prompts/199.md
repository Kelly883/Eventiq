We're building an event discovery marketplace. For this step, I need you to build three pages that let users browse, search, and explore events.

**EventBrowsePage at /events** — This is the main event marketplace. Start with a hero section at the top containing a search bar with real-time autocomplete (calls GET /api/events/public/search as the user types, debounced to 300ms). Below the search, add a filter sidebar that's sticky on desktop and collapsible on mobile. The sidebar should have: a category dropdown, a date range picker with presets (Upcoming, This Week, This Month, Custom), a price range slider, and a location/venue search field. All filters should update the event list in real-time without page reload.

The main content area shows a responsive grid of event cards (1 column on mobile, 2 on tablet, 3 on desktop). Each card displays: thumbnail image, event title, organizer name with avatar, date/time, venue name, ticket availability status with color-coded badges (green for plenty, amber for low stock, red for sold out), starting price, and a social proof badge (trending/popular). Add a sort dropdown with options: relevance, date, price, popularity. Implement infinite scroll or pagination — when the user scrolls near the bottom, load the next page of results from GET /api/events/public/list. The 'Create Event' button should only show for authenticated organizers and route to /organizer/events/create. Update ticket availability badges every 30 seconds by re-fetching from the API.

Handling states: Loading shows 6 skeleton event cards with shimmer effect. Empty state (no events match filters) shows an illustration with 'No events found' message and a 'Clear filters' button. Error 500 shows an error banner with a retry button. Success displays the full event grid.

**EventDetailPage at /events/:eventId** — Shows comprehensive event information. Start with a hero banner image (full width, 300px height on mobile). Below that, display event title, organizer info (avatar, name, link to public profile), date/time, venue address with an embedded map, event capacity, and current attendance. Include a rich-text description section with images. Show ticket tier breakdown as a horizontal scrollable carousel on mobile or a grid on desktop — each tier card displays tier name (Regular, VIP, VVIP, Early Bird), current price, quantity available, and a 'Select Ticket' button. Display active pricing window information with a countdown timer to the next price change (fetch from GET /api/events/public/:eventId/pricing). Add a reviews/ratings section if implemented. Show related events from the same organizer (fetch from GET /api/events/public/:eventId/related). Include social media share buttons. Add an 'Add to Wishlist' button if the user is authenticated. Pin a sticky 'Buy Tickets' CTA button at the bottom that opens the checkout flow.

Handling states: Loading shows skeleton banner, placeholder text blocks, and shimmer ticket cards. Event not found or not published shows 'Event not found' with a link back to the browse page. Error 500 shows an error banner with retry. Success displays full event details with live-updating ticket availability.

**CategoryBrowsePage at /events/category/:categoryId** — Filtered event listing for a specific category. Start with a breadcrumb navigation showing 'Events > Category Name'. Add a category header with the category icon and description. The filter sidebar is the same as EventBrowsePage but with the category pre-selected and not removable. Show the same event grid below with all other filters (date, price, location, sort) available. Include a link to 'Browse all categories' that returns to the main browse page.

Handling states: Loading shows skeleton cards. Empty state shows 'No events in this category' with a 'Browse all events' link. Category not found shows 'Category not found' with a link back to browse. Error 500 shows an error banner. Success displays the filtered event grid.

All three pages should call the appropriate endpoints (GET /api/events/public/list, GET /api/events/public/search, GET /api/events/public/filters, GET /api/events/public/:eventId, GET /api/events/public/:eventId/pricing, GET /api/events/public/:eventId/related, GET /api/events/public/category/:categoryId) and apply organizer branding colors to event cards and CTA buttons for visual consistency. Use React Router for navigation and TanStack Query for data fetching.
