We need state management so the three event discovery pages don't handle data fetching themselves. Use TanStack Query for server state and Zustand for client state.

**TanStack Query hooks** — Create custom hooks for each data fetch:

1. useEventList — Fetches paginated events from GET /api/events/public/list. Accepts query params: page, limit, category, dateRange, priceMin, priceMax, sortBy, sortOrder. Manages loading, error, and pagination state. Supports infinite scroll by appending new pages to existing results instead of replacing them. Handles refetching when filters change.

2. useEventSearch — Fetches autocomplete suggestions from GET /api/events/public/search. Accepts a search query string. Debounces the query (300ms) so it doesn't fire on every keystroke. Returns suggestions array. Handles empty query (no suggestions shown).

3. useEventFilters — Fetches available filter options from GET /api/events/public/filters. Caches the result since this is static data. Returns categories, price range, and date range options.

4. useEventDetail — Fetches a single event from GET /api/events/public/:eventId. Accepts eventId as a parameter. Manages loading and error state.

5. useEventPricing — Fetches pricing and ticket tier details from GET /api/events/public/:eventId/pricing. Accepts eventId. Returns current prices, next price change info, and quantity available per tier.

6. useRelatedEvents — Fetches related events from GET /api/events/public/:eventId/related. Accepts eventId and limit. Returns events from the same organizer.

7. useCategoryEvents — Fetches paginated events for a category from GET /api/events/public/category/:categoryId. Accepts categoryId, page, limit, sortBy. Similar to useEventList but pre-filtered by category.

**Zustand store** — Create a store for client-side UI state that persists across page navigation:

1. Filter state — Tracks the current filter selections: selectedCategory, dateRange, priceMin, priceMax, locationSearch, sortBy, sortOrder. Provide actions to update each filter and a 'clearAllFilters' action.

2. Search state — Tracks the search query and whether search results are showing.

3. Wishlist state (if authenticated) — Tracks which events are wishlisted. Provide actions to add/remove from wishlist.

All state should be accessible from any page without prop drilling. The store should reset filters when navigating away from the browse page, but preserve them if the user navigates back (use browser history or session storage).

Implement real-time availability updates by setting up a polling mechanism in useEventList that re-fetches ticket availability every 30 seconds. Use TanStack Query's refetchInterval option.
