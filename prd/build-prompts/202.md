We're building a fraud detection system for admins to monitor and review suspicious transactions. You need to build two components that work together:

**FraudDetectionDashboardPage at /admin/fraud/dashboard** — This is the main admin interface for fraud monitoring. Start with a header showing three metric cards: total flagged transactions in the last 24 hours, a risk score distribution breakdown (low/medium/high counts with color-coded badges), and total blocked orders. Below that, build an interactive data table listing all flagged orders. Each row should show: order ID, transaction amount, buyer email, timestamp, risk score (with color-coded badge: green for low 0-30, amber for medium 31-70, red for high 71-100), and current status. Make the columns sortable by clicking the headers. Add a sticky filter bar above the table with dropdowns for: risk level (low/medium/high), date range picker (start/end dates), payment method filter, and a reason filter (duplicate_ticket_attempt, velocity_check_failed, etc.). When the user clicks on a row, expand it inline to show detailed fraud analysis: full transaction history, payment method fingerprint (card last 4, issuer, country), velocity metrics (orders per hour, total spend in 24h, average order value), and device/IP geolocation info. Include a bulk actions bar that lets admins select multiple flagged transactions and approve or reject them in batch. Add a 'Real-time updates' toggle that refreshes the table every 30 seconds when enabled. At the bottom right, add an 'Export as CSV' button that downloads all visible flagged transactions. For loading state, show skeleton metric cards and placeholder table rows with shimmer animation. For empty state (no flagged transactions), show a friendly message 'No suspicious transactions detected' with an illustration. Handle errors: 401 redirects to login with a 'Session expired' toast, 403 shows 'Access Denied — only admins can view fraud dashboard' with a back button, 500 shows an error banner with a retry button.

**FraudTransactionReviewModal** — This modal opens when an admin clicks on a flagged transaction row in the dashboard. It displays comprehensive fraud analysis for that single order. Structure it as a scrollable card (max-width 2xl) with sections organized vertically: at the top, show order summary (order ID, amount, currency, timestamp); in the middle, show buyer information (email, name, IP address, device fingerprint) and payment method details (card last 4, issuer, country); at the bottom, show the fraud risk analysis. Display the risk score prominently with a color-coded badge. Break down the risk score by category: payment velocity score, duplicate detection score, device fingerprinting score, and geolocation mismatch score. Show the fraud factors that triggered the flag (e.g., 'Duplicate ticket detected', 'High velocity pattern', 'Device fingerprint mismatch'). Include an optional notes field where the admin can document their decision. At the bottom of the modal, make the action buttons sticky: 'Approve Transaction' (green) and 'Reject Transaction' (red). When the admin clicks either button, show a confirmation dialog asking them to confirm the action before it's applied. For loading state, show skeleton sections with shimmer effect. For error state, show 'Unable to load transaction details' with a close button. While submitting, show a spinner on the action button and disable the form.

Both pages should call the backend endpoints: FraudDetectionDashboardPage calls GET /api/admin/fraud/flagged-transactions to load the table data, and FraudTransactionReviewModal calls GET /api/admin/fraud/transaction-details/:fraudEventId to load detailed fraud analysis. When the admin approves or rejects a transaction, call POST /api/admin/fraud/review-transaction with the decision and optional notes.

Make sure both pages are mobile-responsive: on mobile, the dashboard should stack the metric cards vertically and show a collapsible table (tap a row to expand details instead of inline expansion). The modal should use full-width layout on mobile.
