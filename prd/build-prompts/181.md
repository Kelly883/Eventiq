We need several reusable React components that will be shared across the three refund pages (UserRefundRequestPage, UserRefundStatusPage, AdminRefundDashboardPage).

1. RefundStatusBadge — Takes a status string ('pending'|'approved'|'rejected'|'processing'|'completed'|'failed') and renders a color-coded badge. Amber for pending, green for approved, red for rejected, blue for processing, gray for completed/failed. Used on both user and admin pages.

2. RefundTimeline — Takes an array of status changes with timestamps and renders a vertical timeline visualization. Shows stages: submitted → under review → approved/rejected → processing → completed. Highlights the current stage. For mobile, simplifies to a vertical line with stage markers. Used on UserRefundStatusPage.

3. RefundCalculationCard — Takes originalAmount, refundPercentage, and refundMethod, and displays the calculation prominently. Shows: 'Original Price: $80 | Refund Percentage: 80% | Refund Amount: $64'. Sticky positioning on mobile. Used on UserRefundRequestPage.

4. RefundPolicyInfoCard — Takes a RefundPolicy object and displays key details: refund window (e.g., '14 days'), percentage allowed before event, percentage after event, processing time, and cancellation policy text. Used on UserRefundRequestPage to show the policy upfront.

5. RefundReasonSelect — A dropdown component that takes an array of allowed reasons from the policy and renders them as options. Includes descriptions for each reason (e.g., 'event_cancelled' → 'Event was cancelled'). Used on UserRefundRequestPage.

6. RefundMethodRadioGroup — Takes an array of allowed refund methods from the policy and renders them as radio buttons with descriptions. Options: 'original_payment_method' (refund to your original card), 'store_credit' (credit to your account), 'alternative_payment_method' (refund to a different card). Used on UserRefundRequestPage.

7. RefundHistoryList — Takes an array of refund status changes and renders them as a list with timestamps. Shows what changed, when, and by whom (if admin-reviewed). Used on UserRefundStatusPage.

8. AdminRefundTable — A data table component for the admin dashboard. Takes an array of RefundRequest objects and renders columns: ticket ID, event name, buyer email, refund amount, reason, status badge, submission date, and action buttons (approve/reject/view details). Supports sorting by clicking column headers and expandable rows for full details. Used on AdminRefundDashboardPage.

9. AdminMetricCard — Takes a metric name (e.g., 'Pending Refunds'), value (e.g., '24'), and trend indicator (up/down/neutral). Renders a card with the metric prominently displayed and a small trend indicator. Used on AdminRefundDashboardPage summary.

10. AppealModal — A modal component that takes a RefundRequest (with rejected status) and renders a form to submit an appeal. Includes a textarea for appeal reason, character counter, and submit button. Shows loading state while submitting. Used on UserRefundStatusPage.

11. RefundFilterBar — A sticky filter bar with dropdowns for: status (pending/approved/rejected/processing/completed), event, date range (from/to), refund amount range (min/max), and reason. Also includes a search field for ticket ID, email, or event name. Used on AdminRefundDashboardPage.

12. RefundMethodBadge — Takes a refund method string and renders a small badge showing the method (e.g., 'Original Card', 'Store Credit'). Used on both user and admin pages.
