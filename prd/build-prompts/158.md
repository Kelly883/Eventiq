We need five API endpoints for the audit logging and compliance system. All endpoints require admin authentication and should be rate-limited to prevent abuse.

1. GET /api/admin/compliance/audit-logs/list — The main audit log listing endpoint. Accept query params: page (default 1), limit (default 50, max 100), action (optional, filter by action type), targetType (optional), status (optional), startDate and endDate (ISO8601, optional), classification (optional), sortBy (createdAt, action, or status), sortOrder (asc or desc). Verify the user is authenticated and has 'Admin' role. Query auditLogs filtered by all the provided params. Eager load the related User for actor names. Calculate summary metrics: total events in date range, success rate percentage, failed events count, retention days remaining. Return paginated results with metrics. Mask sensitive data (IP addresses) in the response. Rate limit: 20 requests/min per user.

2. GET /api/admin/compliance/audit-logs/:logId/details — Get full details of a single audit log. Accept logId as URL param (UUID). Verify admin role. Query the specific audit log by ID. Eager load related User and target entity details. Decrypt sensitive fields if needed. Return the complete audit event with all context: id, timestamp, action, actor details, targetType, targetId, targetDetails, status, ipAddress (masked), userAgent, geolocation, requestData (sanitized), responseData (sanitized), changedFields, errorMessage, errorCode, complianceClassification, retentionDate, metadata. Rate limit: 20 requests/min per user.

3. GET /api/admin/compliance/audit-logs/export — Export filtered audit logs as CSV or JSON. Accept query params: format (required: csv or json), startDate, endDate, action, targetType, classification (all optional). Verify admin role. Query auditLogs filtered by the provided params. Sanitize sensitive data before export (mask IPs, remove raw request/response bodies). Format as CSV or JSON based on the format param. Set appropriate Content-Type and Content-Disposition headers for file download. Stream the file to the client. Log this export action to auditLogs with action='data_export_requested', classification='sox_financial'. Rate limit: 5 exports/min per user to prevent abuse.

4. POST /api/admin/compliance/audit-logs/bulk-tag — Tag multiple audit logs for compliance review. Accept JSON body: { logIds: array of UUIDs (required, max 100), tag: string (required, e.g., 'compliance_review', 'incident_investigation', 'data_breach'), notes: string (optional, max 500 chars) }. Verify admin role. Validate that all logIds exist. Add the tag to metadata.tags array for each log. Create a new auditLog entry: action='audit_log_tagged', targetType='audit_log', metadata={tag, notes, taggedBy=userId}. Return success with count of tagged logs. Rate limit: 10 bulk operations/min per user.

5. POST /api/admin/compliance/reports/generate — Generate a compliance report asynchronously. Accept JSON body: { reportType: string (required: 'data_access'|'user_activity'|'payment_audit'|'refund_audit'|'data_retention'|'incident_report'), startDate: ISO8601 (required), endDate: ISO8601 (required), classification: string (optional), format: string (optional: 'pdf'|'csv'|'json', default 'pdf') }. Verify admin role. Validate date range (endDate > startDate, not in future). Queue the report generation as an async job and return immediately with jobId. The job should: query auditLogs filtered by date range and classification, generate the report based on type (data_access groups by targetType/targetId, user_activity groups by userId, payment_audit filters action='payment_*', refund_audit filters action='refund_*', data_retention shows retention dates, incident_report filters status='failed' or fraud events), format as PDF/CSV/JSON, store the file in storage at compliance-reports/{reportId}.{ext}, create a compliance_reports record, and log the action to auditLogs with action='compliance_report_generated', classification='sox_financial'. Return 202 status with jobId and estimated completion time. Rate limit: 5 report generations/min per user.

For all endpoints, implement proper error handling: 400 for invalid params, 401 for missing/invalid auth, 403 for non-admin users, 404 for not found, 500 for server errors. Use Laravel's authorization policies to check admin role.
