We need to make sure errors don't break the user experience and provide helpful feedback.

Network errors:
- If GET /api/admin/email-templates fails on page load, show an error banner with a 'Retry' button. The template list should be empty until retry succeeds.
- If GET /api/admin/email-templates/:templateId fails when selecting a template, show a notification: 'Failed to load template. Please try again.' Keep the previously selected template visible.
- If PATCH /api/admin/email-templates/:templateId fails during save, show a notification with the error message and a 'Retry' button. Keep the form populated so the user doesn't lose their edits.
- If DELETE /api/admin/email-templates/:templateId fails, show a notification: 'Failed to delete template. Please try again.' The template stays in the list.
- If POST /api/admin/email-templates fails during creation, show a notification with validation errors. Keep the form populated.
- If POST /api/admin/email-templates/send-test fails, show a notification: 'Failed to send test email. Check the recipient address and try again.'

Validation errors:
- If the user tries to save with an empty template name, show an inline error under the name field: 'Template name is required.'
- If the subject is empty, show: 'Subject is required.'
- If the HTML body is empty, show: 'Email body cannot be empty.'

Auth errors:
- If a 401 is returned, redirect to the login page.
- If a 403 is returned, show an 'Access Denied' page with a link back to the admin dashboard.

Server errors (5xx):
- Show an error banner: 'Something went wrong. Please try again later.' with a 'Retry' button.

All error notifications should auto-dismiss after 5 seconds or allow the user to dismiss manually.
