We're building a comprehensive accessibility and localization system. For this step, I need you to build three settings pages that let users customize their experience.

AccessibilitySettingsPage at /settings/accessibility — This is a full-featured accessibility control panel. Start with a vertical scrollable layout organized into four categories: Text, Colors, Motion, and Navigation. For Text settings, add a font size slider (12px to 24px, default 16px) with live preview showing how text looks with the selected size. Add line height, letter spacing, and word spacing adjusters (all with live preview). For Colors, add a high contrast toggle that switches to WCAG AAA color scheme, and a color blindness simulation dropdown with options: none, protanopia, deuteranopia, tritanopia. For Motion, add a toggle to reduce animations and transitions. For Navigation, add a focus indicator enhancement toggle and a keyboard shortcuts reference button that opens a modal showing all available shortcuts (Tab, Enter, Escape, etc.). On the right side (desktop) or below (mobile), show a live preview section that updates in real-time as the user adjusts settings. All settings should save automatically to the backend via PATCH /api/users/me/accessibility-preferences/update. Show a brief 'Settings saved' toast after each save. Load initial settings from GET /api/users/me/accessibility-preferences. Handle loading state with skeleton setting cards and shimmer effect. Handle errors: 401 redirects to login with 'Sign in to customize accessibility' toast, 403 shows 'Access Denied', 500 shows error banner with retry button.

LanguagePreferencePage at /settings/language — This page lets users choose their language and locale formatting. At the top, display a language selector grid showing all supported languages (English, Spanish, French, German, Portuguese, Chinese, Japanese, Arabic, etc.) with native language names and flag icons. Highlight the current language with a checkmark. When the user selects a language, the entire UI should immediately switch to that language (all labels, buttons, error messages, date/time formats). Below the language grid, show locale formatting options as grouped cards: date format selector (MM/DD/YYYY, DD/MM/YYYY, YYYY-MM-DD), time format (12-hour, 24-hour), currency display (USD, EUR, GBP, etc.), and number formatting (comma vs period for decimals). Add a preview section showing real-world examples of how dates, times, and numbers will be formatted with the current locale settings. For RTL languages like Arabic and Hebrew, automatically apply right-to-left layout. Support full keyboard navigation with arrow keys to navigate the language list. Load initial settings from GET /api/users/me/language-preferences. Save changes via PATCH /api/users/me/language-preferences/update. Handle loading state with skeleton language selector and placeholder preview. Handle errors: 401 redirects to login with 'Sign in to change language' toast, 403 shows 'Access Denied', 500 shows error banner with retry. Show brief loading state during language switch, then immediate UI update.

DeviceLocalizationSyncPage at /settings/device-localization — This page manages localization settings across multiple devices. Display a list of registered devices (phone, tablet, desktop) as cards, each showing: device name (editable), device type icon, current language preference, accessibility settings summary (font size, high contrast status), last sync timestamp, and sync status badge (green=synced, amber=pending, red=error). At the top, add sticky bulk action buttons: 'Sync All Settings to This Device' and 'Apply This Device's Settings to All Devices'. For each device, add individual actions: 'Edit Settings' and 'Remove Device'. Include a toggle to sync accessibility settings across all devices or keep device-specific settings. Show an offline sync status indicator with 'Pending sync' badge for devices that aren't currently online, with estimated sync time when they come online. Real-time sync status should update every 30 seconds. Load device list from GET /api/users/me/devices. Update device settings via PATCH /api/users/me/devices/:deviceId/localization-settings/update. Trigger bulk sync via POST /api/users/me/devices/sync-all. Handle loading state with skeleton device cards (3 devices) and shimmer effect. Handle empty state: show 'No devices registered' with illustration and 'Add Device' link. Handle errors: 401 redirects to login, 403 shows 'Access Denied', 500 shows error banner with retry. Show spinner on device card during sync operations and disable interactions.

On mobile, convert all three pages to full-width stacked layouts: accessibility settings cards stack vertically with preview below, language grid becomes a vertical list, device cards stack with collapsible action menus.

All three pages should use react-i18next for translations and react-axe for accessibility auditing during development.
