We need to create three database tables to support the API integration feature. Use Laravel migrations to create these tables:

1. api_keys table — Store API keys for organizers. Fields: id (uuid, primary key), organizer_id (uuid, foreign key to users), name (string), key_prefix (string, for display only), hashed_key (string, the bcrypt hash), scopes (json, array of scope strings like 'events:read', 'orders:read'), last_used_at (timestamp, nullable), expires_at (timestamp, nullable), revoked_at (timestamp, nullable for soft delete), created_at and updated_at (timestamps). Add indexes on organizer_id and key_prefix for fast lookups.

2. webhooks table — Store webhook endpoint configurations. Fields: id (uuid, primary key), organizer_id (uuid, foreign key to users), url (string, the endpoint URL), secret (string, for HMAC signature verification), subscribed_events (json, array of event types like 'order.created', 'ticket.checked_in'), status (string, enum: 'active', 'inactive', 'failed'), last_failure_at (timestamp, nullable), failure_count (integer, default 0), created_at and updated_at (timestamps). Add indexes on organizer_id and status.

3. webhook_delivery_logs table — Audit trail of webhook delivery attempts. Fields: id (uuid, primary key), webhook_id (uuid, foreign key to webhooks), event (string, the event type), payload (json, the full payload sent), status (string, enum: 'success', 'failed', 'pending'), response_code (integer, nullable, the HTTP response code), response_body (text, nullable, the response from the endpoint), duration_ms (integer, how long the delivery took), created_at (timestamp). Add indexes on webhook_id and created_at for efficient querying.

Run php artisan migrate to apply all migrations to the database.
