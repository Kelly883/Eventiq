Now we need to connect the check-in pages to the rest of the app so users can actually reach them.

Add routes:
- /check-in/:eventId → CheckInDashboardPage (main check-in hub)
- /check-in/:eventId/bulk → BulkCheckInPage (bulk check-in)

Add a navigation guard: both routes require authentication. If the user isn't logged in, redirect to /login. If they're logged in but don't have VenueStaff or Organizer role, show an 'Access Denied' page.

On the event details page (or wherever staff manage events), add a 'Start Check-In' button that navigates to /check-in/:eventId.

Wire up these connections:
- When a check-in succeeds, update the stats in real-time (don't wait for the next auto-refresh)
- When the user goes offline, show a banner at the top of the page
- When connectivity returns, automatically sync queued check-ins and show a confirmation
- Add a 'Download Report' link that calls GET /api/venue/check-in/export with the appropriate filters
- The search bar should be accessible from both the dashboard and bulk check-in pages (or provide a quick link between them)
