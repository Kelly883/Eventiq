Now we need to connect the offline sync feature to the rest of the app so it's accessible and works seamlessly.

Add routes for: /offline-sync-settings (OfflineSyncSettingsPage) and /offline-tickets (OfflineTicketsPage). Both should require authentication — if the user isn't logged in, redirect to login.

Add a way to access OfflineSyncSettingsPage from the main app: either a menu item in the settings/profile section or a dedicated 'Offline' tab in the bottom navigation (if the app has one). Label it something like 'Offline Sync' or 'Manage Offline Data'.

Wire up these connections:
- When the app starts, check if cached tickets exist in localStorage. If they do and are fresh (less than 24 hours old), make them available to OfflineTicketsPage without fetching.
- When the user goes offline (navigator.onLine becomes false), show a subtle indicator (like a small offline badge in the header or a toast notification) and enable access to OfflineTicketsPage if cached data exists.
- When the user comes back online, hide the offline indicator and refresh the cached data if it's older than 1 hour (or let the user manually refresh).
- From OfflineTicketsPage, include a 'Refresh' button that only appears when online — tapping it navigates to OfflineSyncSettingsPage and automatically triggers a sync.
- After a successful sync, show a brief confirmation message ('Tickets synced successfully') and update the last sync timestamp.

Make sure the offline sync feature doesn't interfere with the normal app flow — users who don't care about offline access shouldn't see it or be slowed down by it.
