We need type definitions and models so the frontend and backend speak the same language.

On the frontend (React/TypeScript), create types in src/features/dashboard/types/:

1. DashboardOverview — matches the GET /api/organizer/dashboard/overview response: totalRevenue (number), totalTicketsSold (number), averageConversionRate (number), upcomingEventCount (number), totalEventCount (number), revenueTrend ('up'|'down'|'flat'), ticketsTrend, conversionTrend, lastUpdatedAt (ISO string)

2. EventMetrics — for each event card: id (UUID), title (string), date (ISO string), status ('draft'|'upcoming'|'live'|'past'), thumbnailUrl (string), totalRevenue (number), totalTicketsSold (number), ticketsAvailable (number), utilizationPercentage (number), conversionRate (number)

3. EventDetail — for the EventDetailWidget: eventId, title, date, status, totalRevenue, totalTicketsSold, conversionRate, tiers (array of tier objects), pricingWindows (array of pricing window objects)

4. ActivityItem — for each sales activity feed item: id, eventId, eventName, tierId, tierName, quantity, unitPrice, totalAmount, saleTimestamp, buyerEmail

5. DashboardPreferences — matches organizer_dashboard_preferences: defaultEventFilter, defaultDateRange, expandedEventId, showActivityFeed, autoRefreshEnabled

On the backend (Laravel), create the OrganizerDashboardPreferences model with:
- Fillable properties for all mutable fields (defaultEventFilter, defaultDateRange, expandedEventId, showActivityFeed, autoRefreshEnabled)
- A belongsTo relationship to the Organizer model
- Accessor methods to return defaults if a preference record doesn't exist yet
- Timestamps (created_at, updated_at) handled automatically by Laravel

Also create or update Event, AnalyticsEventsMetrics, TicketTier, PricingWindow, and AnalyticsSalesTimeline models with proper relationships and eager loading setup.
