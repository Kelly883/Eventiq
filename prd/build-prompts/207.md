We're building an email notification system. For this step, I need you to create the AdminEmailTemplateManagementPage at /admin/settings/email-templates — this is where admins manage all transactional and promotional email templates.

The page uses a two-column layout. On the left, display a list of all email templates fetched from GET /api/admin/email-templates. Each template in the list shows its name, type (e.g., 'Order Confirmation', 'Event Reminder'), and status (active/inactive). Clicking a template loads its details into the right column editor.

The right column contains the template editor form. When a template is selected, fetch its full details from GET /api/admin/email-templates/:templateId and populate these fields: template name, subject line, and a rich-text editor (use TipTap) for the HTML body. Below the editor, show a sidebar or collapsible section listing available placeholder variables (like {{user.name}}, {{event.title}}) that admins can insert into the template.

Include action buttons: 'Save' (calls PATCH /api/admin/email-templates/:templateId), 'Delete' (calls DELETE /api/admin/email-templates/:templateId with confirmation), and 'Send Test Email' (opens a modal where the admin enters a recipient email, then calls POST /api/admin/email-templates/send-test). Also add a 'Create New Template' button that opens a form to POST /api/admin/email-templates with name, type, and subject.

Handle these states: Loading (show skeleton list items and disabled editor form), Empty (show an illustration with 'No email templates created yet' and a 'Create Template' CTA), Saving (spinner on the Save button, form disabled), Error 401 (redirect to login), Error 403 (show 'Access Denied' page), Error 500 (show error banner with retry button). The page is protected — only users with the Admin role can access it.
