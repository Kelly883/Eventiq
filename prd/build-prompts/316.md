We need to make sure things fail gracefully when something goes wrong, especially under the time pressure of a live event.

CheckInDashboardPage:
- Stats fail to load on first load → show a full-screen error with a 'Retry' button (not a small notification — the page has no content yet)
- Stats fail to auto-refresh → show a brief notification but keep the stats that already loaded (don't blank them out)
- Search fails → show a notification but keep any previous search results on screen
- Check-in fails because the ticket is already checked in → show a friendly message: 'This ticket was already checked in at [time]'
- Check-in fails because the ticket is void → show a warning: 'This ticket is void and cannot be checked in'
- Check-in fails because the ticket is fraud-flagged → show a warning: 'This ticket has been flagged for fraud. Contact an organizer.'
- Check-in fails due to network error → show a notification with a 'Retry' button
- Check-in fails due to rate limit (429) → show a message: 'Too many check-ins. Please wait 60 seconds.' and disable the check-in button for 60 seconds
- User's login expires (401) → redirect to login page

BulkCheckInPage:
- Bulk check-in fails on first load (can't fetch event) → show a full-screen error with a 'Retry' button
- Bulk check-in partially fails (some succeed, some fail) → show a summary: 'X checked in successfully, Y already checked in, Z failed' with a detailed list of failures
- Bulk check-in fails due to too many tickets (> 100) → show an error: 'Maximum 100 tickets per batch. You entered X.'
- Bulk check-in fails due to malformed input → show an error: 'Invalid ticket ID format. Use one per line or comma-separated.'
- Bulk check-in fails due to rate limit (429) → show a message and disable the button for 60 seconds
- Export fails → show a notification: 'Export failed. Try again.' with a 'Retry' button

SearchResultsPanel:
- Search returns no results → show a friendly message: 'No tickets found. Try a different search.'
- Search fails due to query too short (< 2 chars) → show a hint: 'Search requires at least 2 characters'
- Search fails due to network error → show a notification but keep previous results on screen

Offline scenarios:
- App goes offline → show a banner at the top: 'You're offline. Check-ins will be queued and synced when you're back online.'
- App comes back online → show a banner: 'You're back online. Syncing check-ins...' → then 'Synced X check-ins successfully'
- Offline-sync fails due to conflicts → show a dialog for each conflict: 'This ticket was already checked in at [time]. Continue anyway?' with 'Yes' and 'No' buttons
- Offline-sync fails due to network error → show a notification: 'Sync failed. Will retry when online.' and keep the queue

All pages:
- If the user's role changes mid-session (e.g., they're demoted from VenueStaff), show a message: 'Your permissions have changed. Please log in again.' and redirect to login
- If the event is deleted or archived while they're checking in, show: 'This event is no longer available.'
- If the server returns a 500 error, show: 'Something went wrong on our end. Please try again later.' (don't show technical details)
- All error messages should be clear, actionable, and not use technical jargon
