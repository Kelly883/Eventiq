We're building a tiered ticketing system for event organizers. For this step, I need you to create a ticket tier management page that lets organizers configure and manage multiple ticket tiers for their events.

Create a page component that displays a form for managing ticket tiers. This page should load when an organizer navigates to edit an event's ticket configuration. The page needs to show a list of existing ticket tiers (if any) and allow adding new ones.

Each ticket tier in the list should display: tier name, price, quantity available, early bird price (if set), sales dates, and max tickets per customer. Make each tier editable inline or via a modal — when clicked, it should open a form pre-populated with that tier's data.

The form for creating or editing a tier should have these fields:
- Tier name (text input, required)
- Price in base currency (decimal input, required, show as currency)
- Quantity available (number input, required, unsigned)
- Sales start date (datetime picker, optional)
- Sales end date (datetime picker, optional)
- Benefits description (textarea, optional — this is what makes this tier special)
- Tier image URL (text input, optional — for visual differentiation)
- Early bird price (decimal input, optional — lower price for early purchases)
- Early bird end date (datetime picker, optional — when early bird pricing expires)
- Max tickets per customer (number input, optional, unsigned — prevents bulk buying)

Add validation on the client side: price must be positive, quantity must be positive, early bird price (if set) must be less than regular price, end dates must be after start dates, max per customer must be positive if set.

Include an 'Add Tier' button that adds a new blank tier to the form. Each tier should have a 'Remove' button. At the bottom, add a 'Save All Tiers' button that sends the entire tier configuration to the backend via PATCH /api/organizer/events/:eventId.

While saving, disable the form and show a loading spinner. On success, show a confirmation message. On error, display the error message and keep the form editable so the user can retry.
