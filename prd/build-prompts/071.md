We need to set up the database schema to support the check-in system. Create these tables using Laravel migrations:

1. tickets table — If it doesn't exist, create it with: id (UUID primary key), event_id (UUID, foreign key to events), ticket_id (string, unique), attendee_name (string), attendee_email (string), tier (string), status (enum: 'valid', 'checked_in', 'void'), checked_in_at (timestamp, nullable), checked_in_by (UUID, foreign key to users), created_at, updated_at. Add indexes on (event_id, status) for fast filtering and (event_id, checked_in_at) for time-range queries.

2. fraud_events table — Track duplicate check-in attempts and suspicious activity: id (UUID), ticket_id (UUID, foreign key to tickets), event_id (UUID), fraud_type (enum: 'duplicate_checkin', 'invalid_qr', 'manual_override'), detected_at (timestamp), first_check_in_at (timestamp), first_check_in_by (UUID), second_check_in_at (timestamp), second_check_in_by (UUID), risk_level (enum: 'low', 'medium', 'high'), notes (text, nullable). Add indexes on (ticket_id, event_id) and (event_id, detected_at).

3. audit_logs table — Log all check-in actions for compliance: id (UUID), event_id (UUID), user_id (UUID, foreign key to users), action (string), ticket_id (UUID, nullable), details (JSON), created_at. Add index on (event_id, created_at).

4. ticket_inventory table — Track real-time inventory: id (UUID), event_id (UUID), total_available (integer), total_checked_in (integer), total_void (integer), last_updated_at (timestamp). Add index on event_id.

5. analytics_events_metrics table — Track event metrics: id (UUID), event_id (UUID), total_tickets_sold (integer), total_checked_in (integer), check_in_rate (decimal), last_updated_at (timestamp). Add index on event_id.

Run php artisan migrate to apply all migrations.
