Now we need to connect the role management pages to the rest of the app and enforce access control.

Add routes:
- /admin/roles → AdminRoleManagementPage (admin-only)
- /settings/permissions → UserPermissionsPage (authenticated users only)

Create a route guard for /admin/roles that checks if the current user's role is 'Admin'. If not, redirect to /settings/permissions with a toast 'Access Denied — only admins can manage roles'. If the user is not authenticated, redirect to login.

On the main navigation (header or sidebar), add a link to /settings/permissions for all authenticated users. Add a link to /admin/roles only if the user is an admin.

Wire up these connections:
- When a role change succeeds on AdminRoleManagementPage, show a success toast with the count of updated users
- When a permission request succeeds on UserPermissionsPage, show a success toast 'Request submitted'
- If a user's session expires (401 error), redirect to login with 'Session expired' toast
- If a user is demoted from admin while viewing /admin/roles, redirect to /settings/permissions with a toast 'Your admin access has been revoked'
- The 'Manage other users' permissions' link on UserPermissionsPage should route to /admin/roles (only visible if user is admin)

Add a global error boundary that catches 403 errors and shows 'Access Denied' with a back button.
