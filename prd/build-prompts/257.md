Now connect the checkout pages to the rest of the app so users can flow from browsing events to purchasing tickets.

Add routes for: /cart (CartPage), /checkout (CheckoutPage), /order/:orderId/confirmation (OrderConfirmationPage), and /my-tickets (UserTicketsPage).

From the event browsing pages, when a user adds a ticket to their cart, show a brief confirmation toast and optionally a 'View Cart' link. The cart icon in the header should show the number of items and link to /cart.

Wire up these navigation flows:
- CartPage 'Proceed to Checkout' button → /checkout (pass cart state)
- CheckoutPage 'Pay' button success → /order/{orderId}/confirmation (redirect with orderId from response)
- OrderConfirmationPage 'View My Tickets' button → /my-tickets
- UserTicketsPage 'Browse Events' button (when empty) → /events
- All protected pages (CheckoutPage, OrderConfirmationPage, UserTicketsPage) should redirect to /login if the user isn't authenticated

When the user completes payment and lands on OrderConfirmationPage, they should NOT be able to go back to CheckoutPage with the browser back button — clear the checkout state after successful payment.

Add a 'My Tickets' link in the user menu or header so authenticated users can easily access their tickets.

Handle deep linking: if a user tries to access /order/:orderId/confirmation directly, they should be able to view it if they own that order, or see a 403 error if they don't.
