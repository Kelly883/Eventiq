Let's make sure the check-in system is locked down and can't be abused.

Client-side security:
- All six endpoints (GET /api/venue/check-in/search, POST /api/venue/check-in/bulk, GET /api/venue/check-in/stats, POST /api/venue/check-in/detect-duplicate, POST /api/venue/check-in/offline-sync, GET /api/venue/check-in/export) require a valid Bearer token in the Authorization header. Store the token securely (httpOnly cookie or secure localStorage). Include it in every API request.
- Validate that the user has VenueStaff or Organizer role before showing the check-in pages. This is a client-side check only — the server will enforce it too, but the client should prevent accidental access.
- The search endpoint (GET /api/venue/check-in/search) has a rate limit of 60 searches/min per user. Implement client-side rate limit detection: if you get a 429 response, show a user-friendly message and disable the search for 60 seconds.
- The bulk endpoint (POST /api/venue/check-in/bulk) has a rate limit of 30 operations/min per user. Same handling: detect 429 and show a message.
- The export endpoint (GET /api/venue/check-in/export) has a rate limit of 5 exports/min per user. Disable the export button for 60 seconds after a successful export.
- The detect-duplicate endpoint (POST /api/venue/check-in/detect-duplicate) decrypts QR code data server-side. Never attempt to decrypt on the client — always send the encrypted payload to the server.
- The offline-sync endpoint (POST /api/venue/check-in/offline-sync) handles conflict resolution. When syncing, compare the local checkedInAt timestamp with the server's version. If they differ, the server wins (trust the server as source of truth).

Server-side security (what the backend should enforce, but verify in your API calls):
- All endpoints require authentication (Bearer token). If missing or invalid, return 401.
- All endpoints enforce VenueStaff or Organizer role via Policy. If the user doesn't have the role, return 403.
- All endpoints verify the user is authorized for the event (can't check in attendees for an event they don't manage). Return 403 if not authorized.
- The search endpoint limits results to 10 items per query to prevent data dumping.
- The bulk endpoint accepts max 100 ticket IDs per request to prevent resource exhaustion.
- The bulk endpoint is idempotent: checking in the same ticket twice returns success but doesn't double-count.
- The detect-duplicate endpoint decrypts QR codes server-side only. The client never sees the decryption key.
- The offline-sync endpoint handles conflicts gracefully: if a ticket was already checked in on the server, the sync returns 'conflict' status and the server's check-in time.

Implement these checks in your React code:
- Before calling any endpoint, verify the token exists and the user has the right role.
- Catch 401 responses and redirect to login.
- Catch 403 responses and show 'Access Denied'.
- Catch 429 responses and show a rate limit message with a countdown timer.
- Catch 400 responses and show the error message from the server.
- For the offline-sync endpoint, handle 409 (conflict) responses by showing a dialog: 'This ticket was already checked in at [time]. Continue anyway?' and let the user decide.
