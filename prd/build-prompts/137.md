We need four API endpoints for the role and permission system. All are admin-only and must be protected by the IsAdmin middleware and Laravel Policies.

1. GET /api/admin/users/list — List all users with their roles and permissions. Accept query params: ?role=Organizer&search=john&page=1&limit=20. Verify admin authorization via Policy. Query the users table with optional filters (role name, search by email/name). Eager load the role and permissions for each user. Return paginated results: { users: [{id, email, name, role: {id, name}, permissionCount, createdAt}], total, page, limit }. Return 400 for invalid params, 401 for unauthenticated, 403 for non-admin, 500 for database errors. Rate limit to 10/min per admin.

2. POST /api/admin/roles/assign — Assign a role to one or more users. Request body: { userIds: [string], roleId: string, reason?: string }. Verify admin authorization. Validate that roleId exists. For each userId: verify user exists, check if role change is allowed (prevent self-demotion), store old role/permissions in auditLog, update user.roleId, invalidate user's sessions, create auditLog entry. Return { updated: number, message: 'Role assigned to X users' }. Return 400 for missing/invalid fields, 401 for unauthenticated, 403 for non-admin or self-demotion, 404 for missing users, 429 for rate limit, 500 for database errors. Use database transactions to ensure atomicity.

3. POST /api/admin/permissions/update — Grant or revoke specific permissions for a user. Request body: { userId: string, permissionIds: [string], action: 'grant' | 'revoke', reason?: string }. Verify admin authorization. Validate userId and permissionIds. For each permissionId: check if it's high-risk (if so, require additional confirmation), add/remove from user's permissions, create auditLog entry, invalidate user's sessions. Return { updated: number, message: 'Permissions updated' }. Return 400 for missing/invalid fields, 401 for unauthenticated, 403 for non-admin or attempting to modify own high-risk permissions, 404 for missing user/permission, 429 for rate limit, 500 for database errors. Use transactions.

4. GET /api/admin/audit-log/list — Retrieve the audit log of all role and permission changes. Accept query params: ?targetUserId=uuid&action=role_assigned&page=1&limit=50. Verify admin authorization. Query auditLogs table with optional filters. Eager load admin and targetUser details. Sort by createdAt descending (most recent first). Return paginated results: { logs: [{id, admin: {id, name, email}, targetUser: {id, name, email}, action, oldValue, newValue, reason, createdAt}], total, page, limit }. Return 400 for invalid params, 401 for unauthenticated, 403 for non-admin, 500 for database errors. Rate limit to prevent abuse.

All endpoints should use Laravel Eloquent for queries, apply the IsAdmin middleware, and log all changes to the auditLogs table. Never expose password hashes in responses.
