We need to make sure things fail gracefully when something goes wrong in the role management system.

AdminRoleManagementPage:
- Network failure on initial load → show a full-screen error banner with a 'Retry' button (not a small notification — the page has no content yet)
- Failure while loading more users (pagination) → show a brief notification but keep the users that already loaded
- Filter or sort change fails → show a notification and revert to the previous filter/sort
- Bulk role assignment fails → show a modal with the error message and a 'Retry' button. If it's a 403 (not admin), show 'Access Denied' and redirect to /settings/permissions. If it's a 429 (rate limit), show 'Too many requests, try again in a minute'
- Permission toggle fails → show a notification with a 'Retry' option. If it's a high-risk permission and the user didn't confirm, show 'This is a high-risk permission — confirm to proceed'
- Audit log fails to load → show a notification but don't block the main page. The audit log section should show 'Failed to load audit log' with a retry link
- If the user's session expires (401) → redirect to login with 'Session expired' toast
- If the user is demoted from admin (403 on a subsequent request) → redirect to /settings/permissions with 'Your admin access has been revoked' toast

UserPermissionsPage:
- Network failure on initial load → show a full-screen error banner with a 'Retry' button
- Permission request submission fails → show a modal with the error. If it's a 400 (validation), show the specific validation error. If it's a 429 (rate limit), show 'Too many requests'
- If the user's login expires (401) → redirect to login with 'Session expired' toast
- If the user's role changes while viewing the page (unlikely but possible) → show a notification 'Your permissions have changed' and reload the page

Global error handling:
- All 401 errors → redirect to login with 'Session expired' toast
- All 403 errors → show 'Access Denied' toast and redirect to the appropriate page (admin → /settings/permissions, user → /login)
- All 500 errors → show an error banner with 'Something went wrong' and a 'Retry' button
- Network timeouts → show 'Request timed out, check your connection'
- All error messages should be user-friendly (no technical jargon or error codes)

Toasts should auto-dismiss after 5 seconds for success messages, 8 seconds for errors. Errors should have a 'Dismiss' button to close early.
