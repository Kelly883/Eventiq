We need to create the data models that represent push notification data in both the backend and frontend.

On the backend (Laravel), create three Eloquent models:

1. PushNotificationDevice at app/Features/PushNotifications/Models/PushNotificationDevice.php:
   - Belongs to User (relationship)
   - Fillable fields: user_id, token, provider, device_type
   - Add a method to soft-delete devices (mark as deleted but retain data)
   - Add a scope to find devices by user_id
   - Add a scope to find active (non-deleted) devices

2. PushNotificationTemplate at app/Features/PushNotifications/Models/PushNotificationTemplate.php:
   - Fillable fields: name, type, title, body, variables, is_active
   - Add a method to render the template with variable substitution (replace {{user.name}} with actual values)
   - Add a scope to find active templates

3. DeliveryPreferences at app/Features/PushNotifications/Models/DeliveryPreferences.php:
   - Belongs to User
   - Fillable fields: push_notifications_enabled, push_order_confirmation, push_event_reminder, push_checkin_alert, push_promotional_offers
   - Add a method to check if a specific notification type is enabled

On the frontend (React + Vite), create TypeScript interfaces at src/features/push-notifications/types/index.ts:

1. PushNotificationDevice interface with fields: id, userId, token, provider, deviceType, createdAt, updatedAt
2. PushNotificationTemplate interface with fields: id, name, type, title, body, variables, isActive, createdAt, updatedAt
3. DeliveryPreferences interface with fields: pushNotificationsEnabled, pushOrderConfirmation, pushEventReminder, pushCheckinAlert, pushPromotionalOffers
4. PushNotificationPermissionStatus type: 'granted' | 'denied' | 'default'

All models should be immutable where appropriate (createdAt fields should not be user-editable).
