We need to set up the database schema for the role and permission system. Create Laravel migrations for four tables:

1. roles table — Columns: id (UUID primary key), name (string, unique), description (text), permissions (JSON array to store permission IDs), isSystemRole (boolean, default false), createdAt, updatedAt. Add indexes on name and isSystemRole for fast lookups.

2. permissions table — Columns: id (string primary key, like 'can_create_events'), name (string), description (text), category (enum: event_management, ticket_management, analytics, user_management, platform_admin), riskLevel (enum: low, medium, high), createdAt. Add an index on category for filtering permissions by type.

3. auditLogs table — Columns: id (UUID primary key), adminId (UUID, foreign key to users), targetUserId (UUID, foreign key to users), action (enum: role_assigned, role_revoked, permission_granted, permission_revoked, permission_request_approved, permission_request_denied), oldValue (JSON), newValue (JSON), reason (text, nullable), createdAt. Add indexes on adminId, targetUserId, and createdAt for fast audit queries. Mark as immutable (no updates after creation).

4. permissionRequests table — Columns: id (UUID primary key), userId (UUID, foreign key to users), permissionId (string, foreign key to permissions), status (enum: pending, approved, denied), reason (text, nullable), approvedBy (UUID, foreign key to users, nullable), approvalReason (text, nullable), createdAt, resolvedAt (timestamp, nullable). Add indexes on userId, status, and createdAt.

Also add a roles_id column to the users table (if not already present) to link each user to their role. Add a permissions JSON column to users to store individual permission overrides.

Run php artisan migrate to apply all migrations.
