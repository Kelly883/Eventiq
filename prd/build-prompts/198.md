We're building a dashboard for event organizers to manage and monitor their events in real-time. You'll create three interconnected pages that work together to give organizers a complete view of their business.

Start with OrganizerDashboardPage at /dashboard — this is the main hub. At the top, display four summary metric cards showing: total revenue (all events combined), total tickets sold, average conversion rate, and upcoming event count. Each card should have a color-coded trend indicator (green arrow for up, red for down, gray for flat). Below the metrics, render a responsive grid of event cards. Each event card shows a thumbnail, event title, date, and progress bars for ticket sales and revenue. Include quick-action buttons on each card: 'Edit Event', 'View Analytics', and 'Manage Inventory'. At the bottom, add a collapsible section for the sales activity feed (we'll build that separately). In the sticky header, add filter controls: a status filter dropdown (all/upcoming/past/draft) and a date range picker (7 days, 30 days, 90 days, all). Put a prominent 'Create New Event' button in the top-right corner. Add a live indicator badge with a pulse animation that shows 'Live' when auto-refresh is active. Handle loading state with skeleton cards and shimmer effects. For empty state (no events), show a friendly illustration with 'Create your first event' text and a 'Create Event' button. For errors, show appropriate messages: 401 redirects to login with a 'Session expired' toast, 403 shows 'Access Denied — only organizers can view dashboard' with a back button, 500 shows an error banner with a retry button.

Next, build EventDetailWidget as an expandable card on the dashboard. When a user clicks an event card, this widget expands to show detailed metrics for that single event. Display the event title, date, venue, and status prominently. Show a tier breakdown with horizontal bars for each ticket tier (Regular, VIP, VVIP, Early Bird), displaying individual sales progress, revenue per tier, and conversion rates. Below that, render a pricing window timeline showing the current active window and upcoming price changes with countdown timers. Use color coding: green for active windows, blue for upcoming, gray for past. Highlight any tiers with low stock with a warning badge. Include three action buttons: 'View Full Analytics' (links to /organizer/events/:eventId/analytics), 'Manage Inventory' (links to /organizer/events/:eventId/inventory), and 'Edit Event' (links to /organizer/events/:eventId/edit). Use a two-column layout on desktop (event info left, metrics right) and stack vertically on mobile. Show skeleton tier bars and placeholder timeline while loading. If loading fails, display 'Unable to load details' with a close button.

Finally, build SalesActivityFeed as a real-time scrollable list showing the latest ticket sales across all the organizer's events. Each activity item should display on one line: event name (color-coded badge), ticket tier, quantity sold, price, buyer email (if available), and relative timestamp (e.g., '2 minutes ago'). Make the feed auto-update every 30 seconds with new sales appearing at the top. When a user clicks an activity item, expand it to show full transaction details. Add an 'Export Activity' button that downloads the feed as CSV. For loading state, show 5 skeleton activity items with shimmer. For empty state, show 'No sales yet'. On mobile, make list items full-width with horizontal scroll for details.

All three pages should pull data from these endpoints: GET /api/organizer/dashboard/overview (for summary metrics), GET /api/organizer/dashboard/events (for event list), GET /api/organizer/dashboard/events/:eventId (for event details), and GET /api/organizer/dashboard/activity-feed (for sales activity). Use TanStack Query to manage these requests with proper caching and refetching strategies.
