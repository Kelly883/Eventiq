We need state management so the payment pages don't handle data fetching themselves. Create three state managers using React Context or your app's existing state library:

1. Payment Methods state — Tracks the list of saved payment methods, loading state (initial load vs. loading more), any errors, and which card is the default. Should support: fetching the list from GET /api/users/me/payment-methods, adding a new method (POST /api/users/me/payment-methods), removing a method (DELETE /api/users/me/payment-methods/:id), and setting a default (PATCH /api/users/me/payment-methods/:id/set-default). When any action succeeds, refresh the list. Handle errors gracefully — if a delete fails, don't remove it from the UI.

2. Stripe Connect state — Tracks the organizer's Stripe Connect status (not connected, pending, enabled), the masked account ID, loading state, and any errors. Should support: fetching the status from GET /api/organizer/settings/stripe-connect, initiating the connect flow (navigate to the endpoint), and handling the return from Stripe (GET /api/organizer/settings/stripe-connect-return). The return endpoint should update the local state with the new status and account ID.

3. Stripe Elements state — Manages the Stripe Elements form instance, validation state, and submission state. Tracks whether the form is valid, whether it's submitting, and any Stripe-specific errors (like 'Your card was declined'). This is local to the AddPaymentMethodModal component.

Keep business logic out of the pages — pages should just call methods on the state managers and react to state changes. For example, PaymentMethodsPage should call paymentMethodsState.fetchList() on mount and paymentMethodsState.removeMethod(id) when the user clicks Remove.
