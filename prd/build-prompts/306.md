We need to make sure things fail gracefully when something goes wrong with the organizer profile feature.

OrganizerPublicProfilePage:
- Network failure on first load → show a full-screen error banner with a 'Retry' button (not a small notification — the page has no content yet)
- 404 (organizer not found or profile is private) → show 'Organizer not found' message with a back button
- 500 (server error) → show an error banner with a 'Retry' button
- Events load failure → show a notification but keep the profile info that already loaded
- Empty state (no events) → show 'No events yet' with a friendly illustration, not an error

OrganizerProfileEditPage:
- Network failure on load → show a full-screen error with 'Retry'
- 401 (not authenticated) → redirect to login page
- 403 (not an organizer) → show 'Access Denied' message with a back button
- 404 (organizer profile not found) → show 'Profile not found' with a back button
- Validation error on save (e.g., displayName required, bio too long) → highlight the invalid field with a red border, show error message below the field, don't submit
- Network failure on save → show a notification with a 'Retry' option, keep the form data
- Avatar upload failure (invalid file type, too large) → show a notification with the specific reason (e.g., 'File must be under 5MB')
- Avatar upload in progress → show a progress indicator (not just a spinner)
- 500 (server error) → show an error banner with 'Retry', keep the form data

OrganizerProfileSettingsPage:
- Network failure on load → show a full-screen error with 'Retry'
- 401 (not authenticated) → redirect to login
- 403 (not an organizer) → show 'Access Denied'
- 404 (profile not found) → show 'Profile not found'
- Toggle/setting change fails → show a notification and revert the toggle to its previous state
- Profile deletion confirmation fails → show a notification, keep the delete button available for retry
- 500 (server error) → show an error banner

All pages:
- If the user's login expires (401 response) during any operation, redirect to the login page
- Show error messages in a consistent style (notification toast or banner)
- Include a 'Dismiss' or 'Close' button on error messages
- Don't show raw error codes or technical jargon — translate to user-friendly messages
