We need to set up the database schema and indexes so dashboard queries run fast.

Create a Laravel migration for the organizer_dashboard_preferences table with these fields:
- id (UUID primary key, auto-generated)
- organizer_id (UUID, foreign key to organizers table, indexed for fast lookups)
- default_event_filter (string: 'all', 'upcoming', 'past', 'draft', defaults to 'all')
- default_date_range (string: '7days', '30days', '90days', 'all', defaults to '30days')
- expanded_event_id (UUID nullable, stores which event detail widget is expanded)
- show_activity_feed (boolean, defaults to true)
- auto_refresh_enabled (boolean, defaults to true)
- created_at (timestamp, set by server)
- updated_at (timestamp, set by server)

Add a unique index on organizer_id so each organizer has exactly one preferences record. Add a foreign key constraint on organizer_id that cascades on delete.

Also ensure these indexes exist on the events table (if not already present):
- organizer_id (for fast filtering by organizer)
- status (for filtering by draft/upcoming/live/past)
- organizer_id + status (composite index for common queries)

And on analytics_events_metrics:
- event_id (for joining with events)
- organizer_id (for aggregating across all organizer's events)

Run the migration with php artisan migrate.
