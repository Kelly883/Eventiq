Now we need to connect the push notification feature to the rest of the app.

Routing:
- PushNotificationSettingsSection is already part of /settings/delivery-preferences, so no new route needed. Just make sure it renders as a section within that existing page.
- AdminPushTemplateManagementPage needs a new route at /admin/settings/push-templates. Protect this route so only users with the 'Admin' role can access it — if a non-admin tries to access it, redirect to /admin or show an access denied page.

Device token registration:
- On app startup (in a useEffect in the root App component or a layout component), check if the user is authenticated. If they are, request a push notification token from the browser (using the Notification API or a service like Firebase Cloud Messaging if you're using it). Once you have the token, POST it to /api/notifications/device-tokens with the device type ('web' for web browsers). This registers the device so the backend knows where to send notifications.
- On logout, DELETE the device token by calling /api/notifications/device-tokens with the token. This stops notifications from being sent to that device.

Notification permission flow:
- When the user first toggles push notifications ON in PushNotificationSettingsSection, request browser notification permission using Notification.requestPermission(). If they grant it, proceed with saving the preference. If they deny it, show a message explaining they won't receive notifications and don't save the preference as enabled.

Admin access:
- Add a link to /admin/settings/push-templates in the admin settings menu or navigation (wherever other admin settings links are).

Deep linking (optional but nice):
- If your app supports deep linking, make sure /admin/settings/push-templates/:templateId works to load a specific template for editing.
