We need four API endpoints to handle device token registration, template management, and test notifications.

1. POST /api/notifications/device-tokens — Register or update a device token for the authenticated user. The request body should contain: token (the FCM token), provider (e.g., 'fcm'), and device_type (web, ios, or android). Use Laravel's updateOrCreate method to handle both new registrations and updates for existing devices based on the unique token. Return the created/updated PushNotificationDevice with 201 status. Check that the user is authenticated (use laravel-sanctum middleware). Validate the input using a FormRequest.

2. DELETE /api/notifications/device-tokens — Delete a specific device token for the authenticated user. The request should include the token to delete (either in the URL or request body). Soft-delete the device (mark as deleted, don't actually remove it). Return 204 No Content on success. Ensure the user can only delete their own devices.

3. GET, POST, PATCH, DELETE /api/admin/push-templates and /api/admin/push-templates/:templateId — Full CRUD for push notification templates (admin only). GET /api/admin/push-templates lists all templates. POST creates a new template with fields: name, type, title (max 65 chars), body (max 178 chars), variables (JSON), is_active. PATCH /api/admin/push-templates/:templateId updates a specific template. DELETE /api/admin/push-templates/:templateId soft-deletes a template. All requests require the user to have the 'Admin' role (use a Laravel Policy). Validate input using FormRequest. Return appropriate status codes (200 for success, 201 for creation, 204 for deletion, 400 for validation errors, 401 for auth, 403 for permission denied).

4. POST /api/admin/push-templates/send-test — Send a test push notification. The request body should contain: user_id (the user to send to), title (optional, overrides template), and body (optional, overrides template). The backend finds all active device tokens for that user_id and dispatches a queued Job to send the notification to each device using the PushNotificationService. Return 202 Accepted (the job is queued, not sent immediately). Require admin role. Validate that the user_id exists.

All endpoints should check authentication using laravel-sanctum middleware. All endpoints should validate input and return clear error messages. Rate limit the device token endpoints to prevent abuse.
