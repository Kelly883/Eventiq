We need three state managers so the settings pages don't handle data fetching themselves, and so accessibility/localization settings apply globally across the entire app.

Accessibility Preferences State — This manages the user's accessibility settings globally. It should track: fontSize (12-24), highContrast (boolean), screenReaderOptimized (boolean), focusIndicatorEnhanced (boolean), motionReduced (boolean), lineHeight (1.0-2.0), letterSpacing (0-0.2), wordSpacing (0-0.2), colorBlindnessMode (none/protanopia/deuteranopia/tritanopia), loading state, and any errors. On app startup, load settings from GET /api/users/me/accessibility-preferences. If the user is authenticated, apply these settings globally (inject CSS variables, set ARIA attributes, disable animations if motionReduced is true). Support updating individual settings via PATCH /api/users/me/accessibility-preferences/update. When settings change, immediately apply them to the DOM and persist to localStorage as a fallback (in case the backend is slow). Expose methods: loadAccessibilityPreferences(), updateAccessibilitySetting(key, value), resetToDefaults().

Localization Preferences State — This manages language and locale formatting globally. Track: language (ISO 639-1 code, default 'en'), region (ISO 3166-1 code), dateFormat (MM/DD/YYYY, DD/MM/YYYY, YYYY-MM-DD), timeFormat (12-hour, 24-hour), currency (ISO 4217 code), numberFormat (comma or period), rtlEnabled (boolean), loading state, and errors. On app startup, load from GET /api/users/me/language-preferences. Initialize react-i18next with the selected language. When language changes, switch i18next namespace and update all UI text immediately. Apply RTL layout if rtlEnabled is true. Support updating via PATCH /api/users/me/language-preferences/update. Expose methods: loadLocalizationPreferences(), updateLanguage(code), updateLocaleFormat(key, value), getCurrentLocale().

Device Localization Sync State — This manages multi-device sync. Track: devices array (with device name, type, language, accessibility settings, last sync time, sync status), loading state, syncing state (which device is currently syncing), and errors. Load device list from GET /api/users/me/devices. Poll sync status every 30 seconds. Support bulk sync via POST /api/users/me/devices/sync-all. Support individual device updates via PATCH /api/users/me/devices/:deviceId/localization-settings/update. Expose methods: loadDevices(), syncAllDevices(), syncDevice(deviceId), updateDeviceSettings(deviceId, settings), removeDevice(deviceId).

All three state managers should be wrapped at the app root using React Context or your existing state management library (Zustand, Redux, etc.). When accessibility or localization settings change, they should apply immediately to the current page and persist to the backend. Use localStorage as a fallback so settings work even if the backend is temporarily unavailable.
