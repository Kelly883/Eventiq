We need to make sure things fail gracefully when something goes wrong.

AuditLogsViewerPage:
- Network failure on first load → show a full-screen error with a 'Retry' button (not a small notification — the page has no content yet)
- Failure while loading more → show a brief notification but keep the logs that already loaded
- Filter or sort change fails → show a notification and revert to the previous filter/sort
- Expanding a log row fails (404 or network error) → show an error in the detail modal with a close button
- Export fails → show a notification with a 'Retry' button
- Bulk tagging fails → show a notification and don't remove the checkboxes (so the user can try again)
- Polling for new events fails → silently skip that poll cycle and try again in 30 seconds (don't show an error for every failed poll)

ComplianceReportsPage:
- Report generation fails (invalid date range, invalid type, etc.) → show an error in the modal with details about what went wrong
- Report generation times out (takes too long) → show a message 'Report is taking longer than expected' with a 'Check Status' button
- Fetching previously generated reports fails → show a notification with a 'Retry' button
- Downloading a report fails → show a notification with a 'Retry' button
- Scheduling a report fails → show an error in the schedule modal
- Fetching compliance checklist fails → show a placeholder with a 'Retry' button

All pages:
- If the user's login expires (401), redirect to the login page with a message 'Your session expired. Please sign in again.'
- If the user loses admin role (403), redirect to a 'Not Authorized' page with a message 'You no longer have permission to access this page.'
- If the server returns a 500 error, show a generic message 'Something went wrong. Please try again later.' and log the error for debugging
- For all errors, include a 'Contact Support' link if the error persists

Error messages should be clear and actionable — tell the user what went wrong and what they can do about it. Avoid technical jargon.
