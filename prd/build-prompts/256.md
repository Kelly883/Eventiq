Now connect the calendar feature to the rest of the app so users can discover and navigate to events.

Add routes for: /events/calendar (EventCalendarPage), and /events/calendar/day/:date (CalendarDayDetailModal — though this typically renders as an overlay on the same page, not a separate route). Make sure the calendar page is accessible from the main navigation — either a 'Browse Events' link in the header, a 'Calendar' tab in the navigation bar, or a dedicated events section in the app menu.

Wire up these connections:
- When a user clicks an event card in the calendar or modal, navigate to /events/:eventId (the event detail page)
- When an organizer clicks 'Create Event', navigate to /organizer/events/create
- When a user is not authenticated and tries to create an event, redirect to the login page first
- The search bar should debounce queries and call the search endpoint (or filter the existing calendar data client-side if the dataset is small)
- Clicking 'Clear filters' should reset all filters and re-query the calendar
- The 'View Details' button in the day modal should navigate to the event detail page
- Back button from the event detail page should return to the calendar (not lose the user's filters or selected date)

Make sure deep linking works: if a user opens /events/calendar?category=concerts&priceMin=50&priceMax=200, the calendar should load with those filters already applied.
