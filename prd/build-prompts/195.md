We're building a dynamic pricing system for event organizers. This step creates two pages that work together: one for configuring pricing rules, and one for previewing how attendees will see the pricing.

EventPricingConfigPage at /organizer/events/:eventId/pricing — This is the main configuration interface. Start by fetching the event and its ticket categories (Regular, VIP, VVIP, Early Bird) from the backend. Display a two-column layout on desktop: left column shows ticket categories as collapsible cards, each displaying the base price and any active pricing windows. Right column shows the pricing windows for the selected category.

For each pricing window, display: window name, start date/time, end date/time, price override, quantity limit, and a delete button. Add a 'Add Pricing Window' button that opens a form. The form should have fields for window name, start date/time, end date/time, price (must be positive), quantity limit (optional), and priority. Validate on the client side: windows can't overlap, prices must be positive, start must be before end, and end must be before the event ends. Use react-hook-form for form state management.

Add a timeline visualization showing when each pricing window is active relative to the event date. Color-code windows: early bird = green, regular = blue, last-minute = orange. Make windows draggable to resize for date adjustment (optional UX enhancement). On mobile, stack everything in a single column with collapsible sections.

At the bottom, add a sticky footer with 'Save Changes' and 'Preview' buttons. When saving, call POST /api/organizer/events/:eventId/pricing/windows for new windows, PATCH for updates, and DELETE for removals. Show a spinner on the Save button while loading. On success, show a 'Pricing updated' toast and refresh the timeline. Handle validation errors by highlighting invalid fields with red borders and error messages below.

PricingPreviewModal — This is a modal dialog (renderAs: 'modal', integratesInto: 'EventPricingConfigPage') that shows how attendees will see the pricing schedule. Call GET /api/organizer/events/:eventId/pricing/preview to fetch the preview data. Display ticket categories with their pricing windows in chronological order. For each category, show a vertical timeline with price points marked. Color-code: green for active windows, blue for upcoming, gray for past. Include a countdown timer showing when the next price change happens. Add a 'Close' button and 'Edit Pricing' button to return to the configuration page.

Handle loading states with skeleton cards in both pages. Handle empty states: if no pricing windows exist, show 'No pricing rules yet' with a CTA to add one. Handle errors: 401 redirects to login, 403 shows 'Access Denied', 404 shows 'Event not found', 500 shows an error banner with a retry button.
