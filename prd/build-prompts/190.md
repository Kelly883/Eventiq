We're building a complete authentication system for a React + Vite app with Laravel backend. You'll create four pages that handle login, registration, password recovery, and password reset.

Start with LoginPage at /login. This is a centered card (max-w-md) on a subtle gradient background with minimal distractions. Build an email field that validates format on blur, a password field with a show/hide toggle icon inside the field itself, and a 'Remember me' checkbox. Add a 'Forgot password?' link below the form that routes to /forgot-password, and a 'Create account' link that routes to /register. The form submission should call POST /api/auth/login. While loading, disable all fields and show a spinner in the submit button. Display inline field-level error messages in red text below each field — not in a separate banner. Handle three error types distinctly: invalid credentials (401) shows 'Invalid email or password' below the password field, rate limiting (429) shows a toast 'Too many attempts, try again in X minutes', and network errors show a dismissible toast with retry. On successful login, auto-redirect to /dashboard immediately. Authenticated users should never see this page — redirect them to /dashboard.

Next, build RegisterPage at /register using the same centered card pattern for visual consistency. Include fields for name, email, password, and confirm password. Add a real-time password strength meter below the password field that shows weak (red), medium (amber), or strong (green) with a text label. Validate on blur: email format, password minimum 8 characters, and password match. The confirm password field should only appear after the password field is valid. Add a required Terms & Conditions checkbox above the submit button. On successful registration, redirect to /login with a toast 'Account created successfully'. If the email is already registered (409), show 'This email is already registered' below the email field with a 'Sign In' link. Handle loading, validation errors, and network errors the same way as LoginPage.

Build ForgotPasswordPage at /forgot-password. This is minimal — just a single email input field with supportive copy explaining the reset process. The submit button sends a reset link to the email via POST /api/auth/forgot-password. Crucially, always show the same success message regardless of whether the email exists (this prevents attackers from enumerating registered emails). After success, replace the entire form with a confirmation state: a mail envelope icon, 'Check your email' heading, and instructions to check email and spam folder. Include a 'Back to Sign In' link that routes to /login. Show 'Sending...' in the button while loading. If rate-limited (429), show 'Too many requests. Please try again later.' as an inline message. Network errors show a toast with retry.

Finally, build ResetPasswordPage at /reset-password. Extract the token from the URL query parameter (?token=...). On mount, validate the token by calling POST /api/auth/reset-password with just the token (no password yet) — show a loading state 'Validating reset link...' during this check. If the token is invalid or expired, show a clear error message 'This link has expired or is invalid' with a prominent 'Request new link' button that routes to /forgot-password. If valid, reveal two password fields: new password (with the same strength meter as RegisterPage) and confirm password. Display password requirements as bullet points (minimum 8 characters, etc.). On form submission, call POST /api/auth/reset-password with the token and new password. Show 'Resetting...' in the button while submitting. On success, redirect to /login with a toast 'Password reset successfully'. All four pages should use the same centered card design pattern for consistency.
