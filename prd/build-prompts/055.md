We need to set up the database tables for the users schema, sessions schema, and passwordResetTokens schema. Laravel uses migrations to manage this.

First, the users table should already exist in Laravel (it comes with the framework), but we need to verify it has all the fields we need: id (UUID primary key), email (unique, indexed), passwordHash (string), name (string), role (string, default 'attendee'), emailVerified (boolean, default false), createdAt (timestamp), updatedAt (timestamp), lastLoginAt (nullable timestamp). If the default users table doesn't have all these fields, create a new migration to add the missing ones.

Create a migration for the sessions table with fields: id (UUID primary key), userId (UUID, foreign key to users.id), token (string, indexed), expiresAt (timestamp), createdAt (timestamp), revokedAt (nullable timestamp). Add a foreign key constraint so deleting a user cascades to delete their sessions.

Create a migration for the passwordResetTokens table with fields: id (UUID primary key), userId (UUID, foreign key to users.id), token (string, indexed), expiresAt (timestamp), usedAt (nullable timestamp), createdAt (timestamp). Add a foreign key constraint so deleting a user cascades to delete their reset tokens.

Run php artisan migrate to apply all migrations. Verify the tables exist in your database with the correct columns and indexes.

Also create Laravel models for Session and PasswordResetToken (they should extend Model and define the table name and fillable fields). The User model already exists but make sure it has the correct fillable fields and hidden fields (hide passwordHash from API responses).
