We need to make sure the offline sync feature is secure and doesn't leak user data.

Authentication:
- Both endpoints (PATCH /api/notifications/device-tokens/:token/offline-status and GET /api/me/tickets/for-offline-sync) require a valid bearer token from Laravel Sanctum. The frontend should include this token in the Authorization header for all requests.
- GET /api/me/tickets/for-offline-sync also requires the X-Device-Token header (the push notification token). The frontend should extract this from the device and include it in every sync request.
- If either token is missing or invalid, the backend returns 401 and the frontend should redirect to login.

Data validation:
- The backend should validate that the device token in the URL (for PATCH) matches the authenticated user's device. Don't trust the client to send the right token — verify on the server.
- The backend should validate that the X-Device-Token header matches a device registered to the authenticated user. If it doesn't, return 403 (forbidden).
- The backend should only return tickets for the authenticated user — never return another user's tickets, even if they somehow request them.
- The backend should only return future events (start_date in the future) — don't include past events in the offline cache.

Data storage:
- On the frontend, cached tickets are stored in localStorage. This is not encrypted, so don't store sensitive data like payment info or personal IDs. Only store what's needed to display tickets offline (event name, date, ticket tier, QR code, order reference).
- If the app supports multiple users on the same device, make sure each user's cached data is isolated. Don't let User A see User B's cached tickets.
- When the user logs out, clear all cached data from localStorage.

Rate limiting:
- The backend should rate-limit both endpoints to prevent abuse. GET /api/me/tickets/for-offline-sync is especially important — limit to maybe 5 requests per hour per user to prevent excessive syncing.

Implement these checks on the frontend:
- Before calling either endpoint, verify the user is authenticated (check for a valid token).
- Before calling GET /api/me/tickets/for-offline-sync, verify the device token is available.
- After receiving cached tickets, validate that they belong to the authenticated user (check user_id in the response).
- When storing cached tickets in localStorage, include the user_id so you can verify they belong to the current user on app restart.
