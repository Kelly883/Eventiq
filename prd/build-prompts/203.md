We're building a ticket delivery system with three React pages. Here's what each one does:

TicketStatusPage at /my-tickets/:ticketId/status — This is where users check if their ticket was delivered. Start with a prominent status badge at the top (color-coded: green for sent, amber for pending, red for failed). Below that, show delivery method cards displaying the current status with an icon and timestamp. The QR code should be large and centered for easy scanning at the venue. Below the QR code, display the ticket details (event name, date, tier, seat info if applicable). Include a 'Download PDF' button so users can manually grab their ticket. At the bottom, show a delivery history timeline with all delivery attempts, timestamps, and outcomes — make each attempt expandable to show details. If delivery failed, show the reason prominently and include a 'Resend Ticket' button. For email delivery, show the recipient email with an option to change it. For SMS, show the phone number. Add troubleshooting suggestions for failed deliveries (check spam folder, verify phone number, etc.). Handle loading state with skeleton cards and placeholder timeline. For errors: 401 redirects to login with 'Session expired' toast, 403 shows 'Access Denied — you don't own this ticket' with a back button, 404 shows 'Ticket not found' with a link back to my-tickets, 500 shows an error banner with a retry button. When resending, show a spinner on the button and disable it.

DeliverySettingsPage at /settings/delivery-preferences — This is where users configure how they want their tickets delivered. Organize the page into vertical card sections: Delivery Methods, Timing, Notifications, and Backup. For each delivery method (email, SMS, dashboard), show a toggle switch with a status indicator (verified/unverified). When email is toggled on, show the current email address with an option to change it — changing requires verification. Same for SMS with the phone number. Add a dropdown for language preference (English, Spanish, French, etc.). Include a section for delivery timing: immediate (default) or scheduled (1 hour before event, 24 hours before event). Add toggles for notification preferences: receive delivery confirmation and receive event reminders. Let users select a backup delivery method in case the primary fails. Put a 'Save Preferences' button at the bottom (sticky on mobile). Show verification status indicators with 'Verify Now' buttons for unverified methods. Handle loading with skeleton toggle cards and placeholder inputs. For errors: 401 redirects to login, 403 shows 'Access Denied', 500 shows error banner with retry. When saving, show a spinner on the button and disable all fields. When verification is pending, show 'Check your email/SMS for verification code'.

AdminDeliveryDashboardPage at /admin/delivery/dashboard — This is an admin-only real-time dashboard for monitoring ticket delivery across all events. Start with summary metric cards at the top showing: total tickets delivered (24h), delivery success rate (%), failed deliveries count, and average delivery time. Color-code trend indicators on these cards. Below the metrics, display an interactive table listing all delivery events with columns: ticket ID, event name, buyer email, delivery method, status (sent/failed/pending), timestamp, and retry count. Use color-coded status badges (green=sent, amber=pending, red=failed). Make rows expandable to show full delivery attempt history, error messages, and recipient contact info without leaving the page. Add a sticky filter bar with filters for event, delivery method, status, and date range. Include a search box to find by ticket ID or email. Add bulk action buttons to retry failed deliveries or manually trigger delivery for specific tickets. Show a delivery method breakdown chart displaying the percentage of tickets delivered via email vs SMS vs dashboard. Real-time updates should refresh every 30 seconds. Add an 'Export CSV' button to download a delivery report. For loading state, show skeleton metric cards and placeholder table rows with shimmer. For empty state (no deliveries), show 'No delivery events yet' with an illustration. For errors: 401 redirects to login with 'Session expired' toast, 403 shows 'Access Denied — only admins can view delivery dashboard' with a back button, 500 shows error banner with retry. On mobile, stack the metric cards and replace the table with collapsible detail cards instead.
