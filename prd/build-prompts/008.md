We're building a real-time sales analytics feature for event organizers. This is a complex feature with multiple pages, charts, and data visualizations, so we need a well-organized structure.

Create an analytics feature area under src/features/analytics/ with these subfolders:

- pages/ — for the three main pages: SalesAnalyticsDashboardPage, DetailedAnalyticsPage, and AnalyticsComparisonPage
- components/ — for reusable UI pieces like MetricCard, SalesVelocityChart, RevenueBreakdownChart, ConversionFunnelChart, TransactionTable, EventSelector, and FilterPanel
- hooks/ — for custom React hooks that handle data fetching and state management (useAnalyticsSummary, useSalesVelocity, useDetailedAnalytics, useEventComparison)
- types/ — for TypeScript interfaces matching our analytics schemas (AnalyticsMetrics, SalesTimelineEntry, TierPerformance)
- utils/ — for helper functions like trend calculation, data formatting, and chart data transformation
- services/ — for API client functions that call the backend endpoints

On the backend (Laravel), create a folder structure under app/Http/Controllers/Organizer/ with AnalyticsController.php to handle all analytics endpoints. Create app/Models/ with Analytics, SalesTimeline, and TierPerformance models. Create database/migrations/ for the three analytics tables.

This structure keeps analytics isolated from the rest of the app while making it easy to find and modify specific pieces.
