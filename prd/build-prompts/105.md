We need data models on both frontend and backend to handle offline sync and device tokens.

On the frontend (React + TypeScript), create these types in src/features/offline/types/:

1. DeviceToken interface: { token: string, offlineEnabled: boolean, lastSyncAt?: Date }. This represents the device's sync status.

2. OfflineTicket interface: { id: string, eventId: string, eventName: string, eventStartDate: Date, ticketTierId: string, tierName: string, qrCodeData: string, orderId: string, orderNumber: string }. This is the flattened ticket structure we'll cache.

3. OfflineSyncState interface: { tickets: OfflineTicket[], lastSyncedAt: Date, isSyncing: boolean, syncError?: string }. This tracks what's cached locally.

On the backend (Laravel), create these models in app/Features/OfflineSync/Models/ and app/Features/Notifications/Models/:

1. PushNotificationDevice model (app/Models/PushNotificationDevice.php): Has fields user_id, token, offline_enabled, last_sync_at. Add a relationship: belongsTo(User). Add a method lastSyncedMinutesAgo() that returns how many minutes since last_sync_at.

2. Create an API Resource at app/Features/OfflineSync/Resources/OfflineTicketResource.php that transforms a ticket into the OfflineTicket structure. It should eager-load event, ticket_tier, order, and event.organizer relationships and format the qrCodeData.

3. Create an API Resource at app/Features/OfflineSync/Resources/OfflineSyncResponse.php that groups tickets by event and includes sync metadata.

Make all models immutable where appropriate (createdAt should never change). Add validation rules to PushNotificationDevice: token must be unique per user, offline_enabled is boolean.
