# Step 282 of 345: Secure analytics endpoints and enforce access control

We need to lock down the analytics feature so only event organizers can access their own event's data.

All analytics endpoints (GET /api/organizer/events/:eventId/analytics/summary, GET /api/organizer/events/:eventId/analytics/sales-velocity, GET /api/organizer/analytics/events-list, GET /api/organizer/analytics/compare-events) must:

1. Require authentication — check for a valid bearer token in the Authorization header. Reject with 401 if missing or invalid.

2. Enforce event ownership — after extracting the userId from the token, query the events table to verify the user owns the event (eventId matches and organizerId == userId). Use Laravel Policies to enforce this. Reject with 403 if the user doesn't own the event.

3. Rate limit to prevent abuse — 20 requests per minute per user for summary and sales-velocity endpoints, 10 requests per minute for comparison endpoints. Return 429 if exceeded.

4. Validate all input parameters — eventId must be a valid UUID format, date ranges must be valid ISO8601 dates, granularity must be one of 'hour', 'day', 'week'. Return 400 for invalid inputs.

5. Protect sensitive data — buyer emails in the detailed analytics should only be shown if the organizer has explicit permission (check a permission flag in the user's profile or event settings). If not permitted, return null or redact the email.

6. Log all analytics access — record who accessed which event's analytics, when, and what filters were applied. This creates an audit trail for security and compliance.

7. Prevent data enumeration — if an event doesn't exist, return 404 (not 403). Don't reveal whether an event exists but the user doesn't own it.

8. Secure the Mixpanel SDK — the Mixpanel token should be public (it's meant to be), but make sure no sensitive data (user IDs, emails, revenue amounts) is sent to Mixpanel. Only send anonymized event names and non-sensitive properties.

9. CORS configuration — if the frontend is on a different domain, configure CORS to only allow requests from your frontend domain. Don't use wildcard '*'.

10. Token refresh — if using JWT tokens, make sure they have appropriate expiration times (15-60 minutes). Implement token refresh so users don't get logged out mid-session. Handle 401 errors by redirecting to login.

On the frontend, ensure:
- The bearer token is stored securely (httpOnly cookie if possible, or secure localStorage)
- The token is included in every analytics API request
- If a 401 error occurs, redirect to login immediately
- If a 403 error occurs, show a clear message and prevent further attempts
- Never log sensitive data (emails, revenue) to the browser console or Mixpanel
