We need to build seven API endpoints for the payment system. Here's what each one does:

1. POST /api/webhooks/stripe — Handles incoming webhooks from Stripe. This is a server-side endpoint that verifies the Stripe signature using the STRIPE_WEBHOOK_SECRET. Use Laravel Cashier's built-in webhook handling or create a custom controller that dispatches jobs for different event types. Handle these events: 'charge.succeeded' (update orders and payments to completed), 'charge.refunded' (update refund_requests and payments tables with refund info), 'customer.subscription.updated' (update user subscription status). Don't require authentication for this endpoint — Stripe will call it directly.

2. GET /api/users/me/payment-methods — Returns the authenticated user's saved payment methods. Check authentication with Laravel Sanctum. Use a Policy to ensure users can only access their own data. Query the payment_methods table filtered by the authenticated user's ID. Return an array of payment methods with id, type, brand, lastFour, expiryMonth, expiryYear, and isDefault. Return 401 if not authenticated.

3. POST /api/users/me/payment-methods/add — Adds a new payment method. Requires authentication. The frontend sends a Stripe payment method ID (pm_...) in the request body. Use Laravel Cashier to add this to the user's Stripe Customer object (create the customer if needed). Save a record to the payment_methods table with gateway='stripe', gateway_payment_method_id=the ID from Stripe, type and details extracted from Stripe. Return 201 with the created payment method. Return 400 if the payment method ID is invalid.

4. DELETE /api/users/me/payment-methods/:id — Deletes a saved payment method. Requires authentication. Use a Policy to verify the user owns this payment method. Call Laravel Cashier to detach it from the Stripe Customer. Soft-delete the record from payment_methods. Return 204 (no content). Return 404 if the payment method doesn't exist.

5. PATCH /api/users/me/payment-methods/:id/set-default — Sets a payment method as default. Requires authentication. Use a Policy to verify ownership. Update the payment_methods table to set is_default=true for this method and is_default=false for all others for this user. Call Laravel Cashier's updateDefaultPaymentMethod(). Return 200 with the updated payment method. Return 404 if not found.

6. GET /api/organizer/settings/stripe-connect — Initiates Stripe Connect onboarding. Requires authentication and the user must have an 'organizer' role (check via Policy). Generate a Stripe Connect account link using the Stripe API. Redirect the user to the Stripe onboarding URL. Return 302 redirect. Return 403 if not an organizer.

7. GET /api/organizer/settings/stripe-connect-return — The callback after Stripe Connect onboarding. This is called by Stripe after the user completes or skips onboarding. Retrieve the organizer's Stripe account details from the Stripe API. Update the organizers table with stripe_account_id and stripe_connect_status. Redirect back to /organizer/settings/payments. Return 302 redirect.

All endpoints except the webhook should use Laravel Sanctum for authentication. Add proper error handling and return appropriate HTTP status codes (401 for auth failures, 403 for permission failures, 400 for validation errors, 500 for server errors).
