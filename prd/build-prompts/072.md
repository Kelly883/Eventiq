We need to set up three database tables for the email notification system.

1. email_templates table — This is the main table. Create a migration that adds columns: id (UUID primary key), name (string, required), type (string, required — e.g., 'order_confirmation', 'event_reminder'), subject (string, required), html_body (longText for compiled HTML), mjml_body (longText for raw MJML source), variables (JSON, stores available placeholder variables like {{user.name}}, {{event.title}}), is_active (boolean, default true), created_at and updated_at timestamps. Add an index on type and is_active for fast filtering.

2. Enhance auditLogs table — Add a metadata JSON column to the existing auditLogs table. This will store additional context about email template changes (e.g., which fields were modified, old vs. new values).

3. Enhance delivery_preferences table — Add three boolean columns to the existing delivery_preferences table: event_cancellations (default true), refund_confirmations (default true), promotional_offers (default false). These control which types of emails users want to receive.

Run all migrations with php artisan migrate. Verify the tables exist and have the correct structure.
