We need to make sure things fail gracefully when something goes wrong and users understand what happened.

OrganizerEventListPage:
- Network failure on first load → show a full-screen error banner with a 'Retry' button (not a small notification — the page has no content yet)
- Failure while loading more events → show a brief toast notification but keep the events that already loaded
- Tab change fails (e.g., network error) → show a notification and revert to the previous tab
- Search fails → show a notification but keep any previous results on screen
- Delete fails → show a modal or toast saying 'Failed to delete event. Please try again.' with a retry option
- 401 (expired auth) → redirect to login page
- 403 (not an organizer) → show 'Access Denied' page with a link to home
- 500 (server error) → show error banner with 'Retry' button

EventCreatePage:
- Network error while saving → show a modal or toast saying 'Failed to save event. Please try again.' with a retry option
- Validation error from server (e.g., title too long) → show the error inline below the field that failed
- File upload fails (network, size, type) → show a toast saying 'Failed to upload banner. Please try again.' with a retry option
- 401 (expired auth) → redirect to login page
- 500 (server error) → show a modal saying 'Something went wrong. Please try again.' with a retry option

EventEditPage:
- Event not found (404) → show a 'Event no longer available' screen with a back button
- Network error while fetching event data → show a loading error state with a 'Retry' button
- Network error while saving changes → show a modal or toast with a retry option
- Validation error from server → show inline below the field
- File upload fails → show a toast with a retry option
- 401 (expired auth) → redirect to login page
- 403 (not the owner) → show 'Access Denied' page
- 500 (server error) → show a modal with a retry option

General patterns:
- All error messages should be user-friendly, not technical jargon (e.g., 'Failed to save event' not 'HTTP 500 Internal Server Error')
- Provide a clear action to recover (Retry button, link to home, etc.)
- Don't leave the user stuck (always a way forward)
- Use toast notifications for non-blocking errors (file upload failed), modals for blocking errors (can't save event)
- If the user's login expires (401), redirect to login and then back to the page they were on after they sign in again
- Show validation errors inline below the field that failed, not in a separate modal
- For the rich-text editor, if it fails to load, show a fallback textarea
- For date pickers, if they fail to load, show text inputs with ISO format placeholder
