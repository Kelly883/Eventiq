We need state management so the calendar pages don't handle data fetching and filtering themselves. Create three state managers:

1. Calendar state — Tracks the calendar view (month/week/day), the currently selected date, the list of events grouped by date, loading state, and any errors. Should support: changing the view (updates the calendar display), selecting a date (opens the day detail modal), and refreshing events. Internally handles pagination cursors if needed.

2. Filter state — Tracks the active filters: selected category, price range (min/max), location search, and sort option (date/price/popularity). Should support: updating any filter (triggers a re-query of the calendar), clearing all filters, and persisting filters to localStorage so they survive page refreshes.

3. Real-time inventory state — Tracks ticket availability for each event. Polls GET /api/events/public/calendar/day/:date every 30 seconds to fetch fresh availability data. Updates the event cards in real-time without requiring a full page refresh. Should handle: starting the poll when the modal opens, stopping it when the modal closes, and gracefully handling poll failures (don't break the UI, just skip that update).

Keep business logic out of the pages — pages should just call methods like selectDate(), updateFilter(), and let the state managers handle the API calls and data updates. Use React Context or a lightweight state library (like Zustand) to make these managers available throughout the component tree.
