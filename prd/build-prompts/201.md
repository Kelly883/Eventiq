We're building a secure checkout and ticket management system for an event ticketing platform. You need to build four pages that handle the complete purchase and ticket lifecycle.

CartPage at /cart — This is where users review items before checking out. Show a table-like layout with columns for ticket tier name, event, quantity, price per ticket, and line total. Each row should have '+' and '-' buttons to adjust quantity and a remove icon. On the right side (desktop) or bottom (mobile), display a summary card showing subtotal, fees, and total. The page should be accessible to both authenticated and unauthenticated users — cart state lives in local storage and is managed by CartContext. If the cart is empty, show an illustration with 'Your cart is empty' and a 'Browse Events' button that links to /events. The main call-to-action is a 'Proceed to Checkout' button that navigates to /checkout — this button should be disabled when the cart is empty. When a user updates a quantity, show a brief loading spinner on just that line item.

CheckoutPage at /checkout — This is a multi-step wizard for completing the purchase. Step 1 shows a final order summary and calls POST /api/cart/verify to confirm prices and availability. Step 2 (for guest users or users without saved billing info) collects billing information. Step 3 integrates Stripe's CardElement for secure payment collection — initialize it using a client secret from POST /api/checkout/create-payment-intent. On submission, call stripe.confirmCardPayment() to process the payment. The right side (desktop) or a collapsible section (mobile) shows the order summary throughout all steps. Payment elements should be styled to match your site's theme. Handle three states: loading (full-page spinner while creating the payment intent), submitting (spinner on the 'Pay' button, form fields disabled), and error (show specific error messages from Stripe like 'Your card was declined' or from the server like 'One or more items are no longer available'). On success, redirect to /order/{orderId}/confirmation. This page requires authentication — prompt users to log in or register if they aren't already.

OrderConfirmationPage at /order/:orderId/confirmation — Display a success confirmation after payment completes. Fetch order details using the orderId from the URL via GET /api/orders/:orderId. Show a prominent 'Thank You' message with a checkmark icon, the order ID, a receipt-like breakdown of items purchased, total amount paid, and payment method used. Include clear next steps like 'Your tickets have been sent to your email' and a primary button 'View My Tickets' that navigates to /my-tickets. Handle loading state with a skeleton layout, success state with the full order summary, and errors: 401 redirects to login, 403 shows 'You do not have permission to view this order', 404 shows 'Order not found' with a link back to the dashboard. This page requires authentication and the backend Policy ensures users can only view their own orders.

UserTicketsPage at /my-tickets — Display all tickets purchased by the authenticated user. Fetch from GET /api/my-tickets. Group tickets by event and list events chronologically. Each event is a collapsible card revealing individual tickets purchased for it. Each ticket card shows event details (title, date, venue), ticket tier, and a unique QR code rendered using qrcode.react. Provide options to download the ticket as a PDF or add it to a mobile wallet if supported. Handle loading state with skeleton ticket cards, empty state with an illustration and 'You have no tickets yet' message plus a 'Browse Events' button, error 401 redirects to login, and error 500 shows an error banner with a retry button. This page requires authentication and the API endpoint only returns tickets owned by the authenticated user.
