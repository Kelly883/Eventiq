We need to create both backend Eloquent models and frontend TypeScript types so data is consistent across the stack.

On the backend (Laravel), create four Eloquent models in app/Models/:

1. Order model — Maps to the orders table. Define relationships: hasMany('OrderItem'), belongsTo('User'), belongsTo('Event'), hasMany('Payment'). Add a method getFormattedTotal() that returns the total amount formatted as currency (e.g., '$99.99'). Add a method canBeRefunded() that checks if status is 'completed'. Add a scope scopeForUser($query, $userId) to filter orders by user.

2. OrderItem model — Maps to the order_items table. Define relationships: belongsTo('Order'), belongsTo('TicketTier'). Add a method getLineTotal() that returns quantity * unit_price.

3. Ticket model — Maps to the tickets table. Define relationships: belongsTo('Order'), belongsTo('User'), belongsTo('Event'), belongsTo('TicketTier'). Add a method isValid() that checks status === 'valid'. Add a scope scopeForUser($query, $userId) to filter tickets by user.

4. Payment model — Maps to the payments table. Define relationships: belongsTo('Order'). Add a method isSuccessful() that checks status === 'succeeded'.

On the frontend (React), create TypeScript types in src/features/checkout/types/:

1. Order type — id, userId, eventId, totalAmount, currency, status ('pending' | 'completed' | 'failed' | 'refunded'), paymentGateway, paymentIntentId, createdAt, updatedAt

2. OrderItem type — id, orderId, ticketTierId, quantity, unitPrice, createdAt, updatedAt

3. Ticket type — id, orderId, userId, eventId, ticketTierId, qrCodeData, status ('valid' | 'checked_in' | 'void'), checkedInAt, createdAt, updatedAt

4. Payment type — id, orderId, paymentIntentId, amount, currency, status, gateway, gatewayResponse, createdAt, updatedAt

Make all types immutable (readonly properties) since they represent data from the server.
