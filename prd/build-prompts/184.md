We need six reusable components that both the AuditLogsViewerPage and ComplianceReportsPage will share or use independently.

1. AuditLogsTable — A dense, scannable table component displaying audit log entries. Props: logs (array of AuditLog), loading (boolean), onRowClick (callback). Columns: timestamp (formatted), action (color-coded badge: blue=user action, green=system action, orange=admin action, red=error), actor (user email or 'System'), targetType, targetId, status (success/failed/pending), metadata summary. Each row is expandable to show full details. Implement sorting by clicking column headers. Show a loading skeleton while fetching. Handle empty state with a friendly message.

2. FilterPanel — A collapsible filter sidebar for audit logs. Props: onFilterChange (callback with filter object), filters (current filter state). Includes: date range picker (start/end dates), action type multi-select dropdown, targetType multi-select, status checkboxes (success, failed, pending), compliance classification multi-select, and a search box for target ID or actor email. Add a 'Clear All' button to reset filters. Show a badge count of active filters.

3. ExportButton — A button component that triggers audit log export. Props: filters (current filters to export), onExportStart (callback), onExportComplete (callback). Shows a dropdown menu with format options (CSV, JSON). On click, calls the export endpoint with current filters, shows a progress indicator, and triggers download when complete. Disable the button while exporting.

4. BulkActionBar — A toolbar that appears when audit logs are selected (checkboxes in the table). Props: selectedCount (number), onTag (callback with tag and notes), onClearSelection (callback). Shows: selected count, a 'Tag for Review' button that opens a modal to enter tag name and notes, and a 'Clear Selection' button. The modal validates that tag is not empty and notes don't exceed 500 chars.

5. ReportGenerator — A form component for generating compliance reports. Props: onReportGenerated (callback with jobId), onError (callback). Includes: report type selector (radio buttons or dropdown: data_access, user_activity, payment_audit, refund_audit, data_retention, incident_report), date range picker (required), classification filter (optional), format selector (PDF, CSV, JSON), and a 'Generate Report' button. Show a progress indicator and estimated completion time after submission. Validate that endDate > startDate and dates are not in the future.

6. ComplianceChecklist — A status indicator component showing compliance requirement statuses. Props: items (array of ComplianceChecklistItem). Displays each item as a row with: status indicator (green circle=compliant, amber circle=warning, red circle=non-compliant), requirement name, description, and last checked timestamp. Show a summary at the top: X/Y requirements met. This component is read-only (no actions).

All components should handle loading and error states gracefully. Use consistent styling with the rest of the app.
