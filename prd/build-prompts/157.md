We need three endpoints to power the AdminDashboardPage with real-time metrics, activity feed, and alerts.

1. GET /api/admin/dashboard/overview — Returns platform metrics for the dashboard.
   - Query params: ?period=24h|7d|30d (default: 24h)
   - Process: Verify auth token and extract userId. Check user has 'Admin' role using AdminPolicy::viewDashboard(). Query orders filtered by createdAt >= period start, sum total_amount for totalRevenue. Query events filtered by status='published', count for activeEvents. Query users filtered by role='organizer' and status='pending', count for pendingApprovals. Query fraud_events filtered by status='flagged', count for flaggedTransactions. Query payouts filtered by status='failed', count for failedPayouts. Calculate trend indicators by comparing current period to previous period (e.g., if revenue went from $10k to $12k, trend='up'). Return aggregated metrics.
   - Success (200): { period, totalRevenue (decimal), activeEvents (integer), pendingApprovals (integer), flaggedTransactions (integer), failedPayouts (integer), revenueTrend ('up'|'down'|'flat'), eventsTrend, transactionsTrend }
   - Errors: 400 (invalid period), 401 (unauthenticated), 403 (not admin), 500 (database error)
   - Rate limit: 20/min per user
   - Log to auditLogs with action='dashboard_viewed'

2. GET /api/admin/dashboard/activity-feed — Returns recent admin actions.
   - Query params: ?limit=20&offset=0 (optional, for pagination)
   - Process: Verify auth token. Check 'Admin' role. Query auditLogs filtered by action in ['user_suspended', 'user_unsuspended', 'event_approved', 'event_flagged', 'event_cancelled', 'payout_approved', 'payout_rejected', 'payment_refunded'], order by createdAt descending. Eager load related users (for performedBy), events, orders, payouts to avoid N+1 queries. Paginate with limit/offset. Return activity items with human-readable descriptions (e.g., 'Admin John suspended user jane@example.com').
   - Success (200): { activities: [{id, action, description, performedBy (admin name), targetType ('user'|'event'|'order'|'payout'), targetId, timestamp}], total, limit, offset }
   - Errors: 400 (invalid pagination), 401 (unauthenticated), 403 (not admin), 500 (database error)
   - Rate limit: 20/min per user

3. GET /api/admin/dashboard/alerts — Returns system alerts requiring admin attention.
   - Query params: ?severity=critical|warning|info (optional, default: all)
   - Process: Verify auth token. Check 'Admin' role. Query multiple sources: failed payment batches (payments where status='failed' and retryCount >= maxRetries), high fraud scores (fraud_events where riskScore > 75 and status='flagged'), system errors (system_logs where level='error' in last 24h), failed payouts (payouts where status='failed'), low inventory (ticket_inventory where isLowStock=true). Aggregate and sort by severity (critical > warning > info) and timestamp. Apply severity filter if provided. Return alert list with actionable information.
   - Success (200): { alerts: [{id, type ('payment_failure'|'fraud_spike'|'system_error'|'payout_failure'|'low_inventory'), severity ('critical'|'warning'|'info'), title, description, actionUrl, timestamp}], total }
   - Errors: 400 (invalid severity), 401 (unauthenticated), 403 (not admin), 500 (database error)
   - Rate limit: 20/min per user

Implementation details:
- Use Laravel's query builder or Eloquent with proper eager loading to avoid N+1 queries.
- Apply AdminOnly middleware to all three routes.
- Use rate limiting middleware configured for 20/min read operations.
- Return proper HTTP status codes and error messages.
- Log all dashboard access to auditLogs for audit trail.
