Now we need to connect the fraud detection feature to the rest of the app so it integrates with the checkout flow and admin navigation.

**Admin Navigation** — Add a 'Fraud Detection' link in the admin sidebar or navigation menu that goes to /admin/fraud/dashboard. This should only be visible to users with the 'Admin' role. The link should show a badge with the count of flagged transactions (update this every 30 seconds or when the dashboard is open).

**Checkout Integration** — The fraud detection system runs automatically during checkout. When a user initiates payment via POST /api/checkout/create-payment-intent, the backend runs fraud detection and returns a fraudRiskScore and requiresAdditionalVerification flag. On the frontend checkout page, if requiresAdditionalVerification is true, show a message to the user: 'Your transaction requires additional verification. Please wait while we review your order.' and disable the payment button. If the backend returns a 403 (fraud blocked - high risk), show an error message: 'We're unable to process your payment at this time due to security concerns. Please contact support.' with a support link. If the risk score is returned but no additional verification is needed, proceed normally with the payment flow.

**Webhook Handling** — The backend webhook endpoint POST /api/webhooks/payment-provider handles payment provider events (Stripe, Paystack, etc.). When a payment succeeds, the backend checks if the transaction was flagged for fraud. If it was auto-blocked, the order is voided and refunded automatically (user sees 'Payment failed' in the checkout). If it was flagged but approved by an admin, the order proceeds normally. If it was flagged and still pending review, the order is held with status='fraud_hold' and the user sees 'Your order is under review. We'll email you when it's approved.' This is all handled server-side, but make sure the checkout page handles the different order statuses correctly.

**Deep Linking** — If an admin receives a notification about a flagged transaction, they should be able to click a link that takes them directly to that transaction's review modal on the fraud dashboard. The link format is /admin/fraud/dashboard?fraudEventId={id}. When the page loads with this query param, automatically open the FraudTransactionReviewModal for that transaction.

**Audit Logging** — Every fraud decision (approve/reject) is logged to the backend's auditLogs table with the admin's ID and timestamp. Make sure the frontend doesn't need to do anything special here — the backend handles it when the admin submits their decision via POST /api/admin/fraud/review-transaction.
