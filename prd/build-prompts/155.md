We need to build the POST /api/refunds/request endpoint that allows authenticated users to submit refund requests. This is the core endpoint that drives the UserRefundRequestPage.

In app/Http/Controllers/RefundController.php, create a request() method that:

1. Validates the incoming request with Laravel validation rules:
- ticketId: required, uuid, exists:tickets.id
- reason: required, in:event_cancelled,personal_circumstances,duplicate_purchase,other
- explanation: nullable, string, max:500
- refundMethod: required, in:original_payment_method,store_credit,alternative_payment_method

2. Extracts the authenticated user from the bearer token (Laravel's auth middleware handles this)

3. Queries the tickets table to get the ticket and verify it exists (404 if not)

4. Uses the RefundPolicy authorization to check that the user owns this ticket (403 if not)

5. Queries the orders table to get the original purchase price and payment method

6. Queries the refund_policies table by eventId to get the policy for this event

7. Validates refund eligibility:
- Check if the request is within refundWindowDays (calculate days since ticket purchase date)
- If event has started, check if allowRefundsAfterEventStart is true (403 if not)
- Check if reason is in the policy's refundReasons array (400 if not)
- Check if refundMethod is in the policy's allowedRefundMethods array (400 if not)
- Check if user hasn't already requested a refund for this ticket (409 if duplicate)
- Check if user hasn't exceeded maxRefundsPerUser for this event (403 if exceeded)

8. Calculates the refund amount:
- If event hasn't started: refundAmount = originalAmount * (refundPercentageBeforeEvent / 100)
- If event has started: refundAmount = originalAmount * (refundPercentageAfterEventStart / 100)

9. Determines the initial status:
- If requiresApproval=false OR (autoApproveThreshold is set AND refundAmount < autoApproveThreshold): status='approved', queue RefundProcessingJob
- Otherwise: status='pending'

10. Creates a RefundRequest record with all the data

11. Creates an auditLog entry with action='refund_requested', userId, ticketId, refundAmount

12. Sends a notification to the user with the refund reference number and expected processing timeline

13. Returns 200 with: { refundRequestId, status, refundAmount, expectedProcessingDays, referenceNumber, message }

Handle errors:
- 400: Invalid input (validation fails), invalid reason, invalid refund method
- 401: Unauthenticated (no bearer token)
- 403: User doesn't own ticket, refund window closed, event policy doesn't allow refunds, user exceeded max refunds
- 404: Ticket or event not found
- 409: Duplicate refund request for same ticket
- 429: Rate limited (5 requests/hour per user)
- 500: Database error

Implement rate limiting using Laravel's throttle middleware: Route::post('/refunds/request', [RefundController::class, 'request'])->middleware('throttle:5,60');

All requests should be logged to auditLogs table with userId, action, and timestamp.
