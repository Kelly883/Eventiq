Let's make sure the role and permission system is properly secured against abuse and unauthorized access.

All four endpoints (GET /api/admin/users/list, POST /api/admin/roles/assign, POST /api/admin/permissions/update, GET /api/admin/audit-log/list) must enforce admin-only access using Laravel Policies. Check that the authenticated user's role is 'Admin' before allowing any action. Return 403 Forbidden if not.

GET /api/admin/users/list — Validate query parameters: role must be one of the four valid roles (Admin, Organizer, Attendee, Support Staff), page must be a positive integer, limit must be between 1 and 100. Never expose password hashes or sensitive user data. Rate limit to 10 requests per minute per admin to prevent abuse.

POST /api/admin/roles/assign — Validate that userIds is a non-empty array and roleId exists in the roles collection. Prevent self-demotion: if the admin is trying to demote themselves, return 403. Use a database transaction to ensure atomicity — if any user update fails, roll back all changes. After a successful role change, invalidate the user's sessions (set revokedAt timestamp on all their active sessions) so the new role takes effect immediately. Log the change in auditLogs with the admin ID, target user ID, old role, new role, and optional reason. Rate limit to 10 requests per minute per admin.

POST /api/admin/permissions/update — Validate that userId exists, permissionIds are valid, and action is 'grant' or 'revoke'. Check the riskLevel of each permission — if any is 'high', require explicit confirmation (the client should send a confirmHighRisk flag). Prevent admins from modifying their own high-risk permissions without a second confirmation. Use a transaction. After updating, invalidate the user's sessions. Log each permission change in auditLogs. Rate limit to 10 requests per minute per admin.

GET /api/admin/audit-log/list — Validate query parameters. Logs are immutable and append-only — never allow deletion or modification. Return 403 if a non-admin tries to access. Rate limit to 10 requests per minute per admin.

All endpoints must check authentication first (401 if no valid token). All endpoints must validate input and return 400 for invalid data. All endpoints must use HTTPS only (enforce in middleware). All endpoints must log access attempts (especially failed ones) for security monitoring.

On the frontend, never store sensitive data (like admin tokens) in localStorage — use httpOnly cookies. Never expose the admin API endpoints in client-side code or error messages. Sanitize all user input before sending to the API.
