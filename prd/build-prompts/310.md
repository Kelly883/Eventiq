We need to make sure things fail gracefully when something goes wrong, so users always know what happened and can recover.

OrganizerDashboardPage:
- Network failure on initial load → show a full-screen error banner with 'Unable to load dashboard' and a 'Retry' button. Don't show partial data.
- 401 (auth expired) → redirect to login page with a 'Session expired' toast notification.
- 403 (not an organizer) → show a full-screen message 'Access Denied — only organizers can view dashboard' with a back button.
- 500 (server error) → show an error banner with 'Something went wrong' and a 'Retry' button. Keep any previously loaded data visible.
- Failure while loading more events (pagination) → show a brief toast notification 'Failed to load more events' but keep the already-loaded events visible.
- Filter or sort change fails → show a toast 'Failed to apply filter' and revert the filter/sort to the previous selection.

EventDetailWidget:
- Failure to load event details → show 'Unable to load event details' message with a close button. The widget should collapse.
- Tier data missing or malformed → show a placeholder 'Tier data unavailable' instead of crashing.
- Pricing window data missing → show 'No pricing windows configured' instead of an empty section.

SalesActivityFeed:
- Failure to load activity feed → show a toast 'Failed to load activity feed' but keep any previously loaded activities visible.
- Auto-refresh fails → don't show an error (it's a background operation), just silently skip that refresh cycle and try again in 30 seconds.
- CSV export fails → show a toast 'Failed to export activity' with a 'Retry' button.
- Empty activity feed → show 'No sales yet' message instead of a blank section.

Metric cards:
- If a metric fails to load → show a placeholder 'N/A' or '—' instead of a number. Don't show an error message for individual metrics.
- If trend calculation fails → hide the trend indicator but still show the metric value.

General error handling:
- All API errors should be caught and logged (but not exposed to the user in raw form).
- Show user-friendly error messages, never technical jargon or error codes.
- Provide a 'Retry' button for recoverable errors (network failures, timeouts).
- For non-recoverable errors (403, 404), show a back button or navigation link.
- Use toast notifications for transient errors (failed to load more, failed to export) and full-screen messages for critical errors (401, 403, initial load failure).
- Set a timeout of 10 seconds for API requests. If a request takes longer, show 'Request timed out' and offer a retry.
- If the user is offline, show 'No internet connection' and disable auto-refresh.

Implement a global error boundary that catches React errors and shows 'Something went wrong' with a 'Reload Page' button.
