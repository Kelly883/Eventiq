We're building a real-time sales analytics system for event organizers. You need to create three pages that let organizers monitor ticket sales, dive into detailed transaction data, and compare performance across events.

Start with SalesAnalyticsDashboardPage at /organizer/events/:eventId/analytics. This is the main dashboard organizers will check constantly. At the top, render four metric cards in a row showing: total revenue, tickets sold, average ticket price, and conversion rate (tickets sold divided by page views). Each card should show the current value prominently and include a small trend indicator — green arrow up if the metric improved compared to the previous period, red arrow down if it declined, gray dash if flat. These come from calling GET /api/organizer/events/:eventId/analytics/summary.

Below the metrics, arrange two charts side-by-side on desktop (stacked on mobile): a line chart on the left showing sales velocity over time (cumulative sales and revenue by hour/day depending on the date range), and a bar chart on the right showing revenue breakdown by ticket tier. Both charts come from GET /api/organizer/events/:eventId/analytics/sales-velocity. Use recharts for both charts with interactive tooltips so users can hover and see exact values.

At the top of the page, add a sticky header with a date range picker (start and end date inputs using date-fns for formatting) and a dropdown to filter by ticket tier. Include a 'Live' badge with a pulse animation that indicates when data was last updated. Add a manual refresh button and set up auto-refresh every 30 seconds using polling — call the summary endpoint again and update the metrics and charts.

At the bottom, add a collapsible card for demographic insights showing attendee breakdown by ticket tier and geographic distribution if available. This section can be collapsed on mobile to save space.

Handle loading state by showing skeleton cards for the metrics and placeholder shimmer animations for the charts. For empty state (no sales yet), show a friendly message 'No sales data yet' with an illustration and a link back to the event page. For error 401, redirect to login with a 'Session expired' toast. For 403, show 'Access Denied — only event organizers can view analytics' with a back button. For 404, show 'Event not found' with a link to the events list. For 500, show an error banner with a retry button.

Next, build DetailedAnalyticsPage at /organizer/events/:eventId/analytics/detailed. This is the deep-dive page for power users who want granular data. Use a two-column layout on desktop: a sticky filter panel on the left with date range picker, tier filter, and pricing window filter; the main content area on the right with tabbed sections.

Create five tabs: Transactions, Funnel, Cohorts, Pricing Performance, and Channels. The Transactions tab shows a virtualized table of all sales transactions (use react-window for performance with large datasets) with columns: timestamp, ticket tier, price, buyer email (if available and user has permission). Make the table sortable and filterable. The Funnel tab visualizes the conversion funnel: event page views → ticket page views → purchases, showing drop-off rates at each stage. The Cohorts tab shows repeat attendees vs. first-time buyers. Pricing Performance compares which pricing tiers drove the most revenue and had the highest conversion rates. Channels shows which marketing channels (if tracked) drove sales.

All charts use recharts with interactive tooltips. The transaction table should handle large datasets smoothly with virtualization. On mobile, stack everything single-column and make the filter panel collapsible.

Handle the same error states as the dashboard page: loading shows skeleton rows and placeholder charts, empty state shows 'No transaction data available', 401 redirects to login, 403 shows 'Access Denied', 404 shows 'Event not found', 500 shows error banner with retry.

Finally, build AnalyticsComparisonPage at /organizer/analytics/compare. This page lets organizers compare sales performance across multiple events. Split the page into two sections: the top section shows a list of all the organizer's events with checkboxes (max 3 events can be selected). Each row shows key metrics: total revenue, tickets sold, conversion rate, average ticket price, attendee count. The bottom section shows comparison charts and a metrics table side-by-side for the selected events. Use different colors for each event in the charts so they're visually distinct.

When the user selects events, call GET /api/organizer/analytics/compare-events and render comparison charts showing revenue trends, sales velocity, and tier performance across the selected events. On mobile, stack the sections and make the event selector collapsible.

Handle loading by showing skeleton event list and placeholder comparison charts. Empty state (only 1 event) shows 'Create more events to compare performance'. Error 401 redirects to login, 403 shows 'Access Denied', 500 shows error banner. Success displays the full event list with comparison charts.

All three pages should use date-fns for date formatting and manipulation. Use Mixpanel SDK to log analytics events (page views, filter changes, exports) so you can track how organizers use the analytics feature.
