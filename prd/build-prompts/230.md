We need three state managers so the delivery pages don't handle data fetching themselves. Use React Context or a state management library (like Zustand or Redux) to keep these separate from the UI.

1. Ticket Delivery Status state — Tracks a single ticket's delivery status, loading state, and errors. Should fetch from GET /api/tickets/:ticketId/delivery-status when the page loads. Exposes: ticketId, status (pending/sent/failed/viewed), deliveryMethod, recipientEmail, recipientPhone, deliveryTimestamp, viewedTimestamp, attemptCount, maxAttempts, errorMessage, nextRetryAt, qrCodeData, ticketPdfUrl, and deliveryHistory (array of all attempts with timestamps, statuses, and error messages). Include a resendTicket() method that calls POST /api/tickets/:ticketId/resend-delivery with optional deliveryMethod, recipientEmail, or recipientPhone overrides. This method should handle the spinner state and error handling.

2. Delivery Preferences state — Tracks the user's delivery settings. Fetch from GET /api/users/me/delivery-preferences on page load. Exposes: emailEnabled, emailAddress, emailVerified, smsEnabled, phoneNumber, phoneVerified, dashboardEnabled, primaryMethod, backupMethod, deliveryTiming, receiveConfirmation, receiveReminders, and languagePreference. Include an updatePreferences() method that calls POST /api/users/me/delivery-preferences/update with the changed fields. Include separate methods verifyEmail() and verifyPhone() that call POST /api/users/me/verify-email-delivery and POST /api/users/me/verify-phone-delivery. Handle loading and error states for each operation independently (so saving one field doesn't block the whole form).

3. Admin Delivery Events state — Tracks all delivery events for the admin dashboard. Fetch from GET /api/admin/delivery/events with support for filters (event, method, status, date range) and search (ticket ID, email). Exposes: deliveryEvents (array), totalDelivered (24h), successRate (%), failedCount, averageDeliveryTime, isLoading, error, and filters. Include methods: setFilters(), search(), retryFailed() (calls POST /api/admin/delivery/retry), and exportCSV() (calls GET /api/admin/delivery/export). Implement real-time polling every 30 seconds to refresh the metrics and event list. Handle pagination with cursor-based approach if the event list is large.

Keep all business logic out of the pages — pages should just call methods and react to state changes. Debounce search queries to avoid hammering the backend.
