We need state managers to handle the pricing configuration data and form state without cluttering the pages themselves.

Create a custom hook called usePricingWindows that manages the list of pricing windows for an event. This hook should: fetch windows from GET /api/organizer/events/:eventId/pricing/windows on mount, track loading and error states, provide methods to add a new window (POST), update an existing window (PATCH), and delete a window (DELETE). When any of these methods are called, optimistically update the local state first, then sync with the backend. If the backend call fails, revert the local state and show an error.

Create another hook called usePricingForm that manages the form state for creating/editing a pricing window. This hook should track: window name, start date/time, end date/time, price, quantity limit, and priority. It should provide validation methods that check: window name is not empty, start is before end, end is before the event end date, price is positive, and quantity limit (if provided) is positive. It should also check for overlapping windows with the same ticket category. Provide a reset method to clear the form after successful submission.

Create a hook called usePricingPreview that fetches the preview data from GET /api/organizer/events/:eventId/pricing/preview. This should track loading and error states and provide the structured preview data grouped by category.

For the timeline visualization, create a hook called useTimelineData that takes the list of pricing windows and the event date, and returns a structured format suitable for rendering: windows sorted by start date, with computed properties like isActive, daysUntilStart, daysUntilEnd, and percentageComplete.

All hooks should handle errors gracefully and expose error messages that the pages can display to users. Use React's useState and useEffect for state management.
