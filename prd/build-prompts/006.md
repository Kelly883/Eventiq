We're building a dynamic pricing and sales windows feature for event organizers. This lets them create time-based pricing tiers for ticket categories.

On the frontend (React + Vite), create a pricing feature area under src/features/pricing/ with these subfolders:
- pages (EventPricingConfigPage, PricingPreviewModal)
- components (PricingWindowForm, PricingWindowCard, TimelineVisualization, CategoryCard, PricingPreview)
- hooks (usePricingWindows, usePricingPreview)
- types (pricing types and interfaces)
- services (API calls to pricing endpoints)
- utils (validation, date helpers, formatting)

On the backend (Laravel), create a pricing feature under app/Features/Pricing/ with:
- Models (PricingWindow model)
- Controllers (PricingWindowController for organizer endpoints, PricingController for attendee endpoint)
- Requests (StorePricingWindowRequest, UpdatePricingWindowRequest for validation)
- Policies (PricingWindowPolicy for authorization)
- Resources (PricingWindowResource for API responses)
- Routes (pricing routes in api.php)

This structure keeps pricing logic isolated and makes it easy to test and maintain.
