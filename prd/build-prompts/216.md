We're building a payment gateway integration feature for a Laravel backend. You need to create two React pages that let users manage their payment methods and organizers connect their Stripe accounts.

First, build PaymentMethodsPage at /settings/payment-methods. This is a section within the user settings layout (not a standalone page). The page fetches the user's saved payment methods from GET /api/users/me/payment-methods when it loads. Display the payment methods as a list or card grid, showing the card brand, last four digits, and expiration date for each. Mark the default card with a badge. Each card needs two action buttons: 'Set as Default' (calls PATCH /api/users/me/payment-methods/:id/set-default) and 'Remove' (calls DELETE /api/users/me/payment-methods/:id). Add a prominent 'Add New Card' button that opens a modal (not a new page). Inside the modal, use Stripe Elements to securely collect card details — never send raw card data to your server. When the user submits the form, call stripe.createPaymentMethod to get a payment method ID, then send that ID to POST /api/users/me/payment-methods to save it. Handle loading states with skeleton cards while fetching. Show an empty state with an illustration and 'No payment methods saved' message if the list is empty. Show error states: if the user isn't authenticated (401), redirect to login; if there's a server error (500), show an error banner with a retry option. When an action succeeds (add, remove, or set default), show a toast confirmation and refresh the payment methods list.

Second, build OrganizerPaymentSettingsPage at /organizer/settings/payments. This is also a section within organizer settings. When the page loads, check the organizer's Stripe Connect status by calling GET /api/organizer/settings/stripe-connect. If the organizer isn't connected yet, show explanatory text about the Stripe partnership and a 'Connect with Stripe' button. Clicking that button navigates to GET /api/organizer/settings/stripe-connect, which redirects to Stripe's onboarding flow. If the organizer is already connected, display the masked Stripe account ID, the connection status ('Enabled' or 'Pending'), and a link to their Stripe Express Dashboard. Add a 'Disconnect' button (you'll wire this up later). Show a loading spinner while checking the connection status. If the user isn't authenticated (401), redirect to login. If the user isn't an organizer (403), show 'Access Denied - Only organizers can configure payments.'

Both pages should use the payment_methods schema to understand the data structure (id, user_id, gateway, gateway_payment_method_id, type, details, is_default, created_at, updated_at). The users schema has stripe_id, pm_type, pm_last_four, and trial_ends_at fields that may be relevant for display. The organizers schema has stripe_account_id and stripe_connect_status fields that drive the OrganizerPaymentSettingsPage UI.
