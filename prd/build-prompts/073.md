We need to set up three database tables to store push notification data.

Create a Laravel migration for the push_notification_devices table with these fields:
- id (UUID primary key)
- user_id (foreign key to users table, indexed)
- token (string, unique) — the FCM device token
- provider (string, e.g., 'fcm') — which service provided the token
- device_type (enum: 'web', 'ios', 'android') — the device platform
- created_at and updated_at timestamps

Create a migration for the push_notification_templates table:
- id (UUID primary key)
- name (string) — template name like 'Event Reminder'
- type (string) — notification type
- title (string, max 65 chars) — the notification title
- body (text, max 178 chars) — the notification body
- variables (JSON) — available placeholder variables like {{user.name}}, {{event.title}}
- is_active (boolean, default true)
- created_at and updated_at timestamps

Create a migration to add push notification fields to the existing delivery_preferences table:
- push_notifications_enabled (boolean, default false)
- push_order_confirmation (boolean, default false)
- push_event_reminder (boolean, default false)
- push_checkin_alert (boolean, default false)
- push_promotional_offers (boolean, default false)

Run php artisan migrate to apply all migrations. Add database indexes on push_notification_devices.user_id and push_notification_devices.token for fast lookups.
