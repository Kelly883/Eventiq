We need two API endpoints to power the analytics dashboards. Both are read-only and require authentication.

1. GET /api/organizer/events/:eventId/analytics/summary — Returns high-level metrics for the SalesAnalyticsDashboardPage. Process: Verify the auth token and extract userId. Query the events table by eventId. Check that the authenticated user owns the event using Laravel's Policy (authorize with 'view' action). Query analytics_events_metrics filtered by eventId. If optional startDate and endDate query params are provided, recalculate metrics on-the-fly by querying analytics_sales_timeline and grouping by date range. Calculate trend indicators by comparing the current period to the previous period of equal length. Return: { totalRevenue (decimal), totalTicketsSold (integer), conversionRate (decimal %), averageTicketPrice (decimal), totalPageViews (integer), revenueTrend ('up'|'down'|'flat'), ticketsTrend (string), conversionTrend (string), lastUpdatedAt (timestamp) }. Errors: 400 (invalid eventId or date format), 401 (unauthenticated), 403 (user doesn't own event), 404 (event not found), 500 (database error). Apply rate limit: 20 requests/min per user.

2. GET /api/organizer/events/:eventId/analytics/sales-velocity — Returns time-series sales data for the sales velocity chart on SalesAnalyticsDashboardPage. Process: Verify auth token. Query events by eventId. Check ownership via Policy. Query analytics_sales_timeline filtered by eventId and optional date range. Group sales by granularity (hour, day, or week — default hour). Calculate cumulative sales and revenue, plus period-specific sales and revenue. Return: { dataPoints: [{timestamp (ISO8601), cumulativeSales (integer), cumulativeRevenue (decimal), periodSales (integer), periodRevenue (decimal)}], granularity (string), startDate (ISO8601), endDate (ISO8601) }. Errors: 400 (invalid granularity or date range), 401 (unauthenticated), 403 (forbidden), 404 (event not found), 500 (database error). Rate limit: 20 requests/min per user.

Both endpoints should use Laravel's authorization (Gate::authorize or Policy) to enforce organizer-only access. Use query scopes (scopeForEvent, scopeByDateRange) to keep queries clean. Cache the summary metrics for 30 seconds to reduce database load, but allow manual refresh via a query param (?refresh=true). All responses should include a lastUpdatedAt timestamp so the frontend knows when the data was last refreshed.
