We need five reusable components that the pricing pages will share.

1. CategoryCard — Displays a single ticket category with its base price and list of active pricing windows. Shows category name, base price, and a collapsible section with windows. Each window shows as a compact row with window name, date range, price, and quantity info. Clicking 'Add Window' opens the form. Used in EventPricingConfigPage.

2. PricingWindowCard — Shows a single pricing window with all details: window name, start/end dates, price, quantity limit, quantity sold, and available quantity. Includes edit and delete buttons. Supports drag-to-resize for date adjustment (optional but nice). Color-coded by window type (early bird=green, regular=blue, last-minute=orange). Used in CategoryCard and timeline.

3. TimelineVisualization — Renders a visual timeline showing when each pricing window is active relative to the event date. Horizontal timeline with event date marked. Each window shown as a colored block positioned by its dates. Hover shows details. Used in EventPricingConfigPage to help organizers visualize the pricing schedule.

4. PricingWindowForm — Form for creating or editing a pricing window. Fields: window name (text), ticket category (dropdown), start date/time (datetime picker), end date/time (datetime picker), price (number), quantity limit (number, optional), priority (number). Uses react-hook-form for state management and Zod for validation. Shows validation errors inline. Submit button shows loading state. Used in a modal or inline on EventPricingConfigPage.

5. PricingPreviewTimeline — Displays pricing schedule for a single ticket category in the preview modal. Vertical timeline with price points marked. Shows active (green), upcoming (blue), and past (gray) windows. Includes countdown timer for next price change. Shows current price prominently. Used in PricingPreviewModal.

All components should handle loading states (skeleton placeholders) and error states gracefully.
