We need two API endpoints to handle ticket delivery status and resending.

1. GET /api/tickets/:ticketId/delivery-status — This endpoint retrieves the current delivery status for a single ticket. Process: Verify the user is authenticated (extract userId from bearer token). Query the tickets table to find the ticket by ticketId. Use the DeliveryEventPolicy to check that the user owns this ticket (throw 403 if not). Query delivery_events filtered by ticketId, ordered by createdAt descending to get the full history. Eager load related order and event details to avoid N+1 queries. Compute the current delivery status by looking at the most recent delivery_event. Return a JSON response with: ticketId, status (pending/sent/failed/viewed), deliveryMethod, recipientEmail, recipientPhone, deliveryTimestamp, viewedTimestamp, attemptCount, maxAttempts, errorMessage, nextRetryAt, qrCodeData, ticketPdfUrl, and a deliveryHistory array with all attempts (timestamp, status, method, errorMessage). Handle errors: 400 for invalid ticketId format, 401 if not authenticated, 403 if user doesn't own the ticket, 404 if ticket not found, 500 for database errors. Rate limit to 20 requests/min per user.

2. POST /api/tickets/:ticketId/resend-delivery — This endpoint resends a ticket via a specified delivery method. Request body: deliveryMethod (optional, defaults to user's primary method), recipientEmail (optional for email), recipientPhone (optional for SMS). Process: Verify authentication. Query the ticket and check ownership via policy. Query delivery_events to get the last delivery attempt. Validate that the requested deliveryMethod is enabled in the user's delivery_preferences. If email: validate email format, check that delivery hasn't failed 5+ times already. If SMS: validate phone format (E.164), check attempt limit. Query fraud_events to ensure the order isn't blocked (throw 403 if deliveryBlocked is true). Increment attemptCount on the delivery_event. Queue a SendTicketDeliveryJob with the ticket, user, and delivery method. Update delivery_events status to 'pending' and set nextRetryAt based on exponential backoff. Return 200 with: ticketId, status: 'pending', deliveryMethod, nextRetryAt, message: 'Ticket resend initiated'. Handle errors: 400 for invalid method/format or max attempts exceeded, 401 if not authenticated, 403 if user doesn't own ticket or delivery is blocked by fraud, 404 if ticket not found, 409 if delivery is already in progress, 429 if rate limited (10 resends/min per user), 500 for provider errors. Use the bam-ticketing-sdk to queue the actual delivery.

Both endpoints should be protected by authentication middleware and use Laravel's built-in rate limiting. Log all delivery actions to the audit log with the admin ID and timestamp.
