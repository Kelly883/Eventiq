We need four API endpoints to handle reading and updating accessibility and localization preferences. All endpoints require authentication (Bearer token in Authorization header).

1. GET /api/users/me/accessibility-preferences — Fetch the authenticated user's accessibility preferences. Process: verify auth token, extract userId, call AccessibilityPreference::getOrCreateForUser($userId) to get or create with defaults, return all preference fields (fontSize, highContrast, screenReaderOptimized, focusIndicatorEnhanced, motionReduced, lineHeight, letterSpacing, wordSpacing, colorBlindnessMode). Return 200 with preferences. Handle 401 (unauthenticated), 403 (forbidden), 500 (database error). Rate limit 20/min per user.

2. PATCH /api/users/me/accessibility-preferences/update — Update accessibility preferences. Process: verify auth token, validate input (fontSize 12-24, lineHeight 1.0-2.0, letterSpacing 0-0.2, wordSpacing 0-0.2, colorBlindnessMode valid enum), get or create preferences record, update only provided fields, set updatedAt, create auditLog entry with action='accessibility_preferences_updated', userId, and changedFields, return updated preferences with message 'Accessibility preferences updated'. Return 200. Handle 400 (validation error), 401, 403, 429 (rate limited), 500. Rate limit 10 changes/min per user.

3. GET /api/users/me/language-preferences — Fetch the authenticated user's language preferences. Process: verify auth token, extract userId, call LanguagePreference::getOrCreateForUser($userId) to get or create with defaults (language='en', region=null, dateFormat='MM/DD/YYYY', timeFormat='12-hour', currency=null, numberFormat='comma', rtlEnabled=false), return all preference fields. Return 200. Handle 401, 403, 500. Rate limit 20/min per user.

4. PATCH /api/users/me/language-preferences/update — Update language preferences. Process: verify auth token, validate input (language must be supported ISO 639-1 code from i18next config, dateFormat one of 'MM/DD/YYYY'/'DD/MM/YYYY'/'YYYY-MM-DD', timeFormat '12-hour' or '24-hour', numberFormat 'comma' or 'period'), get or create preferences record, update only provided fields, auto-set rtlEnabled based on language (true if Arabic/Hebrew/Urdu, false otherwise), set updatedAt, create auditLog entry with action='language_preferences_updated', userId, and changedFields, return updated preferences with message 'Language preferences updated'. Return 200. Handle 400 (validation error), 401, 403, 429 (rate limited), 500. Rate limit 5 language changes/min per user.

All endpoints should use Laravel's authorization policies (AccessibilityPreferencePolicy and LanguagePreferencePolicy) to enforce that users can only access their own preferences. Use middleware for rate limiting and authentication.
