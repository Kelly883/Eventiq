We need to build seven public API endpoints in Laravel that the React frontend will call to fetch event data. All of these are public endpoints (no authentication required) but they should be rate-limited to 30 requests per minute per IP to prevent scraping.

1. GET /api/events/public/list — The main event listing endpoint. Accept query params: page (default 1), limit (max 50, default 20), category, dateRange (upcoming/this-week/this-month/custom), priceMin, priceMax, sortBy (date/price/popularity), sortOrder (asc/desc). Validate all params. Query published events, apply filters, join with pricing_windows for price filtering, join with analytics_events_metrics for popularity sorting. Eager load organizer details (name, avatar, branding colors). Compute ticket availability from ticket_inventory. Return paginated results with total count, current page, and limit.

2. GET /api/events/public/search — Autocomplete search endpoint. Accept query param q (min 2 chars, max 100 chars). Query published events, search title and description using full-text search or LIKE pattern. Limit to 10 results. Return minimal data: id, title, organizer name, date.

3. GET /api/events/public/filters — Return available filter options. Query distinct categories from published events, get min/max prices from pricing_windows, return hardcoded date range options. No query params needed. This can be cached on the frontend since it changes infrequently.

4. GET /api/events/public/:eventId — Get full event details. Query event by ID, check status='published' (return 404 if not). Eager load organizer (name, avatar, bio, branding colors, social links), ticket tiers, and analytics metrics. Return comprehensive event details.

5. GET /api/events/public/:eventId/pricing — Get current pricing for an event. Query event by ID, check published status. Query active pricing windows (current time between start and end). If no active windows, return most recent window as fallback. Eager load ticket tiers. For each tier, compute current price and next price change info. Return pricing data with countdown to next price change.

6. GET /api/events/public/:eventId/related — Get related events from the same organizer. Query event by ID, check published. Get organizer_id. Query other published events from same organizer (excluding current event), limit to 5, order by start_datetime ascending. Return related events with minimal data.

7. GET /api/events/public/category/:categoryId — Get events in a specific category. Validate categoryId is a valid category. Query published events filtered by category. Apply sorting (date or popularity). Paginate. Eager load organizer details. Return category info, paginated events, total count.

For all endpoints, return 400 for invalid query params, 404 for not found, 500 for database errors. Include proper error messages. Apply rate limiting middleware to all routes.
