We're building an event calendar feature for browsing and discovering events. This step creates the two main UI pages that users interact with.

Start with EventCalendarPage at /events/calendar. This is the main calendar interface. At the top, add toggle buttons for month, week, and day view — users should be able to switch between these perspectives. Below that, place a search bar with autocomplete that queries event titles as the user types. On the left side, create a sticky filter sidebar (collapsible drawer on mobile) with: a category dropdown, a price range slider (min/max inputs), and a location search field. The main content area shows a calendar grid using react-big-calendar. Each date cell displays an event count and a color-coded indicator: green for available, amber for low stock, red for sold out. Clicking a date opens the CalendarDayDetailModal showing all events for that day. Clicking an event card navigates to /events/:eventId. Add a 'Create Event' button in the top-right that only shows for authenticated organizers — it routes to /organizer/events/create. The page should poll the backend every 30 seconds to refresh ticket availability, so users see real-time inventory updates. Handle loading state with skeleton calendar grid and shimmer effect. Empty state shows 'No events found' with a 'Clear filters' button. Error state shows a banner with a retry option.

Next, build CalendarDayDetailModal. This renders as a right sidebar on desktop (300-400px width) and a full-width bottom sheet modal on mobile. It displays a sticky date header at the top (e.g., 'Friday, March 15, 2024'). Below that, a vertically scrollable list of event cards for the selected date. Each card shows: event thumbnail image, title, organizer avatar and name, date/time, venue name, ticket availability status (e.g., '45 tickets remaining' or 'Sold out'), starting price, and a 'View Details' button. A close button (X) in the top-right dismisses the modal. Apply the same filters from the main calendar to this modal — if the user filtered by category or price, only matching events appear here. Loading state shows 3-5 skeleton event cards with shimmer. Empty state shows 'No events scheduled for this date' with an illustration. Error state shows 'Unable to load events' with a close button. Success state displays all events for the selected date with full details.

Both pages should call GET /api/events/public/calendar (for the month/week view), GET /api/events/public/calendar/day/:date (for the day detail modal), and GET /api/events/public/calendar/range (for date range queries). Wire up the filter sidebar so changing category, price range, or location re-queries the calendar with the new filters. The search bar should debounce input and call the search endpoint. Make sure organizer branding colors are applied to event cards — pull the brandingColors from the organizer object returned by the API.
