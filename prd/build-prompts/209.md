On the right side (or sticky at bottom on mobile), show a refund calculation card that updates in real-time: original price, refund percentage, and final refund amount (e.g., '$80 × 80% = $64'). The 'Submit Refund Request' button calls POST /api/refunds/request. On success, show a confirmation screen with the reference number, expected processing timeline, and a 'View Status' button that navigates to the status page. Display a refund status badge showing the current stage (pending/approved/rejected/processing/completed) with a visual timeline. Handle loading state with skeleton cards and placeholder form fields. Handle error states: 401 redirects to login with a 'Sign in to request refund' toast, 403 shows 'Refund window closed' or 'Not eligible for refund', 404 shows 'Ticket not found', 500 shows an error banner with retry. Validation errors highlight the invalid field with a red border and error message.

UserRefundStatusPage at /my-tickets/:ticketId/refund-status — This shows real-time status of a submitted refund request. Start with a color-coded status badge prominently at the top (amber for pending, green for approved, red for rejected). Below that, display a refund details card with ticket info, original price, refund amount, reason, and submission date. Build a timeline visualization showing all stages: submitted → under review → approved/rejected → processing → completed. Highlight the current stage with a color-coded indicator. Show a refund history section at the bottom listing all status changes with timestamps. For completed refunds, show a green checkmark and actual completion date. Add a 'Download Receipt' button to export the refund confirmation as PDF. Handle loading state with skeleton status card and placeholder timeline. Handle error states: 401 redirects to login, 403 shows 'Access Denied — you don't own this refund request', 404 shows 'Refund request not found', 500 shows error banner with retry. When submitting an appeal, show a spinner on the button and disable it.

AdminRefundDashboardPage at /admin/refunds/dashboard — This is an admin-only real-time dashboard for managing all refund requests. Start with four summary metric cards at the top showing: total pending refunds (count), total refund amount pending ($), approval rate (%), and average processing time (days). Add color-coded trend indicators (green for up, red for down). Below that, build an interactive data table with these columns: ticket ID, event name, buyer email, refund amount, reason, status (with color-coded badges: amber=pending, green=approved, red=rejected, blue=processing, gray=completed), submission date, and action buttons. Make columns sortable. Add expandable rows that show full refund request details including reason, refund policy applied, and audit trail without leaving the page. Add a sticky filter bar with filters for: event, status, date range, refund amount range, and reason. Include a search box to find by ticket ID, email, or event name. Add bulk action checkboxes to approve or reject multiple requests at once. Include an 'Export as CSV' button for the refund report. Add a chart showing refund method breakdown (percentage by original_payment_method, store_credit, alternative_payment_method). Update metrics in real-time every 30 seconds. Handle loading state with skeleton metric cards and placeholder table rows with shimmer. Handle empty state with 'No refund requests yet' message and illustration. Handle error states: 401 redirects to login with 'Session expired' toast, 403 shows 'Access Denied — only admins can view refund dashboard' with back button, 500 shows error banner with retry. On mobile, replace the table with stacked cards and collapse details into expandable sections.
