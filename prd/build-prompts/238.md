We need state managers so the admin pages don't handle data fetching themselves. Use TanStack Query (React Query) for server state and local React state for UI state.

**Dashboard State** — Create a custom hook `useDashboardMetrics()` that fetches from GET /api/admin/dashboard/overview with a query key of `['admin', 'dashboard', 'metrics']`. Support optional query param `period` (24h, 7d, 30d, default 24h). Cache for 60 seconds (staleTime: 60000) so the auto-refresh works smoothly. Return { data, isLoading, error, refetch }. Create another hook `useDashboardActivityFeed()` that fetches from GET /api/admin/dashboard/activity-feed with pagination support (limit, offset). Cache for 60 seconds. Create a third hook `useDashboardAlerts()` that fetches from GET /api/admin/dashboard/alerts with optional severity filter. Cache for 60 seconds. All three should automatically refetch every 60 seconds using `refetchInterval: 60000`.

**User Management State** — Create `useUserList()` hook that fetches from GET /api/admin/users/list with support for: pagination (page, limit), sorting (sortBy, sortOrder), filtering (role, status, dateRange, lastLoginRange), and search (email, userId). Cache for 30 seconds. Return { data (users array), total, page, limit, isLoading, error, refetch }. Create `useUserDetails(userId)` hook that fetches from GET /api/admin/users/:userId/details. Cache for 30 seconds. Create `useSuspendUser()` mutation hook that calls POST /api/admin/users/:userId/suspend with reason. On success, invalidate the user list and user details queries so they refetch. Create `useUnsuspendUser()` mutation hook similarly. Create `useResetPassword(userId)` mutation. Create `useBulkSuspendUsers()` mutation for bulk operations. Create `useExportUsers()` hook that calls GET /api/admin/users/export and triggers a CSV download.

**Event Moderation State** — Create `useEventList()` hook that fetches from GET /api/admin/events/list with support for: pagination, sorting, filtering (status, organizer, dateRange, revenueRange, flagged), and search (title, organizer). Cache for 30 seconds. Create `useEventDetails(eventId)` hook that fetches from GET /api/admin/events/:eventId/details. Create mutation hooks: `useApproveEvent()`, `useFlagEvent()`, `useCancelEvent()`, `useBulkFlagEvents()`. On success, invalidate event list and details queries. Create `useExportEvents()` hook for CSV export.

**Payment Reconciliation State** — Create `usePaymentList()` hook that fetches from GET /api/admin/payments/list with support for: pagination, sorting, filtering (status, method, dateRange, amountRange, fraudRisk), and search (paymentId, orderId, email). Cache for 30 seconds. Create `usePaymentDetails(paymentId)` hook that fetches from GET /api/admin/payments/:paymentId/details. Create mutation hooks: `useRefundPayment()`, `useDisputePayment()`. Create `usePaymentReconciliationReport()` hook that fetches from GET /api/admin/payments/reconciliation-report with date range support. Create `useExportPayments()` hook for CSV export.

**Local UI State** — For each page, use React's `useState` to manage: selected filters, search query, sort column/order, expanded rows, pagination state (current page). Use `useCallback` to memoize filter/sort change handlers so they don't cause unnecessary re-renders.

**Error Handling in State** — All hooks should handle 401 (redirect to login), 403 (show 'Access Denied'), and 500 (show error banner with retry). Use TanStack Query's `onError` callback to handle these globally or per-hook.

**Pagination Strategy** — Use cursor-based pagination where the backend supports it (for dashboard activity feed). For table pages, use offset-based pagination (page/limit) since admins often need to jump to specific pages.
