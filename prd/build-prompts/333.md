Let's add tests to make sure the ticket tier feature works correctly and doesn't break.

Unit tests:
- Validation logic: Test that price validation rejects negative values, quantity validation rejects zero, early bird price validation rejects values >= regular price, date validation rejects end dates before start dates, max per customer validation rejects zero.
- State management (useTicketTiers hook): Test that addTier() adds a blank tier, updateTier() updates the correct tier, removeTier() removes the correct tier, saveTiers() sends the correct payload, resetTiers() discards unsaved changes.
- Error mapping: Test that API error codes (400, 401, 403, 404, 500) map to the correct user-friendly messages.

Component tests:
- TicketTierForm: Test that all fields render, that validation errors display, that the form disables while saving, that the success message appears after saving.
- TicketTierList: Test that tiers render with correct data, that clicking a tier opens it for editing, that the remove button works.
- EventTicketTiersPage: Test that the page loads existing tiers, that unsaved changes trigger a confirmation dialog, that navigating away works correctly.

Integration tests:
- Full user flow: Load an event → navigate to ticket tiers → add a new tier with all fields → edit an existing tier → remove a tier → save → see success message → refresh → verify changes persisted.
- Error flow: Try to save with invalid data → see validation error → fix it → save → success.
- Auth flow: Try to access ticket tiers while logged out → redirected to login. Try to edit another organizer's event → 403 error.

API tests:
- PATCH /api/organizer/events/:eventId with valid tier data → 200 response, tiers saved.
- PATCH with invalid tier data → 400 response with validation errors.
- PATCH without auth → 401 response.
- PATCH for another organizer's event → 403 response.
- PATCH for non-existent event → 404 response.
