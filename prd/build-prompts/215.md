We're building a developer portal for organizers to manage API access and third-party integrations. This is a power-user feature that requires authentication and the 'organizer' role.

Build DeveloperPortalPage at /developer. This page has a tabbed interface with four tabs: 'API Keys', 'Webhooks', 'API Logs', and 'Documentation'. The page should check that the user is authenticated and has the organizer role — if not, show an 'Access Denied' page. If there's a 401 error, redirect to the login modal.

API Keys tab: Show a table of the user's API keys fetched from GET /api/developer/api-keys. Each row displays the key name, prefix (never the full key), scopes, and when it was last used. Include an action button to revoke the key. Add a 'Create New Key' button that opens a modal. In the modal, let the user enter a name and select scopes (checkboxes for 'events:read', 'orders:read', etc.). When they submit, call POST /api/developer/api-keys. If successful, show a modal with the full key displayed once with a 'Copy to Clipboard' button and a warning that they won't see it again. After they close this modal, refresh the keys table.

Webhooks tab: Show a table of webhook configurations fetched from GET /api/developer/webhooks. Each row shows the webhook URL, subscribed events (as a comma-separated list or badge group), status (active/inactive), and failure count. Include edit and delete actions. Add a 'Register Webhook' button that opens a modal with fields for URL and event selection (checkboxes for 'order.created', 'ticket.checked_in', etc.). Include a 'Send Test' button that sends a sample payload to the webhook URL. When they submit, call POST /api/developer/webhooks. After success, refresh the webhooks table.

API Logs tab: Show a reverse-chronological table of recent API calls fetched from GET /api/developer/api-logs. Each row displays the API path, HTTP method, status code, IP address, and timestamp. Make this read-only — no actions needed.

Documentation tab: Show an overview of the API and links to external documentation. This is static content, no API calls needed.

For all tabs, implement loading states with skeleton tables (3-5 shimmer rows). Implement empty states with illustrations and CTAs like 'Create Your First API Key'. Handle errors: show a global error banner with a retry button for 500 errors. Use inline form validation for all inputs (URL format for webhooks, required fields, etc.).

Make the layout responsive. On mobile, collapse the tabs into a dropdown menu. Use a consistent table component across all tabs with inline actions.
