We need to make sure errors are handled well and don't break the user experience. Auth errors should be clear, helpful, and never expose sensitive information.

On LoginPage, handle these errors distinctly:
- Invalid credentials (401): Show 'Invalid email or password' below the password field. Don't distinguish between 'user not found' and 'wrong password' — this prevents email enumeration.
- Rate limit (429): Show a toast 'Too many attempts, try again in X minutes'. Extract the retry-after time from the response header if available.
- Network error: Show a dismissible toast with 'Connection failed. Retry?' and a retry button that re-submits the form.
- Validation error (400): Show inline errors below each field (email format, password required).

On RegisterPage, handle:
- Duplicate email (409): Show 'This email is already registered' below the email field with a 'Sign In' link.
- Validation errors (400): Show inline errors (name too short, email format, password too short, passwords don't match).
- Network error: Show dismissible toast with retry.
- Rate limit (429): Show toast 'Too many registration attempts. Please try again later.'

On ForgotPasswordPage, handle:
- Rate limit (429): Show 'Too many requests. Please try again later.' as an inline message below the form.
- Invalid email format (400): Show inline validation error.
- Network error: Show dismissible toast with retry.
- Always show success message regardless of whether email exists (prevents enumeration).

On ResetPasswordPage, handle:
- Invalid or expired token (400): Show 'This link has expired or is invalid' with a 'Request new link' button that routes to /forgot-password.
- Token already used (400): Show 'This link has already been used. Request a new one.' with 'Request new link' button.
- Validation errors (400): Show inline errors (password too short, passwords don't match).
- Network error during token validation: Show 'Unable to validate link. Check your connection and try again.' with retry button.
- Network error during password reset: Show dismissible toast with retry.

Global error handling: If any API request returns 401 (unauthorized/token expired), automatically log the user out, clear the token, and redirect to /login. Show a brief toast 'Your session expired. Please log in again.'

For all network errors, provide a clear message and a retry option. Don't show raw error codes or stack traces. Use toast notifications for temporary errors (network, rate limit) and inline messages for validation errors.

Error message tone: Be friendly and helpful, not technical. Say 'Check your connection' not 'Network timeout'. Say 'Password too short' not 'Validation failed: password.length < 8'.

Loading and error states: While a request is in progress, disable form fields and show a spinner in the submit button. If an error occurs, re-enable the fields so the user can retry. Don't clear the form on error — let the user see what they entered and fix it.
