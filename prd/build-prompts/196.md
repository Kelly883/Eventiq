We're building a ticket inventory management system for event organizers. For this step, I need you to build two pages: TicketInventoryDashboardPage and AdjustInventoryModal.

TicketInventoryDashboardPage at /organizer/events/:eventId/inventory — This is the main dashboard where organizers see real-time ticket inventory across all tiers and pricing windows for a single event. Start with a summary section at the top showing four key metrics in cards: total capacity, tickets sold, tickets remaining, and a count of low-stock alerts. Below that, build a data table with sortable columns: tier name, base price, quantity limit, sold count, available count, and utilization percentage (as a color-coded bar — green for healthy, amber for low, red for critical). Each tier row should be expandable to show all active and upcoming pricing windows nested underneath with their own quantity limits and quantities sold. Add a sticky header with a filter bar that lets organizers filter by tier and status. Include a sort dropdown to reorder by allocated, sold, or available. Add an 'Adjust Inventory' button that opens the adjustment modal. Include an 'Export' button that downloads the inventory report as CSV. Show inline low-stock alerts with color-coded urgency. Handle loading state with skeleton cards and shimmer placeholders. Show empty state if no tiers exist with a link to the pricing page. For mobile, stack the summary cards vertically and collapse the tier sections into accordion-style cards instead of a table.

AdjustInventoryModal — This is a modal dialog triggered from the dashboard via the 'Adjust Inventory' button. It should display a dropdown to select which tier or pricing window to adjust, a numeric input field for the new quantity (with increment/decrement buttons), and an optional reason textarea for the audit trail. Show the current quantity and proposed new quantity side-by-side in cards so organizers can see the change clearly. The 'Apply' button should submit the change and show a success toast, then refresh the dashboard. The 'Cancel' button closes without changes. Disable the Apply button until the quantity is actually changed. Validate that the new quantity doesn't exceed event capacity — if it does, show a red error message 'Quantity exceeds event capacity by X tickets'. Handle loading state with a spinner in the submit button. Show validation errors inline with red highlighting. On success, close the modal and refresh the inventory data. Handle errors: 401 redirects to login, 403 shows 'Access Denied', 500 shows an error message with a retry button.

Both pages should call the backend endpoints: GET /api/organizer/events/:eventId/inventory/summary for the summary cards, GET /api/organizer/events/:eventId/inventory for the detailed tier and pricing window data, PATCH /api/organizer/events/:eventId/inventory/adjust for submitting inventory changes, and GET /api/organizer/events/:eventId/inventory/export for the CSV export. Use React Router for navigation, useState for local form state in the modal, useEffect for data fetching, and TanStack Query for server state management and caching.
