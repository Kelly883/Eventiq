We need state management to handle dashboard data fetching, caching, and user preferences without cluttering the pages with logic.

First, set up TanStack Query hooks for data fetching. Create a custom hook useOrganizerDashboardOverview() that calls GET /api/organizer/dashboard/overview with optional dateRange and eventFilter query params. It should return { totalRevenue, totalTicketsSold, averageConversionRate, upcomingEventCount, totalEventCount, revenueTrend, ticketsTrend, conversionTrend, lastUpdatedAt, isLoading, error }. Cache this for 30 seconds and allow manual refetch.

Create useOrganizerDashboardEvents() that calls GET /api/organizer/dashboard/events with optional status, limit, offset, and sortBy params. Return { events, total, limit, offset, isLoading, error }. Support pagination by accepting limit and offset as parameters.

Create useEventDetails(eventId) that calls GET /api/organizer/dashboard/events/:eventId. Return { eventId, title, date, status, totalRevenue, totalTicketsSold, conversionRate, tiers, pricingWindows, isLoading, error }.

Create useActivityFeed() that calls GET /api/organizer/dashboard/activity-feed with optional limit, offset, eventFilter, tierFilter, startDate, endDate params. Return { activities, total, limit, offset, isLoading, error }. This should refetch every 30 seconds when auto-refresh is enabled.

Next, set up Zustand for UI state and preferences. Create a store called useDashboardStore that manages: selectedEventId (which event detail widget is expanded), eventFilter (all/upcoming/past/draft), dateRange (7days/30days/90days/all), showActivityFeed (boolean), autoRefreshEnabled (boolean), and expandedSections (which collapsible sections are open). Export actions: setSelectedEventId(), setEventFilter(), setDateRange(), toggleActivityFeed(), toggleAutoRefresh(), toggleSection(). Persist this store to localStorage so preferences survive page reloads.

Create another hook useDashboardPreferences() that calls GET /api/organizer/dashboard/preferences on mount and syncs the response into the Zustand store. This ensures server-side preferences are loaded. Also create a useSaveDashboardPreferences() hook that calls PATCH /api/organizer/dashboard/preferences whenever the Zustand store changes, debounced by 1 second to avoid spamming the server.

For the activity feed auto-refresh, create a custom hook useAutoRefreshActivityFeed() that uses setInterval to refetch the activity feed every 30 seconds, but only if autoRefreshEnabled is true. Clean up the interval on unmount.

Keep all business logic out of the pages — pages should just call these hooks and render based on the returned state.
