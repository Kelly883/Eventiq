We need five API endpoints that power the dashboard and ticket management system. Here's what each one does:

1. GET /api/my-tickets — Returns paginated list of user's tickets grouped by event. Accepts query params: filter (all/upcoming/past), dateRange (7days/30days/90days/all), search (event title or ticket ID), page, limit. Verify auth token, extract userId, query tickets filtered by userId, apply filters, eager load events/tiers/orders/delivery_events, sort by event date descending, paginate with limit/offset. Return { tickets: [...], total, page, limit }. Rate limit 20/min per user.

2. GET /api/users/me/dashboard-overview — Returns dashboard summary metrics and recent activity. No query params. Verify auth, calculate: totalTickets (count), upcomingEventsCount, pastEventsCount, totalSpent (sum), nextUpcomingEvent (first upcoming), recentActivity (last 5 purchases). Eager load relationships. Return { totalTickets, upcomingEventsCount, pastEventsCount, totalSpent, nextUpcomingEvent, recentActivity }. Rate limit 20/min per user.

3. GET /api/users/me/dashboard-preferences — Returns user's dashboard preferences. Verify auth, query user_dashboard_preferences by userId. If not found, return defaults. Return { defaultTicketFilter, defaultDateRange, showRecommendations, showActivityFeed, autoRefreshEnabled }. Rate limit 20/min per user.

4. PATCH /api/users/me/dashboard-preferences — Updates user's dashboard preferences. Verify auth, validate input (filter must be all/upcoming/past, dateRange must be 7days/30days/90days/all), query or create preferences, update provided fields, return updated preferences. Rate limit 10/min per user.

5. GET /api/tickets/:ticketId/details — Returns comprehensive details for a single ticket. Verify auth, query ticket by ticketId, check user owns it via Policy, eager load events/tiers/orders, query delivery_events for history, query related tickets from same order. Return { id, eventId, eventTitle, eventDate, eventVenue, eventOrganizer, tierId, tierName, status, purchaseDate, orderId, qrCodeData, ticketPdfUrl, deliveryStatus, deliveryMethod, deliveryTimestamp, deliveryHistory, relatedTickets }. Rate limit 20/min per user.

All endpoints require bearer token authentication. Use Laravel Policies to enforce that users can only access their own data. Return 401 for missing/invalid tokens, 403 for unauthorized access, 404 for not found, 400 for validation errors.
