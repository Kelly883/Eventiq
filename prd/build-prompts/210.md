We're building a revenue settlement and payouts system. For this step, I need you to build two dashboard pages that let organizers and admins track payouts and settlements.

OrganizerPayoutDashboardPage at /organizer/payouts — This is the organizer-facing payout dashboard. Start with four summary metric cards at the top showing: total revenue (all-time), pending payout amount, last payout date, and next scheduled payout date. Each card should have a color-coded trend indicator (green arrow for up, red arrow for down). Below that, build an interactive data table listing all payouts with columns: payout ID, settlement period (date range), gross revenue, platform commission (%), processing fees, refunds deducted, net payout amount, status (with color-coded badges: amber for pending, blue for processing, green for completed, red for failed), and action buttons. Make the table sortable by clicking column headers. Add a sticky filter bar above the table with filters for date range, status, and payout period. When a user clicks a row, expand it inline to show the full breakdown: ticket sales by tier, refunds applied, commission calculation details, tax withholding if applicable, and payment method used. Include a 'Download Statement' button that exports the payout history as a PDF. For failed payouts, show a retry button and the error reason. Display the current payout method (ACH, wire transfer, etc.) with the last 4 digits of the bank account masked for privacy. On mobile, stack the metric cards vertically and replace the table with collapsible cards. Real-time updates should refresh the pending payout calculations every 60 seconds without a full page reload.

AdminSettlementDashboardPage at /admin/settlements/dashboard — This is the admin-only settlement management dashboard. Start with four summary metric cards showing: total platform revenue (last 24 hours), total pending payouts across all organizers, settlement success rate (%), and average payout processing time in hours. Each card has color-coded trend indicators. Below that, build an interactive table listing all pending settlements with columns: organizer name, event count, gross revenue, platform commission collected, refunds applied, net payout amount, status (with color-coded badges: amber for pending, blue for calculated, green for approved, purple for processing, gray for completed, red for failed), and action buttons. Add bulk action checkboxes on the left of each row so admins can approve or reject multiple settlements at once. Make the table sortable. Add a sticky filter bar with filters for organizer name, status, date range, and revenue range. Include a search field to find settlements by organizer name or event ID. When a user clicks a row, expand it inline to show the full settlement breakdown: individual event revenues, commission calculation by tier, tax withholding details, and payment method. Include an 'Export Settlement Report' button that exports as CSV. Add a chart showing the settlement method breakdown (percentage of payouts by method: ACH, wire, etc.). Include a 'Manual Payout Trigger' button for urgent settlements that requires admin approval. On mobile, stack the metric cards and replace the table with collapsible cards. Real-time updates should refresh every 30 seconds.

For both pages, handle loading states by showing skeleton metric cards and placeholder table rows with shimmer effects. For empty states: organizer page shows 'No payouts yet' with an illustration and explanation of the payout schedule; admin page shows 'All settlements processed' with an illustration. Handle error states: 401 redirects to login with a 'Session expired' toast, 403 shows 'Access Denied' with a back button, 500 shows an error banner with a retry button. Both pages should call GET /api/organizer/payouts/list and GET /api/admin/settlements/list respectively to load data. Use React Router for navigation, TanStack Query for data fetching and caching, and recharts for the settlement method breakdown chart.
