Now we need to connect the event discovery pages to the rest of the app so users can actually reach them.

Add routes for: /events (EventBrowsePage), /events/:eventId (EventDetailPage), and /events/category/:categoryId (CategoryBrowsePage). Make sure the :eventId route is defined before the /category/:categoryId route so the router doesn't confuse 'category' with an event ID.

On the existing home page or main navigation, add a link or button to 'Browse Events' that routes to /events. If the app has a bottom navigation bar or header menu, add an 'Events' or 'Discover' tab.

Wire up these connections:
- When a user clicks an event card on EventBrowsePage, navigate to /events/:eventId
- When a user clicks a category filter chip or the category link, navigate to /events/category/:categoryId
- When a user clicks 'Browse all categories' on CategoryBrowsePage, navigate back to /events
- When a user clicks 'Browse all events' from an empty state, navigate to /events with filters cleared
- When a user clicks a related event on EventDetailPage, navigate to that event's detail page (/events/:relatedEventId)
- The back button should work naturally (browser back or React Router's useNavigate)
- Deep links to /events/:eventId should work from push notifications or shared links — if the user isn't logged in, they can still view the event (it's a public page)
- The 'Create Event' button on EventBrowsePage should only show for authenticated organizers and route to /organizer/events/create (or wherever the organizer dashboard is)
- The 'Buy Tickets' button on EventDetailPage should open a checkout flow (route to /checkout/:eventId or open a modal, depending on your checkout implementation)
- The 'Add to Wishlist' button should only show for authenticated users and should toggle wishlist state in the Zustand store
