We need to build six API endpoints for the QR code ticketing system. Here's what each one does:

1. POST /api/tickets/generate-qr — Ticket owners generate a QR code for their ticket. Takes ticketId in the request body. Verify the user owns the ticket via Policy. Generate a random 32-byte secret, create an encrypted JSON payload with {ticketId, eventId, userId, email, tier, expiresAt}, encode as base64, hash the secret with bcrypt (cost 12), generate a QR code image using the qrcode library, upload to storage at qr-codes/{ticketId}.png, and update the ticket record with qrCodeData, qrCodeSecret, qrCodeGeneratedAt, qrCodeExpiresAt. Return the QR code URL, encrypted payload, and expiry timestamp. Rate limit 10/min per user.

2. POST /api/tickets/verify-qr — Venue staff verify a scanned QR code. Takes qrCodeData (encrypted payload) and optional venueId. Check user has 'VenueStaff' or 'Organizer' role. Decrypt the payload server-side using AES-256, extract ticket details, validate expiry, check ticket status (not void, not already checked-in), check fraud_events table for fraud flags, verify event exists and hasn't passed. Increment qrCodeScannedCount and update lastQrScanAt. Return ticket details with status. Rate limit 60/min per user.

3. POST /api/tickets/:ticketId/check-in — Venue staff mark a ticket as checked in. Takes ticketId in URL and qrCodeData in body. Check user has 'VenueStaff' or 'Organizer' role. Call verify-qr logic to validate. Update ticket: status='checked_in', checkedInAt=NOW, checkedInBy=userId. Create auditLog entry. Decrement ticket_inventory.totalAvailable and increment analytics_events_metrics.totalTicketsSold. Return success with check-in confirmation. Rate limit 60/min per user. Make it idempotent — checking in the same ticket twice returns success but doesn't double-count.

4. POST /api/tickets/:ticketId/void — Organizers/Admins void a fraudulent or cancelled ticket. Takes ticketId in URL and {reason, optional fraudEventId} in body. Check user has 'Organizer' or 'Admin' role. Verify ticket belongs to organizer's event (if organizer). Update ticket: status='void', voidedAt=NOW, voidedBy=userId, voidReason=reason. Create auditLog entry. If fraudEventId provided, update fraud_events record. Increment ticket_inventory.totalAvailable (restore capacity). Create delivery_event with status='blocked'. Return success. Rate limit 10/min per user.

5. GET /api/venue/check-in/sync — Venue staff sync recent check-ins for offline mode. Takes eventId (required) and optional lastSyncAt query params. Check user has 'VenueStaff' or 'Organizer' role. Verify user is authorized for this event. Query tickets filtered by eventId, status='checked_in', checkedInAt > lastSyncAt (if provided). Eager load event and checkedInBy user details. Return paginated list of check-ins with real-time counters: totalCapacity, totalCheckedIn, remainingCapacity. Rate limit 30/min per user.

6. GET /api/organizer/events/:eventId/check-in-analytics — Organizers view check-in analytics. Takes eventId in URL and optional startDate/endDate query params. Check user owns event via Policy. Query tickets filtered by eventId, status='checked_in'. If date range provided, filter by checkedInAt. Calculate metrics: totalCheckedIn (count), checkInRate (percentage), peakCheckInHour (0-23), averageCheckInTime (minutes from event start). Group check-ins by hour for timeline and by tier for breakdown. Return analytics summary with chart data. Rate limit 20/min per user.

All endpoints require authentication (bearer token). All verification attempts and check-ins are logged to auditLogs with staff ID, ticket ID, and result. Decryption happens server-side only.
