We need to make sure only authorized organizers can view and modify inventory, and that all changes are logged.

All five endpoints (GET /api/organizer/events/:eventId/inventory/summary, GET /api/organizer/events/:eventId/inventory, PATCH /api/organizer/events/:eventId/inventory/adjust, GET /api/organizer/events/:eventId/inventory/export, GET /api/organizer/events/:eventId/inventory/audit-log) must:

1. Require authentication — Check for a valid bearer token in the Authorization header. Reject with 401 if missing or invalid.

2. Enforce event ownership — Use Laravel Policy to verify that the authenticated user owns the event. Reject with 403 if they don't. This prevents one organizer from viewing another's inventory.

3. Validate input server-side — For the adjust endpoint, validate that newQuantity is >= 0 and doesn't exceed event capacity. Validate that tierIdOrWindowId is a valid UUID and exists. Validate that reason (if provided) is max 500 characters. Reject with 400 if validation fails.

4. Rate limit to prevent abuse:
   - GET endpoints (summary, inventory, export, audit-log): 20 requests/min per user
   - PATCH adjust endpoint: 5 adjustments/min per user
   - Use Laravel's rate limiting middleware

5. Log all inventory changes — Every PATCH /api/organizer/events/:eventId/inventory/adjust must create an entry in the inventory_adjustments table with: eventId, ticketTierId, pricingWindowId (if applicable), organizerId, adjustmentType, quantityBefore, quantityAfter, quantityDelta, reason, and createdAt timestamp. This audit trail is immutable and helps track who changed what and when.

6. Prevent overselling — When adjusting inventory, use database transactions to ensure atomicity. Check that the new quantity doesn't exceed event capacity. If a pricing window adjustment would exceed the tier's total allocation, reject with 409 (conflict).

7. Protect sensitive data — The Algolia key (if used elsewhere) should never appear in API responses. Only return inventory data for the requested event.

8. CORS — If the frontend is on a different domain, configure CORS to only allow requests from your frontend domain.
