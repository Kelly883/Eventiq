We need to make sure errors don't break the user experience and are communicated clearly.

OfflineSyncSettingsPage:
- Toggle offline_enabled fails → show a friendly error notification ('Failed to update device settings. Please try again.') and revert the toggle to its previous state. Don't leave the toggle in an inconsistent state.
- 'Sync Now' fails due to network error → show 'Check your connection and try again.' Keep the last successful sync timestamp visible so the user knows when data was last synced.
- 'Sync Now' fails due to auth error (401) → redirect to login.
- 'Sync Now' fails due to rate limit (429) → show 'You're syncing too frequently. Please wait a few minutes and try again.'
- 'Sync Now' fails due to server error (500) → show 'Something went wrong. Please try again later.' and include a 'Contact Support' link.

OfflineTicketsPage:
- Page loads but cached data is missing or corrupted → show 'No offline tickets available. Please sync first.' with a link to OfflineSyncSettingsPage.
- Page loads but cached data is very stale (older than 7 days) → show a warning banner 'This data is outdated. Sync for the latest tickets.' with a 'Sync Now' button.
- User is offline and tries to tap 'Refresh' → show 'You're offline. Go online to refresh tickets.' (the button should be disabled anyway, but handle the case gracefully).

General:
- If localStorage quota is exceeded when trying to save cached tickets → show 'Not enough storage to cache tickets. Please clear some data.' and offer to clear old cached data.
- If the app detects corrupted data in localStorage → clear it silently and show 'Offline data was corrupted and has been cleared. Please sync again.'
- All error messages should be in plain language, not technical jargon. Users should understand what went wrong and what to do about it.
- Errors should be dismissible (user can tap to close) and shouldn't block the UI.

Implement retry logic:
- For network errors, offer a 'Retry' button so the user can try again without navigating away.
- For transient errors (rate limit, temporary server error), implement exponential backoff — wait a bit before retrying automatically.
- For permanent errors (auth failure, validation error), don't retry automatically — let the user fix the issue and retry manually.
