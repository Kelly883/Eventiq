We need to define the AuditLog data model on both backend and frontend so they can work with audit log data consistently.

On the backend (Laravel), create app/Features/Compliance/Models/AuditLog.php. This Eloquent model should:
- Extend Model and use SoftDeletes
- Define the table as 'audit_logs'
- Cast fields: action, target_type, status, compliance_classification as enums (use Laravel's native Enum support)
- Cast JSON fields: geolocation, request_data, response_data, changed_fields, metadata as arrays
- Define a relationship to the User model via user_id
- Add a scope method `forDateRange($startDate, $endDate)` to filter by created_at
- Add a scope method `byAction($action)` to filter by action type
- Add a scope method `byTargetType($targetType)` to filter by target type
- Add a scope method `byStatus($status)` to filter by status
- Add a scope method `byClassification($classification)` to filter by compliance classification

- Mark created_at and user_id as immutable using `$guarded` or `$fillable`

On the frontend (React), create src/features/compliance/types/audit.ts with TypeScript interfaces:
