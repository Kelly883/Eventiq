We need to make sure things fail gracefully when something goes wrong.

AccessibilitySettingsPage:
- Network failure on initial load (GET /api/users/me/accessibility-preferences) → show a full-screen error with 'Retry' button (the page has no content yet)
- Network failure while saving a setting (PATCH /api/users/me/accessibility-preferences/update) → show a brief notification 'Failed to save setting' with a 'Retry' option. Keep the setting in the UI (optimistic update) but mark it as pending until the save succeeds
- Validation error (fontSize out of range, etc.) → show a notification explaining the valid range and revert the setting to its previous value
- 401 (unauthenticated) → show a toast 'Sign in to customize accessibility' and redirect to login
- 403 (permission denied) → show a notification 'Access Denied'
- 429 (rate limited) → show a notification 'Too many changes, please wait a moment'
- 500 (server error) → show an error banner with a 'Retry' button

LanguagePreferencePage:
- Network failure on initial load (GET /api/users/me/language-preferences) → show a full-screen error with 'Retry' button
- Network failure while saving language preference (PATCH /api/users/me/language-preferences/update) → show a notification 'Failed to save language' with 'Retry'. Keep the language selection in the UI but mark as pending
- Unsupported language code → show a notification 'Language not supported' and revert to previous language
- Invalid dateFormat or timeFormat → show a notification explaining valid options and revert to previous value
- 401 (unauthenticated) → show a toast 'Sign in to change language' and redirect to login
- 403 (permission denied) → show a notification 'Access Denied'
- 429 (rate limited) → show a notification 'Too many language changes, please wait'
- 500 (server error) → show an error banner with 'Retry' button
- Language switch loading state → show a brief loading spinner while i18next switches namespaces, then immediate UI update

DeviceLocalizationSyncPage:
- Network failure on initial load (GET /api/users/me/devices) → show a full-screen error with 'Retry' button
- Network failure while syncing (POST /api/users/me/devices/sync-all or PATCH /api/users/me/devices/:deviceId/localization-settings/update) → show a notification 'Sync failed' with 'Retry'. Keep the device card in a syncing state but show the error
- Device not found (404) → remove the device from the list and show a notification 'Device was removed'
- 401 (unauthenticated) → show a toast 'Sign in to manage devices' and redirect to login
- 403 (permission denied) → show a notification 'Access Denied'
- 429 (rate limited) → show a notification 'Too many sync operations, please wait'
- 500 (server error) → show an error banner with 'Retry' button
- Offline device → show 'Pending sync' badge with estimated sync time. When device comes online, automatically retry sync

Global error handling:
- If the user's login session expires (401 on any endpoint), redirect to login page, then back to the settings page they were on
- If the backend is down (500), show a banner 'Service temporarily unavailable' and offer to retry
- Network timeouts → show 'Connection timeout, please check your internet' and offer retry
- All error messages should be clear and actionable (not technical jargon)

Optimistic updates — For better UX, update the UI immediately when the user changes a setting, then sync to the backend. If the backend save fails, revert the UI change and show an error with retry option.
