We need to define the data models on both backend and frontend.

On the backend (Laravel), create Eloquent models:

1. ApiKey model at app/Models/ApiKey.php — Represents an API key. Define relationships: belongsTo(User), hasMany(AuditLog). Add accessors/mutators as needed. Add a static method generateKey() that creates a random 32-character key. Add a method checkKey($rawKey) that uses Hash::check() to verify a raw key against the hashed_key. Add scopes like scopeForOrganizer($query, $organizerId) and scopeActive($query) to filter by organizer and exclude revoked/expired keys.

2. Webhook model at app/Models/Webhook.php — Represents a webhook endpoint. Define relationships: belongsTo(User), hasMany(WebhookDeliveryLog). Add a static method generateSecret() that creates a random secret for HMAC signing. Add scopes like scopeForOrganizer($query, $organizerId) and scopeActive($query).

3. WebhookDeliveryLog model at app/Models/WebhookDeliveryLog.php — Represents a single webhook delivery attempt. Define relationships: belongsTo(Webhook). This is mostly read-only for auditing.

4. AuditLog model at app/Models/AuditLog.php (if it doesn't exist) — Represents an audit trail entry. Fields: id, user_id, action (string), resource_type (string), resource_id (string), changes (json), ip_address (string), created_at. Used for logging API key creation, revocation, webhook changes, etc.
