We need to define the data models on both backend and frontend so we can work with refund data consistently.

On the backend (Laravel), create three Eloquent models:

1. RefundRequest model (app/Models/RefundRequest.php):
- Extend Illuminate\Database\Eloquent\Model
- Define relationships: belongsTo(User), belongsTo(Ticket), belongsTo(Order), belongsTo(Event), belongsTo(RefundPolicy via eventId), hasMany(RefundAppeal)
- Add accessor methods: getFormattedAmountAttribute() returns '$XX.XX', getStatusBadgeColorAttribute() returns 'amber'|'green'|'red'|'blue'|'gray' based on status, getIsEligibleForAppealAttribute() returns true if status='rejected' and appealCount < 3
- Add scope methods: scopeForUser($query, $userId) filters by user_id, scopeByStatus($query, $status) filters by status, scopeByEvent($query, $eventId) filters by event_id
- Cast fields: original_amount and refund_amount as decimal(10,2), appeal_count as integer, payment_gateway_response as json, approved_at/processing_started_at/completed_at/last_appeal_at as datetime

2. RefundPolicy model (app/Models/RefundPolicy.php):
- Extend Illuminate\Database\Eloquent\Model
- Define relationships: belongsTo(Event), belongsTo(Organizer), hasMany(RefundRequest via eventId)
- Add accessor: getFormattedWindowAttribute() returns 'Refunds allowed within 14 days'
- Add scope: scopeActive($query) filters where is_active=true
- Cast fields: allowed_refund_methods and refund_reasons as json, refund_percentage_before_event and refund_percentage_after_event_start as decimal(5,2), auto_approve_threshold as decimal(10,2)

3. RefundAppeal model (app/Models/RefundAppeal.php):
- Extend Illuminate\Database\Eloquent\Model
- Define relationships: belongsTo(RefundRequest), belongsTo(User), belongsTo(User, 'reviewed_by')
- Add scope: scopeForUser($query, $userId) filters by user_id, scopePending($query) filters where status='pending'
- Cast fields: reviewed_at as datetime
