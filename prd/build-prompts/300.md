We need to make sure things fail gracefully when something goes wrong, so organizers aren't left confused.

TicketInventoryDashboardPage:
- Network failure on initial load → show a full-screen error banner with a 'Retry' button (not a small notification — the page has no content yet)
- Failure while loading more data (pagination) → show a brief toast notification but keep the data that already loaded
- Filter or sort change fails → show a toast notification and revert to the previous filter/sort selection
- Export fails → show a toast saying 'Export failed' with a retry option

AdjustInventoryModal:
- Validation error (negative quantity, exceeds capacity) → highlight the input field in red and show the error message below it (e.g., 'Quantity exceeds event capacity by 50 tickets')
- Network error on submit → show an error message in the modal with a 'Retry' button
- 404 (tier/window not found) → show 'Tier not found' and close the modal
- 409 (conflict - adjustment would cause overselling) → show 'This adjustment would exceed the tier's allocation' and don't close the modal
- 429 (rate limited) → show 'Too many adjustments. Please wait a moment and try again'
- 500 (server error) → show 'Something went wrong' with a retry button

All pages:
- 401 (session expired) → show a toast saying 'Session expired' and redirect to login page
- 403 (access denied) → show a full-screen error saying 'Access Denied — only event organizers can manage inventory' with a back button
- 404 (event not found) → show 'Event not found' with a link back to the events list
- 500 (server error) → show an error banner with a 'Retry' button

For all errors, log them to the browser console (in development) so you can debug. In production, consider sending errors to an error tracking service like Sentry.

Make sure error messages are clear and actionable — don't show technical jargon or error codes. Tell the organizer what went wrong and what to do next.
