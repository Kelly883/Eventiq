We need to set up the routing for the four auth pages and create guards to protect routes based on authentication status.

In src/router.tsx (or wherever your routes are defined), add these routes:
- /login → LoginPage
- /register → RegisterPage
- /forgot-password → ForgotPasswordPage
- /reset-password → ResetPasswordPage (with query parameter ?token=...)

Create a ProtectedRoute component that checks if the user is authenticated. If authenticated, render the requested page. If not authenticated, redirect to /login. This will be used for pages that require login (like /dashboard).

Create a PublicRoute component that checks if the user is authenticated. If authenticated, redirect to /dashboard. If not authenticated, render the requested page. This prevents logged-in users from accessing the login/register pages (they should go straight to the dashboard).

In src/features/auth/context/AuthContext.tsx, create an AuthContext that provides:
- isAuthenticated (boolean)
- user (User | null)
- token (string | null)
- login (email, password) → calls POST /api/auth/login
- register (email, password, name) → calls POST /api/auth/register
- logout () → clears token and user from localStorage
- forgotPassword (email) → calls POST /api/auth/forgot-password
- resetPassword (token, newPassword) → calls POST /api/auth/reset-password

Wrap the entire app with AuthProvider so all pages can access the auth context.

On app startup, check if there's a token in localStorage. If yes, verify it's still valid (you can do this by making a test API call or just trust the expiry time). If valid, restore the user session. If not valid or expired, clear localStorage and show the login page.

When a user logs in successfully, store the token in localStorage and set the auth context. When they log out, clear localStorage and redirect to /login. When they reset their password, invalidate all sessions (the backend does this), so they need to log in again.
