# Fraud Endpoint Velocity Check

POST /api/fraud/velocity-check

## Description

REQUEST: { userId: string, eventId: string, amount: decimal, paymentMethodId: string }
PROCESS: 1. Query orders by userId with createdAt in last 24 hours 2. Calculate velocity metrics: orders in 24h, total spend in 24h, average order value, orders in last hour 3. Query payments by paymentMethodId (card fingerprint) with createdAt in last 24 hours 4. Calculate payment method velocity: how many different users used this card in 24h, total spend on this card 5. Compare against thresholds: if orders_in_24h > 10 OR total_spend_in_24h > $5000 OR orders_in_1h > 3, flag as suspicious 6. If payment method used by 5+ different users in 24h, flag as card testing pattern 7. Create fraud_events record with velocityMetrics if flagged 8. Return velocity risk assessment
SUCCESS (200): { velocityRiskScore: number, riskLevel: string, velocityMetrics: {ordersIn24h, totalSpendIn24h, averageOrderValue, ordersInLastHour}, paymentMethodVelocity: {usersIn24h, totalSpendIn24h}, isSuspicious: boolean }
ERRORS: 400 (invalid input), 401 (unauthenticated), 404 (user not found), 500 (database error)
SECURITY: Auth required. Velocity checks run during checkout. All suspicious patterns logged. Rate limit 20/min per user.
