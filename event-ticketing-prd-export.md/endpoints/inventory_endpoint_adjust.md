# Inventory Endpoint Adjust

PATCH /api/organizer/events/:eventId/inventory/adjust

## Description

REQUEST: URL param eventId (UUID), body: { tierIdOrWindowId (string, required - either ticketTierId or pricingWindowId), newQuantity (integer, required, >= 0), reason (string, optional, max 500 chars) }
PROCESS: 1. Verify auth token and extract userId 2. Query events by eventId 3. Check user owns event via Policy 4. Validate input: newQuantity >= 0, newQuantity <= event.capacity 5. Determine if adjustment is for tier or window (check which ID is provided) 6. If tier: query ticket_inventory, validate new quantity doesn't exceed event capacity 7. If window: query pricing_windows, validate new quantity doesn't exceed tier's total allocation 8. Store old quantity in inventory_adjustments record 9. Update ticket_inventory or pricing_windows with new quantity 10. Recalculate ticket_inventory aggregates if window was adjusted 11. Create inventory_adjustments audit entry with organizerId, quantityBefore, quantityAfter, reason 12. Return updated inventory state
SUCCESS (200): { tierId, tierName, newQuantity, previousQuantity, quantityDelta, message: 'Inventory adjusted successfully' }
ERRORS: 400 (validation failed - negative quantity, exceeds capacity, invalid ID), 401 (unauthenticated), 403 (user doesn't own event), 404 (tier/window not found), 409 (conflict - adjustment would cause overselling), 429 (rate limited), 500 (database error)
SECURITY: Auth required. Event ownership enforced via Policy. Input validation server-side. Rate limit 5 adjustments/min per user to prevent abuse. All changes logged to inventory_adjustments with organizerId and timestamp.
