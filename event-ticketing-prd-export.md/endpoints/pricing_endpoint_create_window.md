# Pricing Endpoint Create Window

POST /api/organizer/events/:eventId/pricing/windows

## Description

REQUEST: URL param eventId (UUID), body: { ticketCategoryId (string, required), windowName (string, required, max 100), startDateTime (timestamp, required), endDateTime (timestamp, required), price (decimal, required, > 0), quantityLimit (integer, optional, > 0), priority (integer, optional, default 0) }
PROCESS: 1. Verify auth token 2. Query events by eventId 3. Check user owns event via Policy 4. Validate input: windowName not empty, startDateTime < endDateTime, endDateTime <= event.endDateTime, price > 0, quantityLimit > 0 if provided 5. Check for overlapping windows with same ticketCategoryId (if overlap, return 409) 6. Verify ticketCategoryId exists and belongs to this event 7. Create pricing_windows record with isActive computed, quantitySold=0 8. Return created window with 201 status
SUCCESS (201): { id, windowName, ticketCategoryId, startDateTime, endDateTime, price, quantityLimit, quantitySold, isActive, priority, createdAt }
ERRORS: 400 (validation failed - invalid dates, negative price, empty name), 401 (unauthenticated), 403 (user doesn't own event), 404 (event or ticket category not found), 409 (overlapping window exists), 429 (rate limited), 500 (database error)
SECURITY: Auth required. Event ownership enforced via Policy. Input validation server-side. Rate limit 10 creates/min per user to prevent abuse.
