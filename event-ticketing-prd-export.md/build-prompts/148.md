We need to build six API endpoints that handle fraud detection, transaction review, and admin dashboard queries. All endpoints require authentication and specific endpoints require admin role.

1. POST /api/checkout/create-payment-intent — Called during checkout to initialize fraud detection before payment. Request: cartItems (array of {ticketTierId, quantity, pricingWindowId}), userId, email, paymentMethodId (optional). Process: verify auth token, validate cart items via /api/cart/verify, calculate total amount, initialize FraudDetectionService with transaction data, call detectFraudRisk() to get risk score, if risk > 75 auto-block with 403 response, if risk 31-70 create payment intent with additional verification flag, create pending order record, log fraud event. Response: {clientSecret, paymentIntentId, orderId, fraudRiskScore, requiresAdditionalVerification}. Rate limit 10/min per user.

2. POST /api/webhooks/payment-provider — Webhook from Stripe/Paystack. Request: webhook payload with signature header. Process: verify signature using Stripe SDK, extract event type and payment intent ID, query fraud_events by orderId, if payment_intent.succeeded: check fraud_events.status (if auto_blocked void order, if flagged create with fraud_hold status, if approved proceed to completion), transactionally update order status, create tickets, decrement inventory, update analytics. Response: {received: true}. No rate limit (webhook).

3. POST /api/fraud/detect-duplicate-tickets — Detect duplicate ticket purchases. Request: {ticketTierId, eventId, qrCodeData, userId}. Process: query tickets by eventId and ticketTierId, search for matching QR codes, check if matches are from same user or different users, calculate duplicate risk score, flag if duplicate detected, create fraud_events record with duplicateTicketInfo. Response: {isDuplicate, matchingTickets, riskScore, riskLevel}. Rate limit 20/min per user.

4. POST /api/fraud/velocity-check — Check user purchase velocity. Request: {userId, eventId, amount, paymentMethodId}. Process: query orders by userId in last 24h, calculate velocity metrics (orders in 24h, total spend, average order value, orders in last hour), query payments by paymentMethodId in last 24h, calculate payment method velocity, compare against thresholds (>10 orders in 24h, >$5000 spend, >3 orders in 1h, 5+ users on same card = card testing), create fraud_events if flagged. Response: {velocityRiskScore, riskLevel, velocityMetrics, paymentMethodVelocity, isSuspicious}. Rate limit 20/min per user.

5. GET /api/admin/fraud/flagged-transactions — List flagged transactions for admin dashboard. Query params: page, limit (default 50), riskLevel (high|medium|low), status (flagged|reviewed|approved|rejected), startDate, endDate, sortBy (riskScore|createdAt), sortOrder (asc|desc). Process: verify admin role via Policy, query fraud_events with filters, eager load orders, users, payments, paginate, sort. Response: {transactions: [{id, orderId, userId, email, amount, riskScore, riskLevel, detectionMethod, fraudFactors, status, createdAt, reviewedBy, reviewedAt}], total, page, limit}. Rate limit 20/min per user.

6. GET /api/admin/fraud/transaction-details/:fraudEventId — Get detailed fraud analysis for a single transaction. URL param: fraudEventId. Process: verify admin role, query fraud_events by fraudEventId, eager load orders, users, payments, tickets, calculate velocity metrics for user, query for duplicate tickets. Response: {fraudEvent, order, user, payment, velocityMetrics, duplicateTickets}. Rate limit 20/min per user.

For each endpoint, create a controller in app/Features/Fraud/Http/Controllers/, request validation class in app/Features/Fraud/Http/Requests/, and register routes in routes/api.php. Use Laravel's authorization policies to enforce admin-only access where needed.
