We need three things set up before building the API integration feature:

1. Bcrypt for key hashing — On the backend, make sure bcrypt is available (Laravel includes it by default via the Hash facade). We'll use it to hash raw API keys before storing them in the api_keys table. The raw key is generated once, hashed, and never retrievable again.

2. API key authentication middleware — Create a middleware at app/Http/Middleware/ApiKeyMiddleware.php that intercepts requests to /v1/* and /graphql endpoints. It should:
   - Extract the API key from the Authorization header (Bearer token format)
   - Query the api_keys table to find a matching key (comparing the raw key against the hashed_key using Hash::check())
   - Verify the key hasn't been revoked (revoked_at is null)
   - Verify the key hasn't expired (expires_at is null or in the future)
   - Attach the authenticated organizer and their scopes to the request for later use
   - Return 401 if the key is invalid, revoked, or expired

3. GraphQL setup — Install rebing/graphql-laravel via Composer. Configure it in config/graphql.php to use the same API key middleware. Set up the GraphQL schema to include resolvers for querying events, orders, and tickets. Each resolver should check the user's scopes (e.g., 'events:read', 'orders:read') before returning data.

On the frontend, install react-router-dom and zustand if not already present. These will be used for routing to the DeveloperPortalPage and for state management.
