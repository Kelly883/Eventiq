We need to make sure only authorized admins can manage email templates and that template content is safe from XSS attacks.

On the backend (Laravel):
- All six endpoints (GET /api/admin/email-templates, GET /api/admin/email-templates/:templateId, POST /api/admin/email-templates, PATCH /api/admin/email-templates/:templateId, DELETE /api/admin/email-templates/:templateId, POST /api/admin/email-templates/send-test) must check that the authenticated user has the Admin role. Use Laravel Policies to enforce this — only admins can create, read, update, or delete templates.
- Sanitize all template content (html_body, mjml_body) on the backend before saving to the database. Use a library like HTML Purifier to strip dangerous tags and attributes while preserving safe HTML. This prevents admins from accidentally (or intentionally) injecting malicious scripts.
- Validate all input using Laravel FormRequest classes. Template name must be non-empty, type must be one of a predefined list, subject must be non-empty, and html_body must be valid HTML.
- Rate limit the POST /api/admin/email-templates/send-test endpoint to prevent abuse (e.g., 5 requests per minute per user).

On the frontend (React):
- Protect the route /admin/settings/email-templates with a role check. Before rendering the page, verify the user has Admin role. If not, redirect to 403.
- When displaying template content in the editor, use TipTap's built-in sanitization to prevent XSS.
- Never send the user's auth token in the request body — always use the Authorization header with Bearer token.
- Implement CSRF protection: include the CSRF token in all POST, PATCH, DELETE requests.
