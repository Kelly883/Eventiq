We need five reusable components that the AdminEmailTemplateManagementPage will use:

1. TemplateList — A left-column list of all email templates. Shows template name, type badge (e.g., 'Order Confirmation'), and active/inactive status indicator. Clicking a template loads it into the editor. Support filtering by type and status via dropdown filters at the top. Show a loading skeleton while fetching. Show an empty state with 'No templates' and a 'Create Template' button if the list is empty. This component manages its own state using the useEmailTemplates hook.

2. TemplateEditor — The main editor component in the right column. Contains form fields for: template name (text input), type (dropdown with predefined types), subject (text input), and a rich-text editor (TipTap) for the email body. The editor should support both MJML and HTML modes with a toggle. Show a 'Save' button that calls the API. Show a 'Send Test' button that opens the TestEmailModal. Disable the form while saving. Show a spinner on the Save button during submission.

3. VariablesSidebar — A sidebar panel showing available placeholder variables for the selected template type (e.g., {{user.name}}, {{event.title}}, {{order.total}}). Each variable should be clickable to insert it into the editor at the cursor position. Group variables by category (user, event, order, etc.). Show a tooltip on hover explaining what each variable contains.

4. TestEmailModal — A modal dialog that opens when the admin clicks 'Send Test Email'. Contains an email input field (pre-filled with the admin's email if available) and a 'Send' button. Show a loading spinner while sending. On success, show a confirmation message. On error, show the error message with a retry button. Close the modal after success.

5. TemplateStatusBadge — A small reusable badge component that shows whether a template is active (green 'Active') or inactive (gray 'Inactive'). Used in the TemplateList and in the editor form. Clicking it toggles the status (for admins with permission).
