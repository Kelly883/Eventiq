We're building a QR code ticket verification system for venue staff. For this step, I need you to build the VenueCheckInPage at /venue/check-in/:eventId — this is the main interface where venue staff scan tickets at event entry.

The page should have a full-screen camera view optimized for mobile scanning. Use the jsQR package to detect QR codes from the camera feed in real-time. When a QR code is detected, extract the encrypted payload and send it to POST /api/tickets/verify-qr to validate the ticket. Display the ticket details in a card overlay on top of the camera feed: attendee name, ticket tier, and current status.

At the top, add a sticky search bar so staff can manually look up tickets by ticket ID or attendee email as a fallback when QR scanning doesn't work. Below the camera view, show three action buttons: 'Check In' (calls POST /api/tickets/:ticketId/check-in to mark the ticket as checked-in), 'Mark Void' (calls POST /api/tickets/:ticketId/void for fraudulent tickets), and 'Manual Entry' (opens a form to enter ticket details manually).

Implement real-time sync status: show a counter displaying total check-ins and remaining capacity for the event. Call GET /api/venue/check-in/sync to fetch this data and update it every 30 seconds.

Handle multiple states clearly with color-coded status badges:
- Green badge for 'valid' tickets (ready to check in)
- Amber badge for 'already checked-in' tickets (show the check-in timestamp)
- Red badge for 'void' or 'invalid' tickets
- Gray badge for 'expired' QR codes

Loading state: show 'Initializing camera...' with a spinner while the camera is starting. Camera permission denied: show 'Please enable camera access' with a link to settings. Invalid QR: show 'Invalid ticket' with a red badge. Network error: show 'Offline mode - limited functionality' with a sync status indicator. Success: show a green checkmark and 'Checked in successfully' with the attendee name.

Implement offline mode: cache recent tickets locally using localStorage so venue staff can continue checking in even without internet. When connection is restored, sync the cached check-ins by calling GET /api/venue/check-in/sync with the lastSyncAt parameter to get only new data.

The page should require 'VenueStaff' or 'Organizer' role — this is enforced by the backend Policy, but show a 'Not authorized' message if the user lacks permissions.
