Now we need to connect the QR check-in feature to the rest of the app's navigation and authentication.

Add the route /venue/check-in/:eventId to the router. This page should only be accessible to users with 'VenueStaff' or 'Organizer' role — add a route guard that checks the user's role before allowing access. If the user lacks permissions, redirect to an 'Access Denied' page or back to the home page.

Wire up these connections:

1. From the event details page or organizer dashboard, add a 'Check In' button or link that navigates to /venue/check-in/:eventId. Pass the eventId as a URL parameter.

2. When a check-in succeeds, show a confirmation toast/notification with the attendee name and check-in timestamp. Include an optional 'View Analytics' link that goes to the organizer analytics page.

3. When the user's auth token expires (401 response from any API call), redirect to the login page. After login, redirect back to the check-in page so the staff member can continue working.

4. Implement a 'Sync Status' indicator in the page header that shows:
   - Green dot + 'Synced' when all data is up-to-date
   - Yellow dot + 'Syncing' when data is being synced
   - Red dot + 'Offline' when there's no internet connection
   - Badge with count of pending check-ins when offline

5. Add a 'Settings' or 'Help' link on the page that opens a modal with:
   - Camera permission troubleshooting
   - Offline mode explanation
   - Manual entry instructions
   - Link to contact support

6. When the page unmounts (user navigates away), ensure the camera stream is stopped and any pending syncs are queued for later.
