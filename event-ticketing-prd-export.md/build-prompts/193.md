We're building an event management system for organizers. For this step, I need you to create three pages that let organizers view, create, and edit their events.

First, build OrganizerEventListPage at /organizer/events. This is the main dashboard where organizers see all their events. Create a tabbed interface with three tabs: 'Upcoming', 'Past', and 'Drafts'. Each tab filters events by status using the GET /api/organizer/events endpoint with a ?status query parameter. Display events in a table or card layout showing the event title, date, and ticket sales progress. Add a prominent 'Create New Event' button at the top that navigates to /organizer/events/create. Each event row should have an 'Edit' action (navigates to /organizer/events/:eventId/edit) and a 'Delete' action (shows a confirmation modal before calling the delete endpoint). Include a search bar that filters events by title on the client side. For performance, implement either infinite scroll or pagination (cap at 20 events per page). Handle three states: loading (show a skeleton table with 5 shimmering rows), empty (show a friendly illustration with 'You haven't created any events yet' and a 'Create New Event' button), and error (show a banner with a retry button). The page should be protected — only users with the 'organizer' role can access it.

Second, build EventCreatePage at /organizer/events/create. This is a long-scroll form broken into logical card sections: Details, Venue, Tickets, and Media. The Details section has a text input for event title, a rich-text editor (using TipTap) for the description, and date/time pickers for start and end times. The Venue section has inputs for venue name and address. The Tickets section is dynamic — users can add, edit, and remove ticket tiers. Each tier has fields for name, price, quantity, and optional sales start/end dates. The Media section has a file upload component for the event banner image. Use react-hook-form for form state management and real-time validation on blur. At the bottom, use a sticky footer with two buttons: 'Save as Draft' (creates the event with status='draft') and 'Publish Event' (creates with status='published'). Both buttons POST to /api/organizer/events with the full event data including ticket tiers. Show a spinner on the clicked button while saving. On success, show a toast notification ('Event created successfully!') and redirect to /organizer/events. Display validation errors inline below each field. This page is also protected for organizers only.

Third, build EventEditPage at /organizer/events/:eventId/edit. This page is nearly identical to EventCreatePage but for editing. Extract the eventId from the URL params. On page load, fetch the event data using GET /api/organizer/events/:eventId (which includes the event details and its ticket tiers). Pre-fill all form fields with the fetched data. The banner image upload component should show a preview of the current banner and allow replacement. The page title should dynamically show 'Editing: [Event Name]'. The sticky footer has 'Save Changes' and optionally 'Archive Event' buttons. 'Save Changes' sends a PATCH request to /api/organizer/events/:eventId with the updated data. Handle loading state (show skeleton form sections while fetching), success (fully populated form), and errors (404 shows 'Not Found', 401/403 handled by auth guard). Reuse the same form component from EventCreatePage by passing an isEditMode prop and initial data to avoid duplication.

All three pages should use the organizer's branding colors from their profile for visual consistency. Use react-router for navigation and swr for data fetching with proper caching.
