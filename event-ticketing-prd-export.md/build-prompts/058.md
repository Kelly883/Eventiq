We need to set up the database schema for events and ticket tiers. Create two Laravel migrations that define the structure for storing event data.

First migration: Create the events table with these columns:
- id (auto-incrementing primary key)
- user_id (unsigned big integer, foreign key to users table)
- organizer_id (unsigned big integer, foreign key to organizers table)
- title (string, required)
- description (text, nullable)
- banner_image_url (string, nullable) — stores the S3 URL or local path
- start_datetime (dateTime, required)
- end_datetime (dateTime, required)
- venue_name (string, required)
- venue_address (string, nullable)
- capacity (unsigned integer, required)
- status (string, required) — values like 'draft', 'published', 'archived'
- created_at and updated_at (timestamps)
- deleted_at (timestamp, nullable) — for soft deletes

Add indexes on user_id and status for fast queries when filtering events by organizer and status.

Second migration: Create the ticket_tiers table with these columns:
- id (auto-incrementing primary key)
- event_id (unsigned big integer, foreign key to events table)
- name (string, required) — e.g., 'Regular', 'VIP'
- price (decimal 8,2, required) — stores price in cents or dollars
- quantity (unsigned integer, required) — total tickets available
- sales_start_date (dateTime, nullable)
- sales_end_date (dateTime, nullable)
- created_at and updated_at (timestamps)

Add a foreign key constraint from event_id to events.id with cascade delete, so deleting an event removes its ticket tiers.

Run php artisan migrate to apply both migrations to your database.
