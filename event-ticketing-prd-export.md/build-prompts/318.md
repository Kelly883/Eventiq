We need to make sure things fail gracefully when something goes wrong, and users understand what happened.

UserRefundRequestPage error handling:
- Network failure loading ticket or policy → show a full-screen error banner with a 'Retry' button (not a small notification — the page has no content yet)
- Validation error (invalid reason, explanation too long, invalid method) → highlight the invalid field with a red border and show an inline error message below it
- 401 (unauthenticated) → redirect to /login with a 'Sign in to request refund' toast
- 403 (refund window closed, not eligible) → show a full-screen message 'Refund window closed' or 'Not eligible for refund' with a back button
- 404 (ticket not found) → show 'Ticket not found' with a back button
- 409 (duplicate refund request) → show 'You've already requested a refund for this ticket' with a 'View Existing Request' button that navigates to the status page
- 429 (rate limited) → show 'Too many refund requests. Please try again later.'
- 500 (server error) → show an error banner with a 'Retry' button

UserRefundStatusPage error handling:
- Network failure loading refund details → show a full-screen error banner with a 'Retry' button
- 401 (unauthenticated) → redirect to /login
- 403 (access denied) → show 'Access Denied — you don't own this refund request' with a back button
- 404 (refund not found) → show 'Refund request not found' with a back button
- 500 (server error) → show an error banner with a 'Retry' button
- Appeal submission failure → show a notification 'Failed to submit appeal' with a retry option
- Polling failure (status update fails) → don't show an error (polling is background), just log it. The user can manually refresh if needed.

AdminRefundDashboardPage error handling:
- Network failure loading refund list → show a full-screen error banner with a 'Retry' button
- 401 (unauthenticated) → redirect to /login with 'Session expired' toast
- 403 (not admin) → show 'Access Denied — only admins can view refund dashboard' with a back button
- 500 (server error) → show an error banner with a 'Retry' button
- Bulk approve/reject failure → show a notification 'Failed to process X requests' with a retry option
- CSV export failure → show a notification 'Failed to export CSV'
- Polling failure (metrics update fails) → don't show an error, just log it. The user can manually refresh.

General error handling:
- All error messages should be user-friendly, not technical jargon (not 'ECONNREFUSED', not 'TypeError: Cannot read property')
- Show error messages in a consistent style (toast notification or inline banner, depending on context)
- For transient errors (network timeout, 500), always offer a 'Retry' button
- For permanent errors (404, 403), offer a 'Go Back' button
- If the user's login expires mid-action, redirect to login and preserve the action intent (so they can retry after signing in)
- Don't show multiple error messages at once — prioritize the most important one
