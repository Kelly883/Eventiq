We need to make sure checkout failures don't leave users confused or stuck.

CartPage — Network failure loading cart: show a notification but keep the cached cart visible. If local storage is corrupted, show a friendly message 'We had trouble loading your cart' with a 'Clear Cart' button. Removing an item fails: show a notification with a retry option.

CheckoutPage — POST /api/cart/verify fails (items no longer available or prices changed): show a full-page error 'Your cart has changed' with a 'Review Cart' button that goes back to /cart and reloads the cart. POST /api/checkout/create-payment-intent fails: show 'We couldn't start the checkout process' with a retry button. Stripe CardElement fails to load: show 'Payment form unavailable' with a retry. stripe.confirmCardPayment() fails with a Stripe error: map the error code to a user-friendly message — 'Your card was declined', 'Insufficient funds', 'Card expired', 'Incorrect CVC', etc. Network failure during payment: show 'Payment processing failed' with a retry option (don't create a new payment intent, reuse the existing one). Payment succeeds but the redirect to OrderConfirmationPage fails: show 'Payment successful, but we're having trouble loading your confirmation' with a 'View Order' button that tries to load the order again.

OrderConfirmationPage — GET /api/orders/:orderId returns 404: show 'Order not found' with a link to /my-tickets. Returns 403: show 'You do not have permission to view this order'. Returns 500: show an error banner with a retry button. Network failure: show a skeleton layout, then retry automatically after a delay.

UserTicketsPage — GET /api/my-tickets returns 401: redirect to /login. Returns 500: show an error banner with a retry button. Network failure: show skeleton ticket cards, then retry. If the user has no tickets, show a friendly empty state with 'You have no tickets yet' and a 'Browse Events' button.

All pages — If the user's session expires (401 on any endpoint), redirect to /login and show a message 'Your session expired, please log in again'. If a request times out (no response after 30 seconds), show 'Request timed out' with a retry option. For any unhandled error, show a generic 'Something went wrong' message with a retry button and an option to contact support.

Payment Provider Errors — Stripe-specific errors should be mapped: card_declined, expired_card, incorrect_cvc, processing_error, rate_limit, etc. Each should have a clear user message. If Stripe is down (5xx error), show 'Payment service temporarily unavailable, please try again later'.
