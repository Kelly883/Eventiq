We need to create two new tables in the database: ticket_inventory and inventory_adjustments. These track current stock levels and maintain an audit trail of all changes.

Create a migration for ticket_inventory with these columns:
- id (UUID primary key, auto-generated)
- event_id (UUID, foreign key to events.id, indexed)
- ticket_tier_id (UUID, foreign key to ticket_tiers.id, indexed)
- total_allocated (integer, default 0) — sum of all pricing window quantities for this tier
- total_sold (integer, default 0) — count of tickets sold
- total_available (integer, computed: total_allocated - total_sold)
- low_stock_threshold (integer, nullable) — threshold for low-stock alerts
- is_low_stock (boolean, computed: total_available <= low_stock_threshold)
- last_updated_at (timestamp)
- created_at (timestamp)
- updated_at (timestamp)

Add a composite index on (event_id, ticket_tier_id) for fast lookups.

Create a migration for inventory_adjustments (immutable audit log) with:
- id (UUID primary key)
- event_id (UUID, foreign key to events.id, indexed)
- ticket_tier_id (UUID, foreign key to ticket_tiers.id)
- pricing_window_id (UUID, nullable, foreign key to pricing_windows.id) — null if adjustment is for entire tier
- organizer_id (UUID, foreign key to users.id) — who made the adjustment
- adjustment_type (enum: 'manual_increase', 'manual_decrease', 'reallocation', 'system_correction')
- quantity_before (integer)
- quantity_after (integer)
- quantity_delta (integer, computed: quantity_after - quantity_before)
- reason (text, nullable, max 500 chars)
- created_at (timestamp)

Add indexes on (event_id, created_at) for audit log queries and (organizer_id) for filtering by who made changes.

Run the migrations: php artisan migrate
