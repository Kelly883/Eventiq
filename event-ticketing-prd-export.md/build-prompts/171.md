We need to build several reusable React components that will be used across EventBrowsePage, EventDetailPage, and CategoryBrowsePage. These components handle the visual presentation and user interactions.

1. EventCard — Displays a single event in a grid or list. Shows: thumbnail image (with fallback), event title (max 2 lines, truncated), organizer name with avatar, date/time formatted nicely, venue name, ticket availability badge (green=plenty, amber=low, red=sold out), starting price, and optional trending/popular badge. Clicking the card triggers a callback (usually navigation to detail page). Accept props: event object, onClick handler, loading state (shows skeleton).

2. FilterSidebar — Sidebar with all filter options. Shows: category dropdown (multi-select or single), date range picker (buttons for upcoming/this week/this month, plus custom date range), price range slider (min/max inputs), location/venue search field. Each filter change triggers a callback with updated filters. On mobile, this should be a collapsible drawer instead of a sidebar. Accept props: current filters, onChange handler, available categories from /api/events/public/filters.

3. SearchBar — Search input with real-time autocomplete. As user types, debounce and call GET /api/events/public/search. Show dropdown with suggestions (event title, organizer, date). Clicking a suggestion navigates to that event's detail page. Accept props: onSearch handler, placeholder text.

4. TicketTierCard — Shows a single ticket tier with: tier name (Regular, VIP, VVIP, Early Bird), current price, quantity available, quantity sold (optional progress bar), and 'Select Ticket' button. Used on EventDetailPage in a horizontal scrollable carousel on mobile, grid on desktop. Accept props: tier object, onSelect handler, loading state.

5. EventGrid — Container component that renders multiple EventCard components in a responsive grid (1 column mobile, 2 columns tablet, 3 columns desktop). Handles infinite scroll or pagination. Shows loading skeleton cards while fetching. Shows empty state when no events match filters. Accept props: events array, isLoading, hasMore, onLoadMore, onEventClick.

6. PricingWindow — Shows current and next pricing information with countdown timer. Displays: current price, next price, time until next price change (formatted as 'in 2 days' or 'in 3 hours'). Used on EventDetailPage. Accept props: pricing object with currentPrice, nextPrice, nextPriceChangeAt.

7. OrganizerCard — Shows organizer info: avatar, name, bio (truncated), link to public profile. Used on EventDetailPage. Accept props: organizer object, onClick handler.

8. AvailabilityBadge — Small badge showing ticket availability status. Color-coded: green for plenty (>20% available), amber for low (5-20% available), red for sold out. Shows text like '45 tickets left' or 'Sold Out'. Accept props: ticketsAvailable, ticketsTotal.

All components should have loading states (skeleton/shimmer effect) and handle error states gracefully. Use TypeScript for type safety. Make sure components are reusable and don't contain business logic — they should just receive data via props and call callbacks.
