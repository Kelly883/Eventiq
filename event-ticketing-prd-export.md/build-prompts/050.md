We need two logging libraries set up for the audit system to work properly.

On the backend, install winston and pino via Composer (or npm if using Node.js alongside Laravel). These will be used for structured logging of audit events. Configure winston or pino to log to a file or external service (like a logging aggregator) so we have a reliable audit trail separate from the database. Set up log rotation so old logs don't consume unlimited disk space.

Also install Laravel's built-in logging (it comes with Laravel) and configure it to use a stack channel that logs to both a file and your chosen logging service. This ensures audit events are captured even if the database is temporarily unavailable.

On the frontend, install axios or your preferred HTTP client if not already present. We'll use this to call the compliance API endpoints. Also install date-fns or dayjs for handling date ranges in the UI filters.

Create a .env file (or update existing) with: AUDIT_LOG_RETENTION_DAYS (how long to keep logs, e.g., 365 or 2555 for 7 years depending on compliance requirements), COMPLIANCE_REPORT_QUEUE (the queue name for async report generation), and LOG_LEVEL (debug, info, warn, error).
