We need to define the data models for both the backend (Eloquent) and frontend (TypeScript) so we have a single source of truth for the event and ticket tier data structures.

On the backend (Laravel), create two Eloquent models:

1. Event model (app/Models/Event.php) — Should have:
- Protected $fillable array with: title, description, banner_image_url, start_datetime, end_datetime, venue_name, venue_address, capacity, status
- A relationship: hasMany('TicketTier') to access ticket tiers for an event
- A relationship: belongsTo('User') for the organizer who created it
- A scope: whereNotDeleted() or use SoftDeletes trait to handle soft deletes
- Casts: cast start_datetime and end_datetime to datetime, capacity to integer, price to decimal

2. TicketTier model (app/Models/TicketTier.php) — Should have:
- Protected $fillable array with: name, price, quantity, sales_start_date, sales_end_date
- A relationship: belongsTo('Event') to link back to the event
- Casts: cast price to decimal(8,2), quantity to integer, dates to datetime

On the frontend (React), create TypeScript types in src/features/events/types/index.ts:

1. Event interface:
```typescript
interface Event {
  id: number;
  user_id: number;
  organizer_id: number;
  title: string;
  description: string;
  banner_image_url: string | null;
  start_datetime: string; // ISO 8601 format
  end_datetime: string;
  venue_name: string;
  venue_address: string;
  capacity: number;
  status: 'draft' | 'published' | 'archived';
  ticket_tiers: TicketTier[];
  created_at: string;
  updated_at: string;
}
```

2. TicketTier interface:
```typescript
interface TicketTier {
  id: number;
  event_id: number;
  name: string;
  price: number;
  quantity: number;
  sales_start_date: string | null;
  sales_end_date: string | null;
  created_at: string;
  updated_at: string;
}
```

These types will be imported and used in the form components and API service functions to ensure type safety throughout the feature.
