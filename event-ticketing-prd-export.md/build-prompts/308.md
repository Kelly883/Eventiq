We need to make sure things fail gracefully when something goes wrong, and users understand what happened.

EventPricingConfigPage:
- Network failure on initial load → show a full-screen error banner with a 'Retry' button (not a small notification — the page has no content yet)
- Failure while adding a window → show a notification with the error message and a 'Retry' button. The form stays open so the user can try again.
- Failure while updating a window → show a notification. Revert the window to its previous state in the UI.
- Failure while deleting a window → show a notification. Keep the window in the list.
- Validation error (overlapping windows, negative price, etc.) → highlight the invalid field with a red border and show the error message below the field. Don't submit the form.
- 401 (session expired) → redirect to the login page
- 403 (don't own the event) → show 'Access Denied' with a link back to the event list
- 404 (event not found) → show 'Event not found' with a link back to the event list
- 500 (server error) → show an error banner with a 'Retry' button
- Rate limit (429) → show a notification saying 'Too many requests, please wait a moment'

PricingPreviewModal:
- Network failure → show 'Unable to load preview' with a 'Close' button
- 401, 403, 404, 500 → show appropriate error message with a 'Close' button

Form validation (client-side, before submission):
- Empty window name → show 'Window name is required'
- Window name > 100 characters → show 'Window name must be 100 characters or less'
- Start date/time not set → show 'Start date and time are required'
- End date/time not set → show 'End date and time are required'
- Start >= End → show 'Start date must be before end date'
- End > Event end date → show 'Window must end before the event ends'
- Price not set → show 'Price is required'
- Price <= 0 → show 'Price must be greater than 0'
- Quantity limit set but <= 0 → show 'Quantity limit must be greater than 0'
- Overlapping window detected → show 'This window overlaps with an existing window for this category'

API error handling (frontend):
- 400 Bad Request → show the validation error message from the server
- 401 Unauthorized → clear the auth token and redirect to login
- 403 Forbidden → show 'You don't have permission to modify this event'
- 404 Not Found → show 'Event or pricing window not found'
- 409 Conflict → show 'This window overlaps with an existing window'
- 429 Too Many Requests → show 'Too many requests, please wait a moment'
- 500 Internal Server Error → show 'Something went wrong, please try again'
- Network error (no response) → show 'Unable to connect, check your internet connection'

All error messages should be user-friendly, not technical. Show them in a consistent way (toast notifications for transient errors, inline messages for form validation, banners for page-level errors).

For the timeline visualization, if data is missing or malformed, show a placeholder or skip that section rather than crashing.
