We need three SDKs set up before building the accessibility and localization feature:

1. i18next — Install react-i18next and i18next. Create src/features/accessibility-localization/i18n/config.ts to initialize i18next with the following configuration: default language 'en', fallback language 'en', supported languages (en, es, fr, de, pt, zh, ja, ar), namespace 'translation', detection plugin to read language from localStorage and user preferences API. Load translation files from src/features/accessibility-localization/i18n/locales/{language}/translation.json. Configure i18next to detect RTL languages (ar, he, ur) and apply dir='rtl' to the document root when needed.

2. react-axe — Install react-axe for development accessibility testing. Initialize it in src/main.tsx only in development mode (check import.meta.env.DEV). This will log accessibility violations to the console during development, helping catch WCAG issues early.

3. Locale formatting utilities — Create src/features/accessibility-localization/utils/localeFormatter.ts with functions to format dates, times, and numbers based on user preferences. Use the Intl API (Intl.DateTimeFormat, Intl.NumberFormat) to handle locale-specific formatting. These functions should accept the user's dateFormat, timeFormat, numberFormat, and locale preferences and return formatted strings.

Also set up environment variables: VITE_API_BASE_URL (for API calls), VITE_SUPPORTED_LANGUAGES (comma-separated list), VITE_DEFAULT_LANGUAGE='en'.
