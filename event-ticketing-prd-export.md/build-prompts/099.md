We need to create the data models and validation logic for email templates.

1. EmailTemplate Eloquent model — Create app/Features/EmailNotifications/Models/EmailTemplate.php. This model should map to the email_templates table and expose all fields: id, name, type, subject, html_body, mjml_body, variables, is_active, created_at, updated_at. Add a method getAvailableVariables() that returns the variables JSON as an array. Add a method isActive() that checks the is_active flag. Make the model fillable for name, type, subject, html_body, mjml_body, variables, and is_active. Cast variables to array and is_active to boolean.

2. Frontend TypeScript interface — Create src/features/email-notifications/types/EmailTemplate.ts with a TypeScript interface matching the model: id (string), name (string), type (string), subject (string), htmlBody (string), mjmlBody (string), variables (string[]), isActive (boolean), createdAt (string), updatedAt (string). Export this so all components can import it.

3. Laravel FormRequest validation — Create app/Features/EmailNotifications/Requests/StoreEmailTemplateRequest.php and UpdateEmailTemplateRequest.php. Both should validate: name (required, string, max 255), type (required, string, in a list of allowed types like 'order_confirmation', 'event_reminder'), subject (required, string, max 255), html_body (required, string), mjml_body (required, string), variables (required, array of strings), is_active (boolean). The requests should authorize using the EmailTemplatePolicy.

4. Sanitization — Add a method in the EmailTemplate model to sanitize html_body before saving. Use Laravel's built-in HTML purifier or a package like mews/purifier to strip dangerous tags and attributes, preventing XSS attacks.
