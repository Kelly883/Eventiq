We're building an admin panel for platform management. You'll create four pages that give admins complete visibility and control over the platform. Each page follows a dense, scannable layout optimized for power users with real-time updates.

**AdminDashboardPage at /admin/dashboard** — This is the command center. At the top, display metric cards showing: total platform revenue (24h), active events count, pending user approvals, flagged transactions count, and failed payouts. Each metric should have a color-coded trend indicator (green for up, red for down). Below the metrics, arrange six navigation tiles in a 2x3 grid linking to: User Management, Event Moderation, Payment Reconciliation, Dispute Resolution, System Configuration, and Reports. Below that, add two collapsible sections: a real-time activity feed showing recent admin actions (user suspensions, event approvals, payout approvals) with timestamps and admin names, and an alerts section highlighting critical issues (failed payment batches, high fraud scores, system errors). Add a sticky header with a search bar for quick lookup of users, events, or orders by ID/email, plus a date range picker and alert severity filter. The page should auto-refresh every 60 seconds with a visual indicator showing the last update time. Handle loading state with skeleton metric cards and shimmer placeholders. Empty state shows 'No recent activity'. Errors: 401 redirects to login with 'Session expired' toast, 403 shows 'Access Denied — only admins', 500 shows error banner with retry.

**AdminUserManagementPage at /admin/users** — Manage all platform users. Start with a summary card showing total users, active users, suspended users, and pending approvals. Below that, display a paginated data table with columns: user ID, email, name, role (organizer/attendee with color-coded badges: blue=organizer, gray=attendee), account status (green=active, amber=pending, red=suspended), registration date, last login date, and action buttons. Make all columns sortable. Expandable rows show user profile info, account history, associated events (for organizers), ticket purchases (for attendees), and audit trail of admin actions. Add filters for role, status, registration date range, and last login date range. Include search by email or user ID. Action buttons: 'View Profile', 'Suspend Account', 'Unsuspend Account', 'Reset Password', 'Send Message', 'View Audit Trail'. For suspended users, display suspension reason and date. Support bulk suspend/unsuspend with a reason field. Add an 'Export as CSV' button. Real-time updates every 60 seconds. Loading state shows skeleton card and placeholder rows with shimmer. Empty state shows 'No users found'. Mobile: stacked cards instead of table, collapsible details.

**AdminEventModerationPage at /admin/events** — Moderate events across the platform. Start with a summary card showing total events, published events, flagged events, and total revenue. Display a paginated data table with columns: event ID, title, organizer name, status (green=published, gray=draft, red=cancelled, orange=flagged), attendee count, ticket sales, revenue, creation date, and action buttons. Flagged events should be highlighted with a warning icon. Make all columns sortable. Expandable rows show full event info (description, venue, dates, ticket tiers, pricing windows), organizer details, sales breakdown by tier, attendee list, and moderation history. Add filters for status, organizer, date range, revenue range, and flagged status. Include search by event title or organizer name. Action buttons: 'View Event', 'Approve Event', 'Flag Event', 'Cancel Event', 'View Attendees', 'View Sales', 'View Moderation History'. For flagged events, show flag reason and date. Support bulk approve/flag/cancel with reason field. Add a moderation notes field for documenting decisions. Include 'Export as CSV' button. Real-time updates every 60 seconds. Loading and empty states similar to user management page.

**AdminPaymentReconciliationPage at /admin/payments** — Reconcile payments and manage disputes. Start with a summary card showing total transactions (24h), total volume, success rate (%), failed count, and refunded count. Display a paginated data table with columns: payment ID, order ID, amount, currency, payment method (card, ACH, etc.), status (green=completed, amber=pending, red=failed, blue=refunded), gateway response code, timestamp, and action buttons. Make all columns sortable. Expandable rows show full payment info (buyer email, card fingerprint masked, IP address masked, device fingerprint), fraud assessment (risk score, detection method), payment gateway response (raw JSON), and dispute history. Add filters for status, payment method, date range, amount range, and fraud risk level. Include search by payment ID, order ID, or email. Action buttons: 'View Payment', 'View Order', 'View Fraud Assessment', 'Refund Payment', 'Dispute Payment', 'View Gateway Response'. For failed payments, show retry button and failure reason. Support bulk refund with reason field. Add a payment reconciliation report showing daily/weekly totals by payment method and status. Include a payment method breakdown chart showing percentage of transactions by method. Add 'Export as CSV' button. Real-time updates every 60 seconds.

All four pages should call their respective endpoints (GET /api/admin/dashboard/overview, GET /api/admin/dashboard/activity-feed, GET /api/admin/dashboard/alerts for the dashboard; similar list/details/action endpoints for the other pages) using TanStack Query for data fetching and caching. Use React Table for sortable, filterable data tables. Implement responsive design: mobile shows stacked cards instead of tables with collapsible details.
