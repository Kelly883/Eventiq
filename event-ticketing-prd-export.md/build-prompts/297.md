Let's make sure the payment feature is properly secured. All payment endpoints must enforce authentication and authorization using Laravel Sanctum and Policies.

Authentication:
- GET /api/users/me/payment-methods: Check that the user is authenticated (Sanctum token). Use the 'me' endpoint to ensure they're only accessing their own data.
- POST /api/users/me/payment-methods/add: Require authentication. The backend must verify the payment method ID came from Stripe (never trust client-side Stripe calls).
- DELETE /api/users/me/payment-methods/:id: Require authentication. Use a Policy to verify the user owns the payment method record (user_id matches the authenticated user).
- PATCH /api/users/me/payment-methods/:id/set-default: Require authentication. Use a Policy to verify ownership.
- GET /api/organizer/settings/stripe-connect: Require authentication and verify the user has the 'organizer' role.
- GET /api/organizer/settings/stripe-connect-return: This is the Stripe callback. Verify the state parameter to prevent CSRF attacks. Update the organizers table only for the authenticated user.
- POST /api/webhooks/stripe: This endpoint receives webhooks from Stripe. Verify the Stripe signature using the webhook secret (never trust the request body without verification). Laravel Cashier handles this, but make sure the webhook secret is stored in the environment config, not hardcoded.

Data handling:
- Card data: Never send raw card data to the server. Always use Stripe.js to create a PaymentMethod and send only the ID (pm_...) to the backend.
- Stripe API keys: The Stripe publishable key can be public (it's in the frontend code). The Stripe secret key must only live in the Laravel backend environment config.
- Stripe Connect: The Stripe Connect secret key must also be in the backend environment config.
- Payment method storage: Store only the gateway_payment_method_id (the Stripe ID), not the full card details. The details JSON field should contain only non-sensitive metadata (brand, last four, expiration — these come from Stripe, not the user).
- User data: The users table has stripe_id, pm_type, pm_last_four, and trial_ends_at. These are managed by Laravel Cashier and should not be directly editable by the user.

Rate limiting:
- GET /api/users/me/payment-methods: 30/min per user
- POST /api/users/me/payment-methods/add: 10/min per user (adding cards is sensitive)
- DELETE /api/users/me/payment-methods/:id: 10/min per user
- PATCH /api/users/me/payment-methods/:id/set-default: 20/min per user
- GET /api/organizer/settings/stripe-connect: 5/min per user (initiating onboarding is rare)
- POST /api/webhooks/stripe: No rate limit (Stripe needs to be able to send webhooks)
