We need to make sure things fail gracefully when something goes wrong with payouts and settlements.

OrganizerPayoutDashboardPage:
- Network failure on initial load → show a full-screen error banner with a 'Retry' button (not a small notification — the page has no content yet)
- Failure while loading more payouts (pagination) → show a brief toast notification but keep the payouts that already loaded
- Filter or sort change fails → show a toast notification and revert to the previous filter/sort selection
- 'Download Statement' fails → show a toast saying 'Failed to download statement' with a retry option
- Real-time update fails (60-second refresh) → silently retry in the background without bothering the user
- Session expires (401) → redirect to login page with a 'Session expired' toast
- User is not an organizer (403) → show 'Access Denied — only event organizers can view payouts' with a back button
- Server error (500) → show an error banner with a 'Retry' button

AdminSettlementDashboardPage:
- Network failure on initial load → show a full-screen error banner with a 'Retry' button
- Failure while loading more settlements (pagination) → show a brief toast but keep the settlements that already loaded
- Filter, sort, or search change fails → show a toast and revert to the previous state
- 'Export Settlement Report' fails → show a toast with a retry option
- Bulk action (approve/reject multiple) partially fails → show a toast saying 'X of Y settlements updated' and highlight which ones failed
- 'Approve Settlement' fails → show a confirmation dialog saying 'Failed to approve settlement: [reason]' with a retry option
- 'Reject Settlement' fails → show a confirmation dialog saying 'Failed to reject settlement: [reason]' with a retry option
- 'Manual Payout Trigger' fails → show a modal saying 'Failed to trigger payout: [reason]' with a retry option
- Real-time update fails (30-second refresh) → silently retry in the background
- Session expires (401) → redirect to login page with a 'Session expired' toast
- User is not an admin (403) → show 'Access Denied — only admins can view settlements' with a back button
- Server error (500) → show an error banner with a 'Retry' button

General error handling:
- Map API error codes to user-friendly messages. For example: 'Invalid date range' instead of 'Bad Request', 'Payout method not supported' instead of 'Unprocessable Entity'
- For validation errors (400), show which field failed and why (e.g., 'Start date must be before end date')
- For rate limit errors (429), show 'Too many requests — please wait a moment and try again'
- For server errors (500), show 'Something went wrong — our team has been notified' and include a support contact
- Never show raw error messages or stack traces to the user
- Log all errors to a client-side error tracking service (e.g., Sentry) so the team can investigate

Retry logic:
- For transient errors (network timeouts, 5xx errors), automatically retry up to 3 times with exponential backoff (1s, 2s, 4s)
- For permanent errors (401, 403, 400), don't retry — show the error immediately
- For rate limit errors (429), retry after the Retry-After header duration
