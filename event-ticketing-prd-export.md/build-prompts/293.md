We need to lock down the admin panel so only authorized admins can access it.

**Authentication & Authorization** — All four admin pages should require a valid bearer token in the Authorization header. On the frontend, wrap all admin routes with an AdminGuard component that checks: 1) user is authenticated (token exists), 2) user has 'Admin' role. If either check fails, redirect to login (if not authenticated) or home page (if not admin). On the backend, every admin endpoint (/api/admin/dashboard/*, /api/admin/users/*, /api/admin/events/*, /api/admin/payments/*) must verify the token and check the user's role via Laravel Policy. Return 401 if token is invalid/expired, 403 if user is not admin.

**Token Refresh** — If a token is expired, the frontend should attempt to refresh it (if your auth system supports refresh tokens). If refresh fails, redirect to login with 'Session expired' message. Never store the token in localStorage (use httpOnly cookies if possible, or sessionStorage as fallback). Include the token in every API request's Authorization header.

**Rate Limiting** — Implement rate limits on all admin endpoints:
- Read operations (GET): 20 requests/min per user
- Write operations (POST/PUT/DELETE): 5 requests/min per user
Return 429 (Too Many Requests) if exceeded. This prevents abuse and brute-force attacks.

**Data Masking** — Sensitive data should be masked in the UI and exports:
- Email addresses: show first 2 chars + asterisks (e.g., 'jo****@example.com')
- Phone numbers: show last 4 digits only (e.g., '****1234')
- Card numbers: show last 4 digits only (e.g., '****5678')
- IP addresses: show first 3 octets only (e.g., '192.168.***')
- Full names: optional, but consider masking in some contexts
This applies to both the UI display and CSV exports.

**Audit Logging** — Every admin action must be logged to the auditLogs table with: admin ID (performedBy), action (suspend_user, approve_event, refund_payment, etc.), target type (user, event, payment), target ID, reason (if provided), timestamp, and IP address. This creates an immutable record of who did what and when. Query this audit trail when showing user/event/payment details.

**CSRF Protection** — If using cookies for auth, implement CSRF tokens on all state-changing requests (POST, PUT, DELETE). Include the CSRF token in request headers or body.

**Input Validation** — On the frontend, validate all user inputs (filters, search queries, reason fields) before sending to the backend. On the backend, validate again (never trust the client). Reject invalid inputs with 400 errors.

**SQL Injection Prevention** — Use parameterized queries or an ORM (Laravel Eloquent) to prevent SQL injection. Never concatenate user input into SQL queries.

**XSS Prevention** — Sanitize all user-generated content (admin notes, reason fields) before displaying. Use React's built-in XSS protection (it escapes by default) and avoid dangerouslySetInnerHTML.

**Access Control on Specific Actions** — Some actions might require additional permissions:
- Refunding payments: only senior admins or finance team
- Cancelling events: only event moderation team
- Resetting passwords: only support team
Implement fine-grained permissions if needed (e.g., 'admin:refund', 'admin:moderate_events').

**Session Management** — Sessions should expire after a reasonable period of inactivity (e.g., 1 hour). On expiration, redirect to login. Warn the user before expiration (e.g., 'Your session expires in 5 minutes').

**Secure Headers** — Set security headers on all admin API responses:
- Content-Security-Policy: restrict script sources
- X-Content-Type-Options: nosniff
- X-Frame-Options: DENY (prevent clickjacking)
- Strict-Transport-Security: enforce HTTPS
