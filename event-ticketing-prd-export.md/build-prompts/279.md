Let's make sure the organizer profile feature is properly secured and can't be abused.

Public endpoints (GET /api/organizers/:organizerId and GET /api/organizers/:organizerId/events):
- No auth required, but rate limit 20/min per IP to prevent scraping
- Always check the isPublic flag on the organizer — if false and the requester is not the organizer, return 404 (don't reveal that private profiles exist)
- Filter sensitive fields based on privacy toggles: only return email if emailPublic is true, only return phone if phonePublic is true
- Never return notificationPreferences, emailPublic, phonePublic, or other private fields in the public response

Authenticated endpoints (GET /api/organizers/me, PATCH /api/organizers/me/update, POST /api/organizers/me/upload-avatar):
- All three require a valid bearer token (Laravel Sanctum)
- All three must check that the user has the 'Organizer' role via Policy — reject with 403 if not
- GET /api/organizers/me returns all profile data including private fields (only to the owner)
- PATCH /api/organizers/me/update: rate limit 5 updates/min per user to prevent spam. Validate all inputs server-side (displayName required, bio max 500 chars, URLs valid format, hex colors valid). Log all changes to auditLogs with the old and new values.
- POST /api/organizers/me/upload-avatar: rate limit 10 uploads/min per user. Validate file type (only image/jpeg, image/png, image/webp) and size (max 5MB) server-side. Store in S3/object storage with access control. Delete old avatar to prevent storage bloat.

Frontend pages:
- OrganizerPublicProfilePage: public, no auth required
- OrganizerProfileEditPage: organizer-only, check auth and role before rendering. Redirect to login if not authenticated, show 'Access Denied' if not an organizer.
- OrganizerProfileSettingsPage: organizer-only, same checks as edit page

Avatar upload:
- Validate file type and size on the client (for UX), but always validate server-side (security)
- Store avatar URL in the database, not the file itself
- Use S3/object storage with proper access control (private by default, public read-only for the avatar URL)
- Delete old avatar from storage when uploading a new one
