Let's make sure the delivery system is properly secured and users can't access data they shouldn't.

Authentication — All three endpoints (GET /api/tickets/:ticketId/delivery-status, POST /api/tickets/:ticketId/resend-delivery, and the admin endpoints) must check that the user is logged in. Reject with 401 if the auth token is missing or invalid.

Ticket ownership — For TicketStatusPage and the resend endpoint, enforce that users can only view and resend their own tickets. This is done via Laravel Policy on the backend, but the frontend should also check: before calling GET /api/tickets/:ticketId/delivery-status or POST /api/tickets/:ticketId/resend-delivery, verify that the ticketId belongs to the current user. If the backend returns 403, show 'Access Denied — you don't own this ticket' and don't let them retry.

Admin-only access — AdminDeliveryDashboardPage should only be accessible to users with the 'Admin' role. Check this on the frontend before rendering the page (redirect to home with 'Access Denied' toast if not admin). The backend also enforces this via Policy, so if a non-admin somehow makes a request to GET /api/admin/delivery/events, they get 403.

Rate limiting — The backend enforces these limits, but the frontend should respect them:
- GET /api/tickets/:ticketId/delivery-status: 20/min per user (don't hammer refresh)
- POST /api/tickets/:ticketId/resend-delivery: 10/min per user (disable resend button after 10 attempts in a minute)
- GET /api/admin/delivery/events: 20/min per user (don't spam filters/search)

Data privacy — Email and phone numbers are hashed on the backend, so the frontend receives hashed values. Never log or display the raw values. When users change their email or phone on DeliverySettingsPage, the new value is sent to the backend for verification — don't store it in local storage or session storage.

Fraud checks — The backend checks fraud_events before allowing resend. If an order is flagged as fraud, the backend returns 403 with 'Delivery blocked due to fraud flag'. The frontend should show this message and not allow retry.

Verification requirements — Email and SMS delivery can only be enabled if verified. The frontend should disable the 'Save' button if the user tries to enable an unverified method. The backend also enforces this, so if they somehow bypass it, they get 400 'Email/phone not verified'.
