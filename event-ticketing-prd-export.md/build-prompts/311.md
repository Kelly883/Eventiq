We need to make sure things fail gracefully when something goes wrong in the calendar feature.

EventCalendarPage:
- Network failure on initial load → show a full-screen error banner with a 'Retry' button (not a small notification — the page has no content yet)
- Failure while loading more events (pagination) → show a brief notification but keep the events that already loaded
- Filter or sort change fails → show a notification and revert to the previous filter/sort selection
- 401 Unauthorized (shouldn't happen on a public page, but handle it) → redirect to login page
- 500 Server error → show an error banner with a 'Retry' button and a link to contact support

CalendarDayDetailModal:
- Failure to load events for the selected date → show 'Unable to load events' message with a close button and a retry option
- Network error while polling for inventory updates → silently skip that update (don't show an error notification — polling is background work). Log the error for debugging but don't interrupt the user.
- 404 No events for date → show 'No events scheduled for this date' message (this is not an error, just an empty state)

Search bar:
- Search fails → show a notification 'Search temporarily unavailable' but keep previous results on screen
- Search returns no results → show 'No events found matching your search' (not an error, just empty state)

Filters:
- Applying a filter fails → show a notification and revert to the previous filter state
- Clearing filters fails → show a notification but let the user try again

All pages: if the user's session expires (401), redirect to the login page. If a 403 Forbidden is returned (shouldn't happen on public endpoints), show a generic error message.

Error messages should be user-friendly, not technical. Say 'Something went wrong. Please try again.' not 'HTTP 500 Internal Server Error'. Provide a 'Retry' button or link to contact support for persistent errors.
