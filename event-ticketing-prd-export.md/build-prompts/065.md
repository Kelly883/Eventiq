We need to optimize the database for fast calendar queries. The calendar feature will frequently query events by date, status, category, and location, so proper indexing is critical.

Create or verify these database indexes in your Laravel migrations:

1. On the events table:
   - Composite index on (status, event_date) — for filtering published events by date range
   - Composite index on (status, category_id) — for category filtering
   - Index on event_date — for date-based sorting
   - Index on status — for published event filtering

2. On the ticket_inventory table:
   - Composite index on (event_id, ticket_tier_id) — for joining with events and getting stock levels
   - Index on event_id — for quick lookups

3. On the pricing_windows table:
   - Composite index on (event_id, ticket_tier_id) — for current price lookups
   - Index on event_id — for joining with events

4. On the organizers table:
   - Index on id — for quick profile lookups (should already exist as primary key)

Create a migration file that adds these indexes if they don't exist. Use Laravel's Schema builder with index() and unique() methods. After creating the migration, run php artisan migrate to apply the indexes.

Also add a database view or raw query helper that groups events by date with availability status — this will be used by the EventCalendarService to quickly calculate availability per date without multiple queries.
