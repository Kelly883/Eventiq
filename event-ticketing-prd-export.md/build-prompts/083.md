We need to define the data models on both backend and frontend so they stay in sync.

On the backend (Laravel), create Eloquent models:

1. Role model (app/Models/Role.php) — Relationships: hasMany permissions (through a pivot table or JSON array), hasMany users. Methods: canAssignRole() (check if a role can be assigned), getPermissionNames() (return human-readable permission names).

2. Permission model (app/Models/Permission.php) — Relationships: belongsToMany roles. Methods: isHighRisk() (return true if riskLevel is 'high'), getCategory() (return the category name).

3. AuditLog model (app/Models/AuditLog.php) — Relationships: belongsTo admin (users table), belongsTo targetUser (users table). Make this immutable (no updates after creation). Methods: getActionLabel() (return human-readable action name).

4. PermissionRequest model (app/Models/PermissionRequest.php) — Relationships: belongsTo user, belongsTo permission, belongsTo approvedBy (users table). Methods: isPending(), isApproved(), isDenied().

On the frontend (React), create TypeScript types in src/features/roles/types/index.ts:
- Role interface: { id: string, name: string, description: string, permissions: string[], isSystemRole: boolean, createdAt: Date, updatedAt: Date }
- Permission interface: { id: string, name: string, description: string, category: 'event_management' | 'ticket_management' | 'analytics' | 'user_management' | 'platform_admin', riskLevel: 'low' | 'medium' | 'high', createdAt: Date }
- AuditLog interface: { id: string, admin: User, targetUser: User, action: string, oldValue: object, newValue: object, reason?: string, createdAt: Date }
- PermissionRequest interface: { id: string, userId: string, permissionId: string, status: 'pending' | 'approved' | 'denied', reason?: string, approvedBy?: User, approvalReason?: string, createdAt: Date, resolvedAt?: Date }
- User interface (extend existing): { id: string, email: string, name: string, role: Role, permissions: string[], createdAt: Date }

Add validation on the frontend using Zod or similar: role name must be 1-50 chars, permission IDs must match the backend's list, reason fields are optional but max 500 chars.
