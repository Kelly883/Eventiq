We're building a ticket management system for users. You need to create three React pages that let users view, manage, and inspect their purchased tickets.

**UserDashboardPage at /dashboard** — This is the main hub. At the top, show four summary metric cards in a 2x2 grid (stacked on mobile): total tickets purchased (all-time), upcoming events count, past events attended, and total spent. Below that, feature a large card showing the next upcoming event with its date, venue, ticket count, and a 'View Tickets' button. Then add a recent activity feed showing the last 5 ticket purchases with event name, tier, purchase date, and delivery status. Include a prominent 'Browse Events' CTA button. If recommendations are enabled in preferences, show a horizontal carousel of 3-5 similar events. Add quick-access links for 'Delivery Preferences', 'Account Settings', and 'Help'. If the user is an organizer, show a 'Go to Organizer Dashboard' link. The page should auto-refresh every 30 seconds if autoRefreshEnabled is true in preferences. Loading state shows skeleton cards with shimmer. Empty state (no tickets) shows an illustration with 'Start your event journey' and a 'Browse Events' CTA. Handle 401 (redirect to login with 'Session expired' toast), 403 (show 'Access Denied' with back button), and 500 (show error banner with retry).

**UserTicketsDashboardPage at /my-tickets** — Display all purchased tickets grouped by event in chronological order (upcoming first, then past). Each event section is a collapsible card showing event title, date, venue, and ticket count. Inside each event, show individual ticket cards in a horizontal layout: QR code on the left, ticket details in the middle (tier name, unique ticket ID, delivery status badge color-coded: green=sent, amber=pending, red=failed), and action buttons on the right ('Download PDF', 'Resend Ticket', 'View Details', 'Add to Wallet'). For failed deliveries, show an inline error message with a 'Resend' CTA. At the top, add a sticky filter/search bar with: filter chips (all/upcoming/past), date range selector (7days/30days/90days/all), and a search field (search by event title or ticket ID). Real-time delivery status updates every 30 seconds. Mobile: stacked single-column with full-width ticket cards. Loading shows 3 skeleton event cards with shimmer ticket placeholders. Empty state shows 'No tickets yet' with 'Browse Events' button. Handle 401 (redirect to login with 'Sign in to view your tickets' toast), 403 (show 'Access Denied' with back button), and 500 (show error banner with retry).

**TicketDetailPage at /my-tickets/:ticketId** — Show a detailed view of a single ticket. Start with a large, centered, scannable QR code at the top with the ticket ID below it. Below that, display the event details card: event title, date/time, venue address with a map embed, organizer name and avatar. Then show the ticket information section with key-value pairs: tier name, seat/section info (if applicable), ticket status (valid/checked-in/void), purchase date, order ID. Add a delivery status section showing: delivery method (email/SMS/dashboard), recipient address (masked for privacy), delivery timestamp, and a vertical timeline of all delivery attempts with timestamps and outcomes. For failed deliveries, show the error reason and a 'Resend Ticket' button. At the bottom, add action buttons: 'Download PDF', 'Add to Wallet', 'Share Ticket', 'Report Issue' (sticky on mobile). If the event has passed, show check-in info: checked-in timestamp and venue staff name who scanned. Show a related section with other tickets from the same order. Loading shows skeleton QR placeholder, event card, and skeleton timeline. Handle 401 (redirect to login with 'Session expired' toast), 403 (show 'Access Denied — you don't own this ticket' with back button), 404 (show 'Ticket not found' with link to /my-tickets), and 500 (show error banner with retry).

All three pages must call their respective endpoints (GET /api/users/me/dashboard-overview for UserDashboardPage, GET /api/my-tickets for UserTicketsDashboardPage, GET /api/tickets/:ticketId/details for TicketDetailPage) and load user preferences from GET /api/users/me/dashboard-preferences. Use TanStack Query for data fetching and caching. Implement proper loading, error, and empty states on all pages.
