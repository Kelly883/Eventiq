We need state management so the AdminEmailTemplateManagementPage doesn't handle data fetching directly. Create a custom hook called useEmailTemplates that manages the template list, selected template, and loading/error states.

The hook should expose:
- templates: array of all templates from GET /api/admin/email-templates
- selectedTemplate: the currently selected template object (fetched from GET /api/admin/email-templates/:templateId)
- isLoading: boolean for initial load
- isSaving: boolean for save operations
- error: any error that occurred
- selectTemplate(id): function to load a template by ID
- saveTemplate(id, data): function to call PATCH /api/admin/email-templates/:templateId
- deleteTemplate(id): function to call DELETE /api/admin/email-templates/:templateId
- createTemplate(data): function to call POST /api/admin/email-templates
- sendTestEmail(templateId, recipientEmail): function to call POST /api/admin/email-templates/send-test
- refetch(): function to reload the template list

Use SWR for data fetching and caching. When a template is saved, updated, or deleted, automatically refetch the list so the UI stays in sync. Handle race conditions — if the user selects a different template while one is loading, cancel the previous request.
