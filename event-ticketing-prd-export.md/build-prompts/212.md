We're building an admin-only compliance dashboard with two pages for auditing and reporting.

AuditLogsViewerPage at /admin/compliance/audit-logs — This is a dense, scannable table showing all system transactions and user actions. Each row represents an audit event with columns: timestamp, action type (user_login, event_created, payment_processed, refund_approved, etc.), actor (who did it), target type (user/event/order/payout), target ID, status (success/failed), and a metadata summary. Color-code the action badges: blue for user actions, green for system actions, orange for admin actions, red for errors. Make rows expandable — clicking a row shows the full context: request/response data, IP address (masked), user agent, geolocation, before/after values for updates, and compliance classification (PCI-DSS, GDPR, SOX). Add filters above the table for date range, action type, actor role, target type, status, and compliance classification. Include a search box for target ID, actor email, or action description. Let users sort by timestamp, action type, or status. The table should poll for new events every 30 seconds and append them to the top without replacing existing rows. Add an 'Export' button that lets admins download the filtered logs as CSV or JSON. Show a retention policy indicator somewhere prominent — tell them how long logs will be kept based on admin settings. Include bulk actions: checkboxes to select multiple events, then a 'Tag for Review' button and a 'Mark as Reviewed' button. Call GET /api/admin/compliance/audit-logs/list for the initial load and pagination, GET /api/admin/compliance/audit-logs/:logId/details when expanding a row, GET /api/admin/compliance/audit-logs/export when exporting, and POST /api/admin/compliance/audit-logs/bulk-tag when tagging events. Handle loading state with skeleton rows, empty state with a friendly message, and error state with a retry button.

ComplianceReportsPage at /admin/compliance/reports — This is a dashboard for generating and managing compliance reports. Show a section for pre-built report templates: Data Access Report, User Activity Report, Payment Audit Trail, Refund Audit Trail, Data Retention Report, and Incident Report. Each template has a card with a description and a 'Generate' button. When clicked, open a modal with: date range selector (start/end dates), data classification filter (public/internal/sensitive/pci), and export format options (PDF, CSV, JSON). Show a progress indicator while the report is generating with an estimated completion time. Once done, display the report in a preview pane with summary statistics at the top (e.g., 'Total transactions: 1,234', 'Success rate: 98.5%') and a detailed data table below. Add options to schedule reports for automatic generation (daily/weekly/monthly) and email them to the compliance team. Show a list of previously generated reports with columns: report type, generation date, generated by (admin name), and actions (download, delete). Let admins search and filter this list by type, date range, or recipient. Add a delete button with confirmation. At the bottom, show a compliance checklist with key requirements: data retention policy, access logging, encryption, etc. Each item should have a green/amber/red indicator showing compliance status. Call POST /api/admin/compliance/reports/generate to start report generation, GET /api/admin/compliance/reports/list to fetch previously generated reports, GET /api/admin/compliance/reports/:reportId/download to download a report, POST /api/admin/compliance/reports/schedule to set up automatic generation, and GET /api/admin/compliance/checklist to fetch compliance status.
