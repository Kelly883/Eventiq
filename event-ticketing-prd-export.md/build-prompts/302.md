We need to make sure things fail gracefully when something goes wrong in the fraud detection system.

**FraudDetectionDashboardPage Errors:**
- Network failure on initial load → show a full-screen error banner with a 'Retry' button (not a small notification — the page has no content yet)
- Failure while loading more transactions → show a brief toast notification but keep the transactions that already loaded
- Filter or sort change fails → show a toast notification and revert to the previous filter/sort selection
- 401 (unauthenticated) → redirect to login with a 'Session expired' toast
- 403 (not admin) → show 'Access Denied — only admins can view fraud dashboard' with a back button
- 500 (server error) → show an error banner with a 'Retry' button
- Real-time updates fail → show a warning toast 'Real-time updates paused due to connection error' and stop polling
- CSV export fails → show a toast 'Unable to export transactions' with a retry option

**FraudTransactionReviewModal Errors:**
- Loading transaction details fails → show 'Unable to load transaction details' message with a close button
- 404 (fraud event not found) → show 'Transaction not found' with a close button
- 401 (unauthenticated) → close the modal and redirect to login
- 403 (not admin) → close the modal and show 'Access Denied' toast
- 500 (server error) → show error message with a 'Retry' button
- Submitting approve/reject fails → show error message and keep the modal open so the admin can retry
- 429 (rate limited) → show 'Too many requests. Please wait a moment before trying again.'

**Checkout Integration Errors:**
- POST /api/checkout/create-payment-intent returns 403 (fraud blocked) → show 'We're unable to process your payment at this time due to security concerns. Please contact support.' with a support link
- POST /api/checkout/create-payment-intent returns 400 (validation failed) → show 'Invalid cart or prices have changed. Please review your order and try again.'
- POST /api/checkout/create-payment-intent returns 429 (rate limited) → show 'Too many payment attempts. Please wait a moment before trying again.'
- Payment webhook fails → the backend handles this, but if the order status doesn't update after 5 minutes, show a message to the user 'Your order is taking longer than expected. We'll email you when it's confirmed.'

**General Error Handling:**
- All error messages should be user-friendly, not technical jargon
- Show a 'Retry' button for transient errors (network, timeout, 500)
- Show a 'Contact Support' link for persistent errors (403, 404, fraud blocked)
- Don't show raw error codes or stack traces to users
- Log errors to a monitoring service (Sentry, LogRocket, etc.) for debugging
- If the user's session expires while they're reviewing a transaction, close the modal and redirect to login with a 'Session expired' toast
