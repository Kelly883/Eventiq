Now we need to connect the event pages to the rest of the app and ensure proper access control.

Add routes for: /organizer/events (OrganizerEventListPage), /organizer/events/create (EventCreatePage), and /organizer/events/:eventId/edit (EventEditPage). All three routes should be protected — only users with the 'organizer' role can access them. If a non-organizer tries to access these routes, redirect to a 'Not Authorized' page or the home page.

Wire up these connections:
- From the main navigation or dashboard, add a link to /organizer/events labeled 'My Events' or 'Manage Events' (only visible to organizers)
- When 'Create New Event' is clicked, navigate to /organizer/events/create
- When 'Edit' is clicked on an event, navigate to /organizer/events/:eventId/edit with the eventId from the event row
- When 'Delete' is confirmed, call the DELETE endpoint and then revalidate the event list (so the deleted event disappears)
- When 'Save as Draft' or 'Publish Event' succeeds, show a toast notification and redirect to /organizer/events
- When 'Save Changes' succeeds on the edit page, show a toast notification and redirect to /organizer/events
- Back button from EventCreatePage or EventEditPage should go back to /organizer/events
- Deep links to /organizer/events/:eventId/edit should work (fetch the event data and pre-fill the form)

Make sure the auth guard checks for the 'organizer' role before allowing access to any of these routes.
