Now we need to connect the analytics pages to the rest of the app and add the ability to export reports.

Add routes for the three analytics pages:
- /organizer/events/:eventId/analytics → SalesAnalyticsDashboardPage
- /organizer/events/:eventId/analytics/detailed → DetailedAnalyticsPage
- /organizer/analytics/compare → AnalyticsComparisonPage

From the event detail page, add a link or tab that navigates to the analytics dashboard for that event. Make it clear this is organizer-only — if a non-organizer tries to access it, they should see the 403 error.

From the organizer's main dashboard or events list, add a link to the comparison page so they can compare performance across events.

Add navigation between the dashboard and detailed analytics page — put a 'View Detailed Analytics' button or link on the dashboard that goes to the detailed page. The detailed page should have a 'Back to Dashboard' link.

Implement export functionality on both the dashboard and detailed analytics pages. On the dashboard, add an 'Export Report' button that lets users choose CSV or JSON format. When clicked, call the export endpoint (GET /api/organizer/events/:eventId/analytics/export) with the current date range and filters, and download the file. On the detailed analytics page, add an 'Export Detailed Report' button that exports the current tab's data as CSV.

Wire up the Mixpanel SDK to log key events:
- 'Analytics Dashboard Viewed' when user lands on the dashboard
- 'Analytics Detailed Viewed' when user lands on detailed analytics
- 'Analytics Comparison Viewed' when user lands on comparison page
- 'Analytics Filtered' when user changes date range or tier filter (include filter values)
- 'Analytics Report Exported' when user exports (include format: CSV or JSON)
- 'Analytics Tab Switched' on detailed page (include tab name)

These events help track how organizers use the analytics feature and identify which features are most valuable.

Add a 'Live' indicator badge that shows the last update time. When auto-refresh fires, update this timestamp and show a brief pulse animation to draw attention to the update.

Make sure the back button from analytics pages goes back to the event detail page (not the app root). Use the browser's back navigation or a custom back handler that knows the previous page.
