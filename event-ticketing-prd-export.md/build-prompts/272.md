Let's make sure the event system is properly secured and can't be abused.

Backend security:
- All six endpoints (POST /api/organizer/events, GET /api/organizer/events, GET /api/organizer/events/:eventId, PATCH /api/organizer/events/:eventId, DELETE /api/organizer/events/:eventId, POST /api/organizer/events/:eventId/upload-banner) must check that the user is authenticated using Laravel Sanctum. Reject with 401 if not.
- The EventPolicy ensures users can only read, update, and delete events they own (user_id == AUTH_USER_ID). The backend should enforce this — don't trust the client.
- POST /api/organizer/events should validate all inputs: title (required, min 1 char, max 255), description (optional, max 5000 chars), start_datetime and end_datetime (required, valid ISO format, end > start), venue_name (required, max 255), venue_address (optional, max 500), capacity (required, positive integer). Ticket tiers must have name (required), price (required, decimal, >= 0), quantity (required, positive integer). Return 422 with validation errors if anything fails.
- PATCH /api/organizer/events/:eventId should validate the same fields and also handle ticket tier syncing (create new, update existing, delete removed). Use a database transaction to ensure consistency.
- DELETE /api/organizer/events/:eventId should soft-delete the event (mark deleted_at, retain data). The EventPolicy ensures only the owner can delete.
- POST /api/organizer/events/:eventId/upload-banner should validate the file: type must be image/* (jpg, png, gif, webp), size max 5MB. Store on S3-compatible storage in path events/{eventId}/banner.{ext}. Update the banner_image_url field. Return 422 if validation fails.
- Rate limit these endpoints: 10/min for POST /api/organizer/events, 30/min for GET /api/organizer/events, 60/min for GET /api/organizer/events/:eventId, 10/min for PATCH, 10/min for DELETE, 5/min for upload-banner.

Frontend security:
- All API calls must include the auth token (Sanctum handles this automatically if configured).
- The EventCreatePage and EventEditPage should only be accessible to users with the 'organizer' role (check before rendering).
- File upload for the banner should validate on the client side before sending (file type, size) to give immediate feedback.
- Never expose the S3 bucket or storage credentials in client code.
- Sanitize the rich-text description on the server side before storing (use a library like HTML Purifier to prevent XSS).

Data validation:
- Ensure start_datetime < end_datetime on both client and server.
- Ensure capacity > 0.
- Ensure ticket tier quantity > 0 and price >= 0.
- Ensure ticket tier sales_start_date < sales_end_date if both are provided.
