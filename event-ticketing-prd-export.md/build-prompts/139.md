We need to build six API endpoints that handle all event creation, retrieval, updating, and deletion operations. All endpoints require authentication via Laravel Sanctum and are scoped to the authenticated organizer.

1. POST /api/organizer/events — Create a new event
Accepts a JSON payload with event details (title, description, start_datetime, end_datetime, venue_name, venue_address, capacity, status) and an array of ticket tiers (each with name, price, quantity, sales_start_date, sales_end_date). Validate all inputs server-side using a StoreEventRequest form request. Create the event record and its associated ticket tiers in a database transaction. On success, dispatch a queued job IncrementTotalEventsCreated to update the organizer's profile counter without blocking the response. Return the created event with a 201 status code.

2. GET /api/organizer/events — List organizer's events
Returns a paginated list of events created by the authenticated user. The EventPolicy automatically scopes the query to only the user's events. Support optional query parameters: ?status=draft or ?status=published to filter by status. Return events with their ticket tiers included. Use Laravel's pagination (default 15 per page).

3. GET /api/organizer/events/:eventId — Get single event details
Retrieves the full details for a specific event, including all its ticket tiers. The EventPolicy ensures the user can only access their own events. Return a 404 if the event doesn't exist or isn't owned by the user. Include the event and all related ticket tiers in the response.

4. PATCH /api/organizer/events/:eventId — Update an existing event
Accepts updated event details and ticket tiers. Handle three operations in a single request: update existing ticket tiers, create new ones, and delete removed ones. Use a database transaction to ensure all changes succeed or all fail. Validate all inputs using an UpdateEventRequest form request. Return the updated event with 200 status.

5. DELETE /api/organizer/events/:eventId — Soft delete an event
Marks the event as deleted (soft delete) without removing it from the database. The EventPolicy ensures only the event owner can delete it. On success, dispatch a queued job DecrementTotalEventsCreated to update the organizer's profile counter. Return a 204 No Content response.

6. POST /api/organizer/events/:eventId/upload-banner — Upload event banner image
Handles file uploads for the event's banner image. Validate the file: must be an image (jpg, png, gif, webp), max 5MB. Store the file on the configured disk (S3 or local) in a path like events/{eventId}/banner.{ext}. Update the event's banner_image_url field with the file's URL. Return the updated event with the new banner URL.

All endpoints should return appropriate error responses: 401 for unauthenticated requests, 403 for unauthorized access, 404 for not found, 422 for validation errors, and 500 for server errors.
