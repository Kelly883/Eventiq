We need five reusable React components that the check-in pages will share:

1. QRScanner — A camera-based QR code scanner. Takes a callback prop onScan(qrCodeData) that fires when a QR code is detected. Shows a video feed with a scanning overlay (crosshairs). Includes a fallback manual entry field for when QR scanning fails. Has a loading state while requesting camera permissions. Used on the main check-in page.

2. SearchBar — A search input with debouncing and autocomplete. Takes props: onSearch(query), placeholder, minChars (default 2). Debounces input by 300ms before firing onSearch. Shows a loading spinner while searching. Used on the check-in page to find attendees by ticket ID, email, or name.

3. TicketCard — Displays a single ticket's information. Shows: ticket ID, attendee name, tier, status badge (color-coded: green for valid, blue for checked-in, red for void), check-in time if applicable. Takes props: ticket (Ticket object), onCheckIn (callback), isLoading (boolean). Used in search results and bulk check-in lists.

4. StatsDisplay — Shows real-time check-in statistics. Displays: total capacity, total checked-in (with percentage), total remaining, total void. Takes props: stats (StatsResponse), isLoading (boolean). Updates in real-time via WebSocket. Used on the check-in dashboard.

5. DuplicateWarning — Shows a warning when a duplicate check-in is detected. Displays: risk level (color-coded), previous check-in time and staff member, current attempt details. Takes props: fraudEvent (FraudEvent), onConfirmOverride (callback), onCancel (callback). Includes a button to override the duplicate if authorized. Used when the detect-duplicate endpoint returns isDuplicate=true.

All components should handle loading and error states gracefully. Use TypeScript for type safety.
