We need state management to handle real-time data fetching, caching, and auto-refresh for the analytics pages.

Create a custom hook called useSalesAnalyticsDashboard that manages the dashboard state. This hook should:
- Fetch summary metrics from GET /api/organizer/events/:eventId/analytics/summary with optional date range and tier filter
- Track loading state (initial load vs. refreshing)
- Track error state with error messages
- Store the metrics data (revenue, tickets sold, conversion rate, average price, trends)
- Store the last update timestamp
- Implement auto-refresh polling every 30 seconds — call the endpoint again and update metrics
- Provide a manual refresh function that immediately fetches fresh data
- Handle date range changes and tier filter changes by clearing the cache and fetching new data
- Compare current period metrics to previous period to calculate trend indicators (up/down/flat)

Create another hook called useSalesVelocityChart that manages sales velocity data:
- Fetch time-series data from GET /api/organizer/events/:eventId/analytics/sales-velocity
- Support granularity parameter (hour, day, week) — default to hour
- Track loading and error states
- Store the data points for the line chart
- When date range changes, refetch with the new range
- Cache the data so switching between tabs doesn't refetch unnecessarily

Create useDemographicInsights for the demographic section:
- Fetch attendee breakdown by tier and geographic distribution
- Track loading and error states
- Store the breakdown data
- Only fetch when the section is expanded (lazy load)

For DetailedAnalyticsPage, create useDetailedAnalytics hook:
- Manage state for all five tabs (Transactions, Funnel, Cohorts, Pricing Performance, Channels)
- Each tab has its own loading, error, and data state
- Support filtering by date range, tier, and pricing window
- Implement lazy loading — only fetch data for the active tab
- Cache data for each tab so switching back doesn't refetch
- For the Transactions tab, implement pagination or cursor-based loading for large datasets

For AnalyticsComparisonPage, create useAnalyticsComparison hook:
- Fetch the list of organizer's events from GET /api/organizer/analytics/events-list
- Track which events are selected (max 3)
- When events are selected, fetch comparison data from GET /api/organizer/analytics/compare-events
- Track loading and error states
- Store comparison metrics and chart data
- When selection changes, refetch comparison data

All hooks should:
- Use React Query or similar for caching and background refetching
- Handle auth errors (401) by returning an error that triggers redirect to login
- Handle permission errors (403) by returning a specific error message
- Implement exponential backoff for retries on network failures
- Log analytics events to Mixpanel when data is fetched (for tracking feature usage)
- Provide a way to manually invalidate cache if needed

Store auth token in a context or hook so all analytics API calls include the bearer token in the Authorization header. Don't pass the token as a query parameter — always use the header.
