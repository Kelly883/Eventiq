We need to make sure things fail gracefully when something goes wrong so users aren't confused or frustrated.

**EventBrowsePage**:
- Network failure on first load → show a full-screen error message with a 'Retry' button (not a small notification — the page has no content yet)
- Failure while loading more events (infinite scroll) → show a brief notification at the bottom but keep the events that already loaded
- Filter or sort change fails → show a notification and revert to the previous filter/sort selection
- Rate limit exceeded (429) → show a message 'Too many requests, please wait a moment' and disable the load-more button for 60 seconds
- Invalid filter values → show a notification and reset that filter to default

**EventDetailPage**:
- Event not found (404) → show a 'Event no longer available' screen with a link back to the browse page
- Event not published (also 404) → show 'Event no longer available' (don't reveal the difference)
- Network error on initial load → show an error screen with a 'Retry' button
- Pricing data fails to load → show a notification but keep the event details visible (pricing is secondary)
- Related events fail to load → show a notification but keep the main event details visible
- Rate limit exceeded → show a message and disable the 'Buy Tickets' button for 60 seconds

**CategoryBrowsePage**:
- Category not found (404) → show 'Category not found' with a link back to browse all events
- Network failure on first load → show a full-screen error with 'Retry'
- Failure while loading more → show a notification but keep loaded events
- Invalid category in URL → show 'Category not found'

**Search autocomplete**:
- Search fails → don't show suggestions, but don't break the search bar
- Search service is down → show a message 'Search temporarily unavailable' but let the user browse normally
- Empty search results → show 'No events found' in the suggestions dropdown

**All pages**:
- If the user's login expires (401 on a protected endpoint like 'Add to Wishlist') → show a modal asking them to sign in, then retry the action after they log in
- 500 server error → show a generic error banner 'Something went wrong' with a 'Retry' button. Don't expose technical details.
- Timeout (request takes > 30 seconds) → show 'Request timed out' with a 'Retry' button

**Error message tone** — Keep error messages friendly and actionable:
- ❌ 'HTTP 500 Internal Server Error'
- ✅ 'Something went wrong. Please try again.'
- ❌ 'Database connection failed'
- ✅ 'We're having trouble loading events. Check your connection and try again.'
- ❌ 'Rate limit exceeded'
- ✅ 'You're browsing too fast. Please wait a moment and try again.'

Implement error boundaries in React to catch unexpected errors and show a fallback UI instead of crashing the page.
