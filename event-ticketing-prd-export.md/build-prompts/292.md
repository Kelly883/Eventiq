Let's make sure the payout and settlement endpoints are properly secured so only authorized users can access sensitive financial data.

Authentication:
- All endpoints (GET /api/organizer/payouts/list, GET /api/organizer/payouts/summary, GET /api/admin/settlements/list, GET /api/admin/settlements/summary, POST /api/admin/settlements/approve, POST /api/admin/settlements/reject, POST /api/admin/settlements/trigger-payout) must verify the bearer token in the Authorization header. If the token is missing or invalid, return 401 Unauthorized.

Authorization:
- GET /api/organizer/payouts/* endpoints: Check that the authenticated user has the 'organizer' role. Use Laravel Policies to enforce that users can only view their own payouts (organizerId must match the authenticated user's organizerId). Return 403 Forbidden if the user is not an organizer or is trying to view another organizer's payouts.
- GET /api/admin/settlements/* endpoints: Check that the authenticated user has the 'admin' role. Return 403 Forbidden if the user is not an admin.
- POST /api/admin/settlements/* endpoints: Check that the authenticated user has the 'admin' role. Return 403 Forbidden if the user is not an admin.

Rate limiting:
- GET /api/organizer/payouts/list: 20 requests per minute per user
- GET /api/organizer/payouts/summary: 20 requests per minute per user
- GET /api/admin/settlements/list: 20 requests per minute per user
- GET /api/admin/settlements/summary: 20 requests per minute per user
- POST /api/admin/settlements/approve: 5 requests per minute per user
- POST /api/admin/settlements/reject: 5 requests per minute per user
- POST /api/admin/settlements/trigger-payout: 5 requests per minute per user

Data masking:
- Never return full bank account numbers in API responses. Always mask to the last 4 digits (e.g., 'ACH ending in 1234').
- Never return sensitive organizer information (tax ID, full address) in settlement details unless the requesting user is an admin.

Audit logging:
- Log all payout approvals, rejections, and manual payout triggers to an auditLogs table with: admin ID, action (approve/reject/trigger), payout/settlement ID, timestamp, and any notes.
- Log all failed payout attempts with: payout ID, failure reason, timestamp, and retry count.

Token refresh:
- If a bearer token is expired, the frontend should attempt to refresh it using a refresh token. If the refresh fails, redirect to login.
- Implement token refresh logic in the API client so it happens automatically before requests fail.

CSRF protection:
- For POST endpoints, verify that the request includes a valid CSRF token (if using session-based auth) or rely on the SameSite cookie attribute (if using JWT).

Input validation:
- Validate all query parameters (page, limit, status, startDate, endDate, sortBy, sortOrder) to prevent injection attacks.
- Reject requests with invalid date formats, negative page numbers, or limit values outside the allowed range (1-100).
- Validate all request body fields (organizer ID, payout method, amount) before processing.
