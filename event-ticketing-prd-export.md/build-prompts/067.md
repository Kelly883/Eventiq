We need to set up the database schema for storing fraud detection events and create indexes for fast queries.

Create a Laravel migration file at database/migrations/ that creates the fraud_events table with these columns:
- id (UUID primary key, auto-generated)
- order_id (UUID, foreign key to orders table, indexed)
- user_id (UUID, foreign key to users table, indexed)
- event_type (string, enum: 'duplicate_ticket_attempt', 'velocity_check_failed', 'payment_pattern_suspicious', 'device_fingerprint_mismatch', 'geolocation_anomaly', 'card_testing', 'high_risk_payment_method')
- risk_score (decimal 5,2, range 0-100)
- risk_level (string, enum: 'low', 'medium', 'high')
- detection_method (string, enum: 'sift_science', 'stripe_radar', 'duplicate_detection', 'velocity_check', 'rule_based')
- fraud_factors (JSON object containing: duplicateTicketDetected, velocityCheckFailed, paymentPatternSuspicious, deviceFingerprintMismatch, geolocationAnomaly, cardTestingPattern, highRiskPaymentMethod)
- payment_details (JSON object: cardLast4, issuer, country, cardFingerprint)
- velocity_metrics (JSON object: ordersIn24h, totalSpendIn24h, averageOrderValue, ordersInLastHour)
- device_info (JSON object: ipAddress, userAgent, deviceFingerprint, country, city)
- duplicate_ticket_info (JSON object: matchingTicketIds array, matchingQRCodes array, matchingEventIds array)
- status (string, enum: 'flagged', 'reviewed', 'approved', 'rejected', 'auto_blocked')
- reviewed_by (UUID, nullable, foreign key to users table)
- review_notes (text, nullable)
- reviewed_at (timestamp, nullable)
- created_at (timestamp)
- updated_at (timestamp)
- deleted_at (timestamp, nullable for soft deletes)

Create composite indexes on:
- (user_id, created_at) for fast user fraud history queries
- (status, created_at) for dashboard queries
- (risk_level, created_at) for filtering by risk level
- (order_id) for looking up fraud events by order

Run the migration: `php artisan migrate`. Verify the table exists in your database with all columns and indexes.
