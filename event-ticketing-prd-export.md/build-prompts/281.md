We need to lock down the pricing feature so only authorized organizers can modify pricing rules.

All six endpoints require authentication via bearer token. Verify the token on every request and extract the userId.

For the organizer endpoints (GET /api/organizer/events/:eventId/pricing/windows, POST /api/organizer/events/:eventId/pricing/windows, PATCH /api/organizer/events/:eventId/pricing/windows/:windowId, DELETE /api/organizer/events/:eventId/pricing/windows/:windowId, GET /api/organizer/events/:eventId/pricing/preview), enforce event ownership via Laravel Policy. Before any operation, query the events table by eventId, then check that the authenticated user owns the event (user_id == AUTH_USER_ID). If not, return 403 Forbidden.

For the public attendee endpoint (GET /api/attendee/events/:eventId/pricing), no auth is required, but check that the event is published (status='published'). This prevents attendees from seeing pricing for unpublished events.

Implement rate limiting on all endpoints:
- GET /api/organizer/events/:eventId/pricing/windows: 20 requests/min per user
- POST /api/organizer/events/:eventId/pricing/windows: 10 requests/min per user
- PATCH /api/organizer/events/:eventId/pricing/windows/:windowId: 10 requests/min per user
- DELETE /api/organizer/events/:eventId/pricing/windows/:windowId: 10 requests/min per user
- GET /api/organizer/events/:eventId/pricing/preview: 20 requests/min per user
- GET /api/attendee/events/:eventId/pricing: 30 requests/min per IP (to prevent scraping)

Validate all input on the server side, even though the frontend validates too. For POST and PATCH requests, check: windowName is not empty and max 100 characters, startDateTime < endDateTime, endDateTime <= event.endDateTime, price > 0, quantityLimit > 0 if provided. Check for overlapping windows: query pricing_windows where ticketCategoryId matches, and (startDateTime < newEndDateTime AND endDateTime > newStartDateTime), excluding the current window if updating. If an overlap exists, return 409 Conflict.

Verify that ticketCategoryId exists and belongs to the event before creating/updating windows. Query ticket_tiers by id and check event_id matches.

Log all changes to an auditLogs table: record the userId, eventId, action (create/update/delete), windowId, old values, new values, and timestamp. This creates an audit trail for compliance.

The Algolia Admin key (if used for search) must never be exposed in API responses or client code. Store it only in server environment variables.

On the frontend, store the auth token securely (httpOnly cookie or secure localStorage). Include the token in the Authorization header for all API requests. If a request returns 401, clear the token and redirect to login.
