We're building a mobile app with offline support for tickets. For this step, I need you to create the frontend pages that let users manage their offline ticket sync settings and view cached tickets.

Create two main pages:

1. OfflineSyncSettingsPage — This is where users control which devices can cache tickets offline. Show a list of the user's registered devices (each with a device token identifier and last sync timestamp). For each device, include a toggle switch that controls the offline_enabled status. When the user flips the toggle, call PATCH /api/notifications/device-tokens/:token/offline-status with the new status. Show a loading state while the request is in flight. If the update succeeds, update the UI immediately. If it fails, show a friendly error message and revert the toggle. Include a 'Last synced' timestamp for each device so users know when their offline data was last refreshed. At the top, add a 'Sync Now' button that manually triggers the offline sync (calls GET /api/me/tickets/for-offline-sync) and updates the last_sync_at timestamp. Show a loading indicator while syncing.

2. OfflineTicketsPage — A read-only view of cached tickets available offline. This page should only render when the user is offline (check navigator.onLine). Display tickets grouped by event (matching the response structure from GET /api/me/tickets/for-offline-sync). For each event, show the event name, date, and a list of the user's tickets for that event. Each ticket should display the ticket tier name, order details, and the QR code (rendered from qrCodeData). Include a 'Last synced' timestamp at the top so users know how fresh the data is. Add a message explaining that this is cached data and may be out of date. Include a 'Refresh' button that only appears when online — tapping it navigates back to OfflineSyncSettingsPage to manually sync.

Both pages should be responsive and work well on mobile screens (phones and tablets). Use a mobile-first design approach: build for small screens first, then add responsive breakpoints for tablets and desktops. On mobile, stack elements vertically. On tablet and up, you can use side-by-side layouts where it makes sense. Make sure touch targets are at least 44x44 pixels so they're easy to tap on mobile devices.

For OfflineSyncSettingsPage, the layout on mobile should be: header → 'Sync Now' button → device list (each device as a full-width card with toggle on the right). On tablet, you could show the device list in a two-column grid if it improves readability.

For OfflineTicketsPage, the layout on mobile should be: header with last sync time → event sections (each event as a collapsible card) → tickets within each event. On tablet, consider a two-column layout for events if space allows.

Make sure both pages handle the responsive design gracefully: no horizontal scrolling, text wraps properly, images scale appropriately. Test on actual mobile devices or use browser dev tools to simulate different screen sizes.
