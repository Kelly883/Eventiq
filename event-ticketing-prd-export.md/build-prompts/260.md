Now we need to connect the dashboard and ticket pages to the rest of the app.

Add routes for: /dashboard (UserDashboardPage), /my-tickets (UserTicketsDashboardPage), and /my-tickets/:ticketId (TicketDetailPage).

On the existing authenticated app shell (after login), add navigation links to both /dashboard and /my-tickets. If the app has a top navigation bar or sidebar, add 'Dashboard' and 'My Tickets' links. If it has a bottom navigation bar, add a 'Tickets' or 'My Tickets' tab.

Wire up these connections:
- From UserDashboardPage: 'View Tickets' button on the next upcoming event card should navigate to /my-tickets
- From UserDashboardPage: 'Browse Events' CTA should navigate to /events (or wherever events are browsed)
- From UserDashboardPage: 'Delivery Preferences' link should navigate to settings or preferences page
- From UserTicketsDashboardPage: 'View Details' button on a ticket card should navigate to /my-tickets/:ticketId
- From UserTicketsDashboardPage: 'Browse Events' button in empty state should navigate to /events
- From TicketDetailPage: Back button should navigate back to /my-tickets
- From TicketDetailPage: 'View Cart' or 'Browse Events' actions should navigate to /events
- Deep links to /my-tickets/:ticketId should work from push notifications or shared links (including when the user isn't logged in — redirect to login first, then back to the ticket)
- When a user is not authenticated, trying to access /dashboard or /my-tickets should redirect to login
- After login, if the user was trying to access /my-tickets, redirect them back to /my-tickets (not /dashboard)

Make sure the navigation feels natural: users should be able to go from dashboard → tickets → ticket detail → back to tickets → back to dashboard without getting stuck or confused.
