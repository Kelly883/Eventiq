We need several reusable React components that will be shared across the three delivery pages (TicketStatusPage, DeliverySettingsPage, AdminDeliveryDashboardPage).

1. DeliveryStatusBadge — A small component that displays the delivery status with color coding. Takes a status prop ('pending', 'sent', 'failed', 'viewed', 'bounced') and returns a colored badge. Pending = amber, sent = green, failed = red, viewed = blue, bounced = orange. Used on TicketStatusPage and AdminDeliveryDashboardPage.

2. DeliveryMethodCard — Shows a single delivery method (email, SMS, or dashboard) with its current status. Takes method, isEnabled, isVerified, and recipient (email or phone) as props. Displays an icon, method name, recipient address, and a status indicator (verified/unverified/disabled). Used on DeliverySettingsPage and TicketStatusPage.

3. DeliveryTimeline — Displays a vertical timeline of all delivery attempts with timestamps, status, and error messages. Takes a deliveryHistory array (from the API response) and renders each attempt as a timeline item. Expandable items show full error details. Used on TicketStatusPage.

4. MetricCard — A reusable card for displaying a single metric (e.g., 'Tickets Delivered: 1,234'). Takes a label, value, and optional trend indicator (up/down/neutral). Used on AdminDeliveryDashboardPage for summary metrics.

5. DeliveryMethodToggle — A toggle switch for enabling/disabling a delivery method. Takes method, isEnabled, and onChange callback. Shows verification status and a 'Verify Now' button if unverified. Used on DeliverySettingsPage.

6. QRCodeDisplay — Renders a QR code using qrcode.react. Takes qrCodeData string and optional size prop. Shows a centered, large QR code with a download button. Used on TicketStatusPage.

All components should be mobile-responsive, handle loading states with skeleton placeholders, and follow the design system (consistent spacing, colors, typography). Each component should be a pure functional component with TypeScript types defined.
