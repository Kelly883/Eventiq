Let's make sure the authentication system is secure against common attacks.

Password handling: Passwords should never be logged, stored in state longer than necessary, or exposed in error messages. On the frontend, clear password fields after successful submission. On the backend (Laravel), use bcrypt with cost 12 to hash passwords before storing. Never return the password hash in API responses.

Rate limiting: Implement rate limits on the backend for all auth endpoints. POST /api/auth/login should allow 5 attempts per 15 minutes per IP to prevent brute-force attacks. POST /api/auth/register should be rate-limited to prevent account creation spam. POST /api/auth/forgot-password should allow 3 requests per hour per IP. The frontend should display these rate limit errors clearly (429 status code).

Email enumeration prevention: The POST /api/auth/forgot-password endpoint must always return the same success message regardless of whether the email exists in the database. This prevents attackers from discovering registered email addresses. Similarly, the login error message should not distinguish between 'user not found' and 'wrong password' — both should show 'Invalid email or password'.

Token security: Store the auth token in localStorage (or preferably httpOnly cookies if your backend supports it). Include the token in the Authorization header (Bearer token) for all API requests. If using JWT tokens, verify the signature on the backend. Tokens should expire after 7 days. If a token is invalid or expired, the backend should return 401, and the frontend should clear the token and redirect to /login.

Password reset tokens: On the backend, generate random tokens for password resets, hash them before storing in the database (never store plain tokens), and set them to expire in 1 hour. Mark tokens as used after they're consumed (set usedAt timestamp) to prevent reuse. On successful password reset, invalidate all existing sessions for that user (set revokedAt on all their sessions) so they're logged out everywhere.

Session management: Create a session record in the database when a user logs in. Store the token, user ID, expiration time, and creation time. On logout, mark the session as revoked (set revokedAt). This allows the backend to track active sessions and invalidate them when needed (e.g., on password reset).

HTTPS only: Ensure all auth endpoints are served over HTTPS in production. Set secure flags on cookies if using them.

CORS: Configure CORS on the backend to only allow requests from your frontend domain.

Validation: Validate all inputs on both frontend and backend. Email format, password length (minimum 8 characters), name length (minimum 2 characters). Never trust client-side validation alone.

Constant-time comparison: When comparing passwords, use bcrypt's constant-time comparison to prevent timing attacks.

Logging: Log authentication events (login, registration, password reset, logout) for security audits. Never log passwords or tokens.
