We need two API endpoints to support offline ticket syncing and device token management. Both are in the Laravel backend.

1. PATCH /api/notifications/device-tokens/:token/offline-status — This endpoint updates the offline-enabled status for a specific device token belonging to the authenticated user. The request body should contain { "offline_enabled": boolean }. Use Laravel Sanctum to authenticate the user. Find the push_notification_devices record where user_id matches the authenticated user and token matches the URL parameter. Update the offline_enabled field. Return the updated PushNotificationDevice as a JSON response with 200 status. If the device doesn't exist or doesn't belong to the user, return 404. Validate that the token format is correct (not empty, reasonable length). Add rate limiting: 30 requests per minute per user.

2. GET /api/me/tickets/for-offline-sync — This is the main offline sync endpoint. It requires authentication via Sanctum bearer token and a custom X-Device-Token header. The process is: (1) Authenticate the user via Sanctum. (2) Extract the X-Device-Token from the request headers. (3) Query all tickets where the user_id matches the authenticated user AND the associated event's start_date is in the future (use Carbon::now()). (4) Eager-load relationships: event, ticket_tier, order, and event.organizer using Eloquent. (5) Transform each ticket using OfflineTicketResource. (6) Group the results by event using OfflineSyncResponse. (7) Find the push_notification_devices record matching the user_id and X-Device-Token header, and update its last_sync_at to now(). (8) Return the grouped ticket data with 200 status. If the X-Device-Token header is missing, return 400 with an error message. If no device is found with that token, return 404. Add rate limiting: 10 requests per minute per user to prevent abuse.

Both endpoints should validate that the authenticated user owns the data they're accessing. Use Laravel's authorization gates or policies to enforce this. Return standard HTTP error codes: 401 for auth failures, 400 for validation errors, 404 for not found, 429 for rate limit exceeded.
