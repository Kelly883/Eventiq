We're building an API and third-party integrations feature for organizers to manage API keys, webhooks, and integrations. This is a power-user feature that requires careful organization.

On the frontend (React + Vite), create a developer feature area under src/features/developer/ with these subfolders:
- pages/ (for DeveloperPortalPage)
- components/ (for tab components like ApiKeysTab, WebhooksTab, ApiLogsTab, DocumentationTab, plus shared components like KeyModal, WebhookForm, LogTable)
- hooks/ (for custom hooks like useApiKeys, useWebhooks, useApiLogs)
- types/ (for TypeScript interfaces: ApiKey, Webhook, ApiLog, AuditLog)
- services/ (for API client functions: fetchApiKeys, createApiKey, revokeApiKey, fetchWebhooks, createWebhook, deleteWebhook, fetchApiLogs, sendTestWebhook)
- store/ (for Zustand state management)

On the backend (Laravel), create a developer feature area under app/Http/Controllers/Developer/ with:
- ApiKeyController (for GET /api/developer/api-keys, POST /api/developer/api-keys, DELETE /api/developer/api-keys/:keyId)
- WebhookController (for GET /api/developer/webhooks, POST /api/developer/webhooks, DELETE /api/developer/webhooks/:webhookId)
- ApiLogController (for GET /api/developer/api-logs)
- Middleware/ (for API key authentication middleware)
- Resources/ (for API Resources to control field exposure)
- Requests/ (for FormRequest validation classes)
- Policies/ (for Laravel Policies to enforce authorization)

Also create app/Models/ for ApiKey, Webhook, WebhookDeliveryLog, and AuditLog models if they don't exist.
