## Description

FUNCTIONALITY: User-facing page showing their own role and permissions. Read-only display of current role (Admin, Organizer, Attendee, Support Staff) with description of what that role allows. Expandable sections for each permission category (Event Management, Ticket Management, Analytics, User Management) showing which specific permissions are granted. Request access button for each permission category — opens a modal to request elevated permissions with optional reason. Shows pending permission requests with status (pending/approved/denied) and request date. Admin approval workflow link if user is an admin (routes to /admin/roles for managing other users' requests).
DESIGN APPROACH: Vertical card layout with role summary at top (large badge, description, permission count). Permission categories as collapsible cards below. Request access button positioned inline with each category. Pending requests section at bottom with status badges (yellow=pending, green=approved, red=denied). Mobile-friendly — stacks vertically, no horizontal scroll.
STATES: Loading shows skeleton cards for role summary and permission categories. Empty state (no permissions) shows 'You have no permissions yet' with explanation and request access button. Error 401 redirects to login. Error 403 shows 'Access Denied' (shouldn't happen on own permissions page). Error 500 shows error banner with retry. Success shows role summary, all permission categories, and pending requests.
SECURITY: User can only view their own permissions (enforced by Policy). Permission requests are logged and require admin approval. No sensitive data exposed.
