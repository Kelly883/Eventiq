## Description

FUNCTIONALITY: Organizer-facing dashboard displaying payout history, pending settlements, and revenue breakdowns. Summary cards show total revenue (all-time), pending payout amount, last payout date, and next scheduled payout date. Interactive table lists all payouts with columns: payout ID, period (date range), gross revenue, platform commission (%), processing fees, refunds deducted, net payout amount, status (pending/approved/processing/completed/failed), and action buttons. Color-coded status badges (amber=pending, blue=processing, green=completed, red=failed). Expandable row details show full breakdown: ticket sales by tier, refunds applied, commission calculation, tax withholding (if applicable), and payment method used. Filters by date range, status, or payout period. Real-time updates every 60 seconds showing pending payout calculations. 'Download Statement' button exports payout history as PDF. For failed payouts, shows retry button and error reason. Payout method display (ACH, wire transfer, etc.) with last 4 digits of bank account masked for privacy.
DESIGN APPROACH: Dense scannable layout for power users. Summary metric cards at top (total revenue, pending payout, last payout date, next payout date) with color-coded trend indicators (green=up, red=down). Data table below with sortable columns (payout ID, period, gross, commission, net, status, date). Expandable rows show detailed breakdown without leaving page. Sticky filter bar with date range, status, period filters. Mobile: stacked cards instead of table, collapsible details. Payout method info displayed in sticky footer showing current payment destination.
STATES: Loading shows skeleton metric cards and placeholder table rows with shimmer effect. Empty state (no payouts) shows 'No payouts yet' with illustration and explanation of payout schedule. Error 401 redirects to login with 'Session expired' toast. Error 403 shows 'Access Denied — only event organizers can view payouts' with back button. Error 500 shows error banner with retry button. Success displays full payout dashboard with live-updating pending amounts and status badges.
SECURITY: Organizer-only (requires organizer role via Policy). Auth required (bearer token). Users can only view their own payouts (enforced by Policy). Rate limit 20/min per user for read operations to prevent abuse. All payout actions logged to auditLogs with organizer ID and timestamp.
