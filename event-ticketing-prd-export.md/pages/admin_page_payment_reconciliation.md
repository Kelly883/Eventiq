## Description

FUNCTIONALITY: Admin interface for reconciling payments and managing payment disputes. Displays paginated table of all payment transactions with columns: payment ID, order ID, amount, currency, payment method (card, ACH, etc.), status (completed/pending/failed/refunded), gateway response code, timestamp, and action buttons. Color-coded status badges (green=completed, amber=pending, red=failed, blue=refunded). Expandable row details show full payment info (buyer email, card fingerprint, IP address, device fingerprint), fraud assessment (risk score, detection method), payment gateway response (raw JSON), and dispute history. Filters by status, payment method, date range, amount range, or fraud risk level. Search by payment ID, order ID, or email. Sort by any column. Real-time updates every 60 seconds showing payment status changes. Action buttons: 'View Payment', 'View Order', 'View Fraud Assessment', 'Refund Payment', 'Dispute Payment', 'View Gateway Response'. For failed payments, shows retry button and failure reason. Bulk refund with reason field. Payment reconciliation report showing daily/weekly totals by payment method and status. Export payment list as CSV. Payment method breakdown chart showing percentage of transactions by method.
DESIGN APPROACH: Dense scannable layout for power users. Summary card at top showing total transactions (24h), total volume, success rate (%), failed count, refunded count. Data table below with sortable columns (payment ID, order ID, amount, method, status, timestamp). Expandable rows show full payment details without leaving page. Sticky filter bar with status, method, date range, amount range, fraud risk filters. Mobile: stacked cards instead of table, collapsible details.
STATES: Loading shows skeleton metric card and placeholder table rows with shimmer. Empty state (no payments) shows 'No payments found' with illustration. Error 401 redirects to login. Error 403 shows 'Access Denied — only admins'. Error 500 shows error banner with retry. Success displays full payment table with live-updating status badges and action buttons.
SECURITY: Admin-only (requires 'Admin' role via Policy). Auth required (bearer token). Rate limit 20/min per user for read operations, 5/min for write operations (refunds, disputes). All payment actions logged to auditLogs with admin ID and timestamp. Sensitive payment data (card numbers, full IP) masked in UI and exports.
