## Description

FUNCTIONALITY: Allows authenticated users to manage their saved payment methods. The page fetches and displays a list of saved cards from '/api/users/me/payment-methods', showing the card brand, last four digits, and expiration date. Each card has a 'Set as Default' and 'Remove' button. A prominent 'Add New Card' button opens a modal containing a Stripe Elements form to securely collect new card details. Submitting the form calls `stripe.createPaymentMethod`, then sends the resulting ID to '/api/users/me/payment-methods' to save it. The default card is clearly marked with a badge.
DESIGN APPROACH: A section within the main user settings layout. Uses a list or card-based layout for saved payment methods. The 'Add New Card' action triggers a modal to avoid a full page navigation, keeping the user in the settings context. The Stripe Elements form is styled to match the application's theme for a seamless experience.
STATES: Loading: Skeleton cards for saved payment methods. Empty: An illustration with 'No payment methods saved' and an 'Add New Card' CTA. Error_401: Redirects to login modal. Error_500: Shows an error banner. Submitting: A spinner overlay on the 'Add New Card' modal. Success: A toast confirms 'Payment method added/removed/updated' and the list refreshes.
SECURITY: Requires authentication. All interactions are scoped to the authenticated user via Laravel Policies. Card data is never sent to the server, only the non-sensitive payment method ID from Stripe.
