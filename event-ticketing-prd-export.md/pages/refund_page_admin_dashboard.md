## Description

FUNCTIONALITY: Admin-only real-time dashboard for managing refund requests across all events. Summary cards show total pending refunds (count), total refund amount pending ($), approval rate (%), and average processing time (days). Interactive table lists all refund requests with columns: ticket ID, event name, buyer email, refund amount, reason, status (pending/approved/rejected/processing/completed), submission date, and action buttons. Color-coded status badges (amber=pending, green=approved, red=rejected, blue=processing, gray=completed). Bulk actions to approve/reject multiple requests at once. Expandable row details show full refund request including reason, refund policy applied, and audit trail. Filters by event, status, date range, refund amount range, or reason. Real-time updates every 30 seconds. Search by ticket ID, email, or event name. Export refund report as CSV. Refund method breakdown chart showing percentage of refunds by method (original payment, store credit, etc.).
DESIGN APPROACH: Dense scannable layout for power users. Summary metric cards at top (pending count, total amount, approval rate, avg time) with color-coded trend indicators (green=up, red=down). Data table below with sortable columns (ticket ID, event, amount, status, date). Expandable rows show full request details without leaving page. Sticky filter bar with status, event, date range, amount range filters. Mobile: stacked cards instead of table, collapsible details.
STATES: Loading shows skeleton metric cards and placeholder table rows with shimmer. Empty state (no refund requests) shows 'No refund requests yet' with illustration. Error 401 redirects to login with 'Session expired' toast. Error 403 shows 'Access Denied — only admins can view refund dashboard' with back button. Error 500 shows error banner with retry button. Success displays full dashboard with live-updating refund metrics.
SECURITY: Admin-only (requires 'Admin' role via Policy). Auth required (bearer token). Rate limit 20/min per user for read operations. All refund decisions logged to auditLogs with admin ID and timestamp.
