## Description

FUNCTIONALITY: A dedicated portal for organizers to manage API access and integrations. It features a tabbed interface for 'API Keys', 'Webhooks', 'API Logs', and 'Documentation'. The 'API Keys' tab allows creating, viewing (prefix only), and revoking personal access tokens with specific scopes (e.g., 'events:read', 'orders:read'). When a new key is created, the full key is shown once in a modal and must be copied. The 'Webhooks' tab allows organizers to register, update, and delete webhook endpoints for real-time notifications on events like 'order.created' or 'ticket.checked_in'. A 'Send Test' button sends a sample payload to the configured URL. The 'API Logs' tab shows a reverse-chronological list of recent API calls made with the user's keys, including status, path, and IP address, fetched from auditLogs. The 'Documentation' tab provides an overview and links to comprehensive external API documentation.
DESIGN APPROACH: A power-user, multi-tab layout within the main app shell. Uses a consistent table component for listing keys, webhooks, and logs, with inline actions (edit, revoke). Modals are used for creating new items and for displaying sensitive information like a newly generated API key. Forms use inline validation. The layout is responsive, with tabs collapsing into a dropdown on mobile.
STATES: Loading: Skeleton tables with 3-5 shimmer rows for each tab. Empty: Each tab has a dedicated empty state with an illustration and a CTA (e.g., 'Create Your First API Key'). Error 401: Redirects to the login modal. Error 403: Shows an 'Access Denied' page as only organizers can view this. Error 500: A global error banner with a retry button. Success: Populated tables and forms for each section.
SECURITY: Requires authenticated user with 'organizer' role. All actions are scoped to the authenticated user's data via Laravel Policies.
