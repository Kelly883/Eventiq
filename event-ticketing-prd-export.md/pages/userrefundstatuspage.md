## Description

FUNCTIONALITY: Displays real-time status of a submitted refund request. Shows refund request details (ticket info, original price, refund amount, reason, submission date). Status timeline with visual stages: submitted → under review → approved/rejected → processing → completed. Current stage highlighted with color-coded badge (amber for pending, green for approved, red for rejected). For approved refunds, shows expected completion date and refund method (original payment method, store credit, etc.). For rejected refunds, displays rejection reason and appeal option. Displays refund history showing all status changes with timestamps. For completed refunds, shows actual completion date and confirmation. 'Download Receipt' button to export refund confirmation as PDF. 'Appeal Decision' button for rejected refunds opens a modal to submit appeal.
DESIGN APPROACH: Vertical scrollable layout with status badge prominently at top (color-coded: amber=pending, green=approved, red=rejected). Refund details card below showing ticket info and amounts. Timeline visualization showing all stages with current stage highlighted. For completed refunds, shows green checkmark and completion details. History section at bottom showing all status changes with timestamps. Mobile: full-width cards with stacked sections, timeline simplified to vertical line with stage markers.
STATES: Loading shows skeleton status card and placeholder timeline. Success displays full refund status with timeline and all details. Error 401 redirects to login. Error 403 shows 'Access Denied — you don't own this refund request'. Error 404 shows 'Refund request not found'. Error 500 shows error banner with retry. Appeal submission shows spinner on button, disabled state.
SECURITY: Authenticated users only. Users can only view their own refund requests (enforced by Policy). Rate limit 20/min per user for read operations.
